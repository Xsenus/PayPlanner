Продолжает [атомарное удаление](company-deletion-atomicity-checkpoint-2026-10-30.md) и [защиту UI](company-deletion-ui-ownership-checkpoint-2026-10-30.md); весь блок ещё не закрыт.

## Воспроизведение и защита

Старый `SellerSnapshotJson` без `ImagesFrozen` хранит текст, но продолжает читать изображения профиля. После мягкого удаления обычный фильтр скрывал исходную компанию: текст оставался, а логотип, печать и подпись исчезали при повторном чтении. Окончательный отрицательный baseline дал **6/6 поведенческих сбоев**: счёт, акт и договор для собственной и обычной компании. Перед удалением логотип существовал, после него становился `null`.

Теперь только при чтении такого снимка существующий `DocumentSellerService` выбирает по точному ID исходной компании **ID и три поля изображений**, включая мягко удалённую запись. В снимке и выбранном продавце должен совпадать положительный ID. Несовпадение отклоняется до запроса изображений с понятным отказом. Текущая компания по умолчанию не подменяет источник; устаревшие картинки из переданного объекта также не используются. Отсутствующий источник оставляет изображения отсутствующими. Без выбранной компании и без значения по умолчанию источник по одному ID снимка не угадывается.

Снятие фильтра ограничено этой проекцией для одного документа, не применяется к общему чтению/выбору профиля, настройкам или остальным справочникам. Удалённая карточка остаётся недоступной через API. Прежние проверки доступа к документу/выдаче и повторная проверка чтения под lease сохраняются; при отказе изображения не выбираются. Общий публичный контракт метаданных не расширялся: внутренний overload получает ID при уже существующем разборе JSON, без второго разбора снимка.

Это совместимость прежнего пути, а не задняя фиксация истории. Изменения живого профиля по-прежнему влияют на незамороженные изображения старого документа до удаления. После удаления читаются оставшиеся в мягко удалённой строке байты. Новые версии изображений не создаются; исторический JSON, текст, дата фиксации, номера, суммы, документы, задачи и их связи не переписываются. Снимки с `ImagesFrozen` сохраняют прежнее чтение неизменяемых версий. При отсутствии `ImagePrintDefaultsFrozen` прежние defaults не берутся из профиля: результат до и после удаления остаётся `null`.

## Проверки и доказательства

Папка вне Git: `D:/PayPlannerRelease/20261030-company-legacy-delete/`; TRX, исходники и DLL/PDB для baseline и квалификации, манифесты и итоговый evidence лежат рядом.

- **21 разный backend-случай составно успешен**: 19 новых и 2 связанных регрессии. Основной адресный запуск — 13 успешных / 3 неуспешных; после исправления только тестового ожидания выполнены три упавших случая и две регрессии, **5/5**. Затем три новые PostgreSQL-проверки, **3/3**. Успешные 13 случаев не повторялись. API-код после основного запуска не менялся, кроме возможного whitespace, отдельно фиксируемого в evidence.
- Шесть preview-сценариев сравнивают три изображения и исторический текст до/после настоящего `Delete`; профиль через `GetById` возвращает `404`. Ещё три проверяют реальный путь повторной выдачи с lease для каждого вида документа без повторной фиксации снимка. Сравниваются все сохранённые scalar/shadow-поля девяти защищённых таблиц: документы, задачи/дела, подразделения, версии и финансовые связи. JSON остаётся побайтно прежним, defaults без маркера отсутствуют до/после, записей версий не прибавляется.
- Неположительный/другой ID снимка отклоняется без единого SQL-запроса; проверены отсутствующий источник/выбор, другая компания по умолчанию и устаревшие изображения объекта той же компании. Два SQL-сценария подтверждают один запрос по ID, только четыре столбца, без адресов, реквизитов и tracked-объектов. Отзыв права чтения перед выдачей не читает изображений и не меняет историю.
- Две существующие регрессии проверяют прежнее следование legacy-снимка живому профилю и round-trip текста без inline-изображений. Замороженное отсутствие изображения остаётся отсутствием в той же регрессии. Прежняя полная квалификация frozen-версий не объявляется заново выполненной.
- **3 native PostgreSQL** выполняют удаление и повторную выдачу счёта/акта/договора с сохранением защищённой истории. Существующий PostgreSQL17 на loopback5433, отдельная `payplanner_ci`, без superuser/createrole/replication/bypassrls. Созданы и штатно удалены шесть принадлежащих фикстурам баз (три template/три clone); остаток отдельно проверен. `EnsureCreated` не является migration/upgrade gate. Пароль из прежнего DPAPI-хранилища только в память процесса, без вывода/Git.

Первый запуск baseline остановился из-за отсутствующей runtime DLL миграций в новом внешнем test-project; он исключён из доказательства дефекта. Подключена прежняя квалифицированная DLL как зависимость модели, миграции не применялись. Первый build исправления нашёл конфликт имени локальной переменной; переименована только она. Основной запуск выявил ошибку нового тестового ожидания пустого tracker после выдачи: прежний lease штатно оставляет документ `Unchanged`. Проверка уточнена до отсутствия любых pending-записей, полное сравнение истории сохранено; только эти три упавших случая повторены. Это не ослабление правил изменения документа.

Сборка настоящего API и малого проекта тестов — без анализаторов и исторической сборки миграций; не полный backend gate. Полные whitespace-preflight API и test-project, encoding, активные roadmap summaries, inventory и итоговый diff фиксируются после правок. Frontend, браузер, Word/PDF, полный gate и CI не запускались; успешные 126 frontend / 5 браузерных предыдущего этапа сохранены в прежних границах. Только синтетические данные, `Email__Enabled=false`, `BackgroundServices__Enabled=false`, без CRM startup/SMTP/production. Новых серверов нет.

## Производительность, очередь и выпуск

Исторический путь теперь читает одну строку по первичному ключу и четыре столбца вместо полного профиля с адресами. Нет N+1, сканирования всех документов, ретроактивной миграции, новых индексов/таблиц или сохранения при preview. Проверка совпадения выполняется до загрузки байтов.

**Продолжение выполнено локально:** [серверный доступ к подразделениям](company-branches-access-checkpoint-2026-10-30.md), 46 backend-случаев составно / 4 native PostgreSQL. Далее — UI просмотра/владельца действий и версия формы подразделения.

Исходная следующая очередь (история) — оставшаяся матрица CMP-05: поля/подразделения/архив/назначение, две компании и обе БД. Не начинать новую реализацию без сверки активного [роадмапа компаний](payplanner-company-roadmap-2026-10-14.md). CMP-04, реальная приёмка CMP-06 и Linux native CMP-01 остаются открыты. Последняя native-проба подготовлена, но не выполнена; Docker/WSL не устанавливать и чужой VPS не использовать для неё по догадке.

Новые **1.14.441–442 неактивны**, пакет **1.14.392–442**, будущий точный допуск **249 → 300**; прежние записи сохранены. Последняя сохранённая сверка чатов остаётся источником, YouGile не менять без отдельной команды. Чужой выпуск, установщик, VPS, push и merge не затронуты. Перед выпуском — один полный обязательный CI итогового объединённого кандидата со всеми семью jobs, assertions и порогами, без полного локального дубликата.
