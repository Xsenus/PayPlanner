## Базовое архитектурное решение

Рекомендуемая стратегия: не вводить отдельную сущность "новое юридическое дело" параллельно текущему `ClientCase`, а эволюционно расширять существующий `ClientCase` до полноценной карточки дела. Это позволит:

- сохранить уже существующие финансовые связи дела со счетами и платежами;
- не плодить дублирующие сущности;
- не делать лишнюю миграцию данных между "старыми делами" и "новыми делами";
- постепенно наращивать функциональность вокруг уже существующего маршрута `/cases`.
