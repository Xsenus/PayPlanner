# Разделение поставщика и клиента расхода в счетах

## Зачем нужна доработка

В доходном счете контрагентом является клиент: это тот, кто должен оплатить нам.

В расходном счете контрагентом является поставщик: эксперт, подрядчик, магазин, государственная пошлина или иной получатель денег. Но расход часто относится к конкретному клиенту и делу. Поэтому в расходном счете нужно хранить две разные связи:

- поставщик, кому мы должны или уже заплатили;
- клиент и дело, ради которых возник расход.

Без этого нельзя надежно считать рентабельность дела и долги: кто должен нам, кому должны мы, сколько заработано и сколько потрачено по конкретному делу.

## Принятое решение

`Payment.ClientId` остается существующей связью с контрагентом счета.

- Для доходного счета это клиент.
- Для расходного счета это поставщик.

Для расходных счетов добавлена новая nullable-связь `Payment.ExpenseClientId`.

- Она указывает клиента, к делу которого относится расход.
- Она не обязательна, чтобы старые и общие расходы продолжили работать.
- Для доходных счетов она не используется.

Связь с делом остается через существующие механизмы счета: `ClientCaseId` и связки `InvoiceClientCases`. Для расходного счета эти дела проверяются относительно `ExpenseClientId`, если он указан.

## Безопасность старых данных

Старые данные не переписываются.

Миграция только добавляет nullable-поле `ExpenseClientId`, индексы и внешний ключ с `SetNull`.

Backfill не выполняется специально: система не пытается автоматически угадать, к какому клиенту относится старый расход. Такие связи лучше проставлять вручную или отдельным контролируемым инструментом, если появится понятное правило.

## Изменения в интерфейсе

В форме счета подписи зависят от типа счета:

- для доходного счета показывается `Клиент`;
- для расходного счета показывается `Поставщик`;
- слово `услуг` убрано, потому что поставщик может быть не только поставщиком услуг.

Для расходного счета добавлен отдельный блок `Клиент и дело расхода`. Эта привязка нужна для аналитики расходов, долгов и рентабельности дела.

## Финансовая сводка по делам

В карточке клиента на вкладке `Дела` добавлена короткая финансовая сводка по каждому делу:

- доходы;
- расходы;
- плановая маржа;
- долги.

Сводка считает доходы по клиенту дела, а расходы — по `ExpenseClientId`. Для старых расходных счетов, где `ExpenseClientId` еще не заполнен, сохраняется совместимость: расход временно считается по прежнему `ClientId`.

Общий сервис статистики также переведен на эту логику, чтобы при выборе клиента поставщик расхода не подменял клиента, ради которого расход был понесен.

## Что делать дальше

Следующий безопасный этап:

- добавить отдельные drill-down отчеты по доходам, расходам, долгам и марже дела;
- добавить быстрый backfill-инструмент для старых расходных счетов, если появится надежное правило сопоставления;
- позже выделить полноценный справочник поставщиков, если поставщиков станет неудобно вести через текущий справочник клиентов/контактов.
