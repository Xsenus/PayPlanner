# Роадмап интеграции с S3-хранилищами

## Цель

Добавить в PayPlanner подключение нескольких S3-совместимых хранилищ, начиная с полной совместимости с HOSTKEY S3, а затем использовать эти подключения для автоматической выгрузки резервных копий базы данных.

## HOSTKEY S3

По документации HOSTKEY подключение выполняется как к S3-compatible storage:

- endpoint: `https://s3-nl.hostkey.com`;
- region: `nl`;
- протокол: HTTPS;
- авторизация: AWS Signature Version 4;
- учетные данные: Access Key и Secret Key из панели HOSTKEY;
- работа идет с bucket и object key/prefix.

## Этап 1. Подключения S3

- Готово: создать ветку `feature/s3-storage-hostkey` от обновленной `main`.
- Готово: добавить backend-модель нескольких S3-подключений в `SystemSettings`.
- Готово: добавить HOSTKEY preset с endpoint `https://s3-nl.hostkey.com` и region `nl`.
- Готово: не возвращать Secret Key в API, показывать только masked preview.
- Готово: добавить проверку подключения через list, upload, download и delete служебного файла.
- Готово: закрепить поведение backend-тестами.

## Этап 2. Права, аудит и UI

- Добавить отдельный раздел прав `S3Storage` в интерфейс настройки ролей.
- Добавить раздел "S3-хранилища" в интерфейс администратора.
- Реализовать список подключений, создание, редактирование, удаление и кнопку "Проверить".
- Показывать понятные ошибки: неверные ключи, нет доступа, bucket не найден, endpoint недоступен.
- Записывать аудит изменения подключений и проверки доступа.

## Этап 3. Файловые операции

- Добавить просмотр объектов внутри bucket/root prefix.
- Добавить загрузку, скачивание, удаление, копирование и перемещение объектов.
- Нормализовать пути и запретить `..`.
- Добавить тесты прав и аудита для каждой операции.

## Этап 4. Резервные копии БД в S3

- Расширить существующий `DatabaseBackupService`.
- Добавить настройку отправки локального backup-файла в одно или несколько S3-подключений.
- Добавить prefix по умолчанию `backups/database/{yyyy}/{MM}/`.
- Хранить результат отправки: pending, success, failed, путь, размер и текст ошибки.
- Добавить retry и отображение статуса в диагностике фоновых задач.

## Этап 5. Приемка

- Проверить подключение с реальным HOSTKEY bucket.
- Проверить ошибочные сценарии: неверный Secret Key, нет доступа к bucket, неверный endpoint.
- Проверить ручной backup БД и отправку в S3.
- Проверить автоматический backup по расписанию и S3-retention.
