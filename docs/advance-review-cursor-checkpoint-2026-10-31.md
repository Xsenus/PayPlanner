## Реализация

Монитор больше не выбирает одни и те же первые старые авансы. В существующих SystemSettings сохраняется один небольшой курсор: версия, последний обработанный ID и верхняя граница текущего цикла. Используются неизменяемые ID, без OFFSET и зависимости от редактируемой даты. Верхняя граница фиксируется по доступным кандидатам при начале цикла; непрерывные поступления не продлевают его бесконечно. Новые и восстановленные записи попадут в следующий цикл. Пустой хвост после ручного разбора/удаления сразу начинает новый цикл без отдельного пустого запуска. Отсутствующий, повреждённый, слишком большой или несовместимый курсор безопасно начинает новый цикл.

Позиция и решения сохраняются в прежней собственной Serializable-транзакции. PostgreSQL использует короткую неблокирующую advisory-блокировку для инициализации общего курсора, затем FOR UPDATE NOWAIT его единственной строки; прежняя блокировка выбранных платежей сохранена. SQLite сохраняет BEGIN IMMEDIATE. Независимые экземпляры не создают два курсора и не теряют продвижение друг друга. Ошибка SQL-записи и отмена до commit не продвигают позицию; неизвестное подтверждение commit проверяется по сохранённым данным на следующем запуске. При отсутствии кандидатов строка прогресса не создаётся; неизменённая позиция не переписывается.

Лимит остаётся 1–500, настройки интервала и размера партии не меняются. Уведомления выполняются после освобождения транзакции; медленная отправка не удерживает курсор и не записывает старую позицию поверх следующей партии. Решения, суммы, номера, связи, баланс и денежные операции не пересчитываются. Схема и миграции не менялись.

## Изоляция уведомлений

Неудачное создание сообщения одному получателю не мешает следующим платежам или эскалации администраторам. Для каждого администратора эскалация также использует отдельную область доставки. Контекст с ошибкой не переиспользуется для другого получателя и не может сохранить случайные изменения платежа. В production оба NotificationService и INotificationService зарегистрированы scoped; это проверено в Program.cs. Сохраняются существующие правила адресатов, личные запреты и дедупликация. Одним ограниченным запросом загружается граф только выбранных платежей; дополнительные области не добавляют повторных запросов загрузки самого платежа.

Весь набор получателей обрабатывается, после чего ошибка задания сохраняется: единственная обычная ошибка передаётся с исходным стеком, несколько ошибок собираются в общий результат. Тайм-аут доставки, не связанный с отменой задания, не маскируется под штатное завершение. Настоящая отмена останавливает отправку. Память и подробные логи ограничены первыми 32 исключениями; общее число сбоев учитывается полностью. Созданные сообщения не дублируются, недостающие проверяются в следующих циклах. Доставка по внешним каналам остаётся в существующей очереди; новый outbox и exactly-once не добавлены.

Для прежних вызывающих мест EnsureReviewEscalationNotificationsAsync сохранён обычный путь через переданный сервис. Дополнительный необязательный callback используется монитором для изоляции каждого администратора; HTTP-контракт не меняется.
