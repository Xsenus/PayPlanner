## Правила исполнения одного пакета

1. Открыть собственный PAY-ID в [источниках](yougile-sources/2026-10-10/cards-source.json), подробную спецификацию и активный профильный roadmap. Прочитать весь предметный блок, не только заголовок. Для операций — [спецификация](claude-yougile-operations-development-spec-2026-10-10.md), для дизайна — [спецификация](claude-yougile-ui-development-spec-2026-10-10.md).
2. Составить таблицу требований с ID `PAY-N.01…`: исходная фраза/макет, существующий экран/API, что сделано, пробел, решение, проверка. Привязать новую правку к доказанному пробелу. Сначала `rg` по существующим модулям/тестам; пути ниже — опорные точки, не указание создать новый модуль.
3. Для каждой прежней кнопки сохранить карту «действие → условия → право → прежнее/новое место → результат/ошибка». Не показывать ложное «нельзя»: отсутствие действия на макете не означает его отмену. Левое меню макетов заказчик исключил из задания. Исходные картинки читать в полном размере по ссылкам карточки; текстовая сверка не является визуальной приёмкой.
4. Любая общая бизнес-логика задачи применяется к старому и новому окну, журналу/календарю/доске и связанным входам, включая административный переключатель формы для всех. UI запрет не заменяет серверный. Новая проверка admin не заменяет проверку исполнителя/бухгалтера/наблюдателя.
5. Выбрать адресные проверки по риску. Только layout: соответствующий UI-test, lint/types, визуально 390/1024/1440. Состояние/форма: тесты успешного и ошибочного сохранения. Деньги/права/данные/интеграции: расширенные регрессии, границы, retry/concurrency и обе стороны контракта; миграции — clean/upgrade SQLite/PostgreSQL. Полный применимый gate один раз перед окончательной публикацией кода, без ослабления CI. Только изменение этого плана не требует application tests.
6. В local backend явно выключить фон и почту; копию production отдельно санитизировать. Для приёмки внешней доставки/денег не использовать реальные destructive операции. Перед закрытием записать точный выполненный сценарий, роль, ревизию, результаты и непройденные условия; обновить существующий roadmap, «Что нового» при изменении продукта и локальный черновик ответа. YouGile публикация отдельно разрешается.

Строки текущей страницы должны иметь отдельное состояние и не подменять этот массив. Необходимы тесты кириллического поиска автора/шаблона без учёта регистра, обеих сортировок с ID по возрастанию при равных датах, `latestOnly=false` по умолчанию, счётчиков и значений фильтров по всей доступной выборке, полной истории при версиях на разных страницах, исчезнувшей старшей версии, скрытого дела и запрета просмотра. На frontend проверить поздний ответ/ошибку после смены дела или фильтра, отмену запроса, корректировку последней страницы после удаления, обновление после подтверждённой публикации и сохранение выбранных вложений согласования; pending/ошибка/retry остаются в прежней панели загрузок. Состояние постраничного запроса должно быть отдельным: сохранять смонтированный интерфейс и черновики при подгрузке, проверять их после позднего ответа и повторной загрузки, не заменять список целиком индикатором загрузки.

Точный total по буквальному `storage.Exists` нельзя получить из сохранённых признаков без обхода файлов; считать опубликованное автоматически доступным также нельзя.
