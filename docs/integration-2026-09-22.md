## Состав интеграции

- Выбор, порядок и ширина колонок журнала с сохранением пользовательских настроек.
- Загрузка занятости исполнителей независимо от фильтров и страницы журнала;
  состояния загрузки, ошибки и повторной попытки в обеих карточках задачи.
  Длительность, изменённая на 15 минут в расписании, корректно отображается
  и сохраняется в старой и новой карточках.
- Доставка уведомлений при переподключении и возврате во вкладку, устранение
  повторного увеличения счётчика и уведомление при возврате прежнего срока.
- Одна общая запись в «Что нового» по выбору пользователя.

## Проверки и публикация

Локальные проверки базы выполнялись только на одноразовых тестовых данных;
production не использовался для разрушительных проверок. Локальная отправка
почты и фоновые службы отключены явно. Проверки завершены 23 сентября:

- Полный backend test project: 2828 пройдено, 0 ошибок. Восстановление пакетов,
  форматирование, аудит уязвимостей и сверка модели EF пройдены.
- На отдельных чистой и обновляемой базах PostgreSQL применены миграции;
  контрольная запись при обновлении сохранена. Пройдены также пути чистой и
  обновляемой SQLite-базы.
- Сборка публикации backend проверена: в пакете отсутствуют локальные настройки,
  секреты и базы данных.
- Полные интеграционные тесты frontend: 297 пройдено, 0 ошибок.
- Повторный полный frontend gate после исправления: 67 проверок маршрутов и
  навигации, 1473 unit-теста, lint, TypeScript, аудит кодировки и production-
  сборка пройдены. Повторный интеграционный прогон: 297 тестов пройдено без ошибок.
- В локальном интерфейсе проверены настройки колонок, независимое недельное
  расписание, конфликт занятости и оба вида карточки. Длительность 75 минут
  дополнительно сохранена через интерфейс и подтверждена в тестовой SQLite-базе.
- Изолированный API smoke подтвердил аутентификацию, независимость недельного
  расписания от фильтра журнала и отсутствие почтовых отправок. Ошибок сервера
  после запуска и во время проверки не обнаружено. В браузере после входа
  и сохранения задачи новых ошибок нет; две первоначальные ошибки авторизации
  были вызваны старой сессией до повторного входа.

Docker CLI на локальной машине отсутствует, поэтому контейнерный запуск не
проверялся. Работоспособность API проверена штатным локальным запуском.
Статус GitHub Actions и опубликованной версии фиксируется отдельно после push:
до отправки текущих изменений production остаётся на исходном коммите.

Предыдущий GitHub Actions run `35711240400` не запустил ни одного шага из-за
ошибки оплаты или лимита расходов аккаунта. Это внешнее ограничение, а не
