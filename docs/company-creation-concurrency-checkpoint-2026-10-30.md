# CMP-05 — создание компании без конкурентного дубля

Продолжение: [согласование пользователя и атомарные настройки](company-approved-access-checkpoint-2026-10-30.md); прежняя следующая проверка ниже выполнена, актуальная очередь находится в новом checkpoint.

Локальный этап после `3cd68a6d` в `feature/company-image-sequencing`. Общий прогресс **9/167 (5.4%)**, 94 в работе / 25 не начато; CMP **0/6 (0%)**, 5 в работе / 1 приёмка. Весь CMP-05 не закрыт. Выпуск другого чата, VPS, установщик, push и merge не затрагиваются.

## Что исправлено

Два независимых соединения воспроизвели создание двух карточек с одним ИНН на SQLite и PostgreSQL. Прежняя проверка выполнялась до записи. Кроме того, при ошибке второго сохранения без настройки изображений в БД оставалась неполная компания; при наличии транзакции в контексте оставались откатившиеся изменения.

Создание через `LegalEntitiesController` теперь использует существующий `DocumentSellerLease.RunSerializableAsync`: актуальный доступ, проверка ИНН, компания, справочные значения, адреса, связи с клиентами, настройки изображений и формирование ответа находятся в одной собственной транзакции. Успех фиксируется только для `CreatedResult`. Ошибка/отказ откатывает всё, очищая только принятый чистый unit of work. Чужая транзакция или ожидающие изменения отклоняются без присвоения владения и сохранения. Нет автоматического повтора записи.

Обнаружен и закрыт второй ручной путь — оформление организации из контакта. Только ветка `legalEntity` переведена на тот же транзакционный подход: создание компании, изменение исходного контакта и привязка его сотрудников сохраняются вместе. ИНН новой компании нормализуется по прежнему правилу обрезки пробелов; исходный контакт и исторические ИНН не переписываются. Ветка оформления физического лица не менялась. Проверка дубля учитывает исторические крайние пробелы. Без ИНН можно создать отдельные карточки, но один контакт нельзя конкурентно оформить дважды даже без ИНН.

Общий отказ при совпадении ИНН больше не раскрывает данные недоступной компании. Название и ID читаются для ответа только после проверки права просмотра/области видимости, а для собственной компании — актуального профиля и назначения сотрудника. Эта проверка применяется при создании и изменении ИНН. Сохраняется прежний запрет создания без просмотра раздела; дополнительного разрешения не введено. Проверка форматов ИНН остаётся справочной, исторические дубли не объединяются и не перенумеровываются.

Новых серверов, таблиц, столбцов или уникального индекса нет. Исторические дубли остаются допустимыми для восстановления прежнего состояния. Существующие слияние контактов и импорт таблиц уже начинают `Serializable` до чтения; они не переписаны и не объявляются заново полностью квалифицированными. Откат импорта/полное восстановление истории не заменены новой политикой. Прямая запись в БД вне согласованных путей не становится глобально уникальной из-за этого этапа.

Пароль — только из прежнего DPAPI-хранилища во временное окружение процесса.

## Производительность и оставшийся объём

Повторного декодирования изображений и загрузки всего справочника в память нет. Обычная проверка ИНН читает один ID; дополнительные проверки доступа/короткие сведения выполняются только при совпадении. Адреса, связи и данные ответа используют прежние запросы внутри одной транзакции. `Serializable` может отклонить и другое пересекающееся изменение: отказ ограничен одним запросом, широкого автоматического повтора нет. Новые ограничения уникальности на исторические данные не накладываются.

Следующий доступный объём CMP-05 — оставшаяся матрица полей/создания/подразделений/архива: две компании, пустой/отдельный КПП, основной/архивный банковский счёт, назначение собственной компании, запрещённые роли, повторное открытие и сохранность старых документов. Принадлежность/назначение собственной компании остаются отдельной проверяемой операцией; этот этап не доказывает атомарность составного пользовательского процесса из нескольких endpoints. CMP-04, ручная приёмка CMP-06 и Linux native-проба CMP-01 остаются открыты. Использовать последнюю сохранённую сверку чатов, не менять YouGile без отдельной команды.

**Следующая короткая проверка SEC-01/CMP-05:** отзыв согласования пользователя (`IsApproved`) при создании/оформлении контакта и назначении собственной компании. Используемые здесь прежние helpers проверяют активность и актуальную роль, а профиль компании отдельно требует согласованного пользователя. Поведение оставшихся маршрутов вместе с общей HTTP-авторизацией ещё не квалифицировано; это открытая предпосылка, не доказанный обход глобального middleware и не закрытый пункт матрицы. Проверить её раньше более тяжёлой матрицы реквизитов/подразделений.
