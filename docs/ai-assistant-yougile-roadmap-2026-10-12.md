## Консультация и выбор направления

Готовая [Алиса AI для бизнеса](https://360.yandex.ru/business/alice-business/) предназначена для рабочего пространства сотрудников и работы с данными сервисов Яндекс 360. Веб-чтение самой страницы вернуло предупреждение об устаревшем браузере; назначение также сверено по её поисковому представлению и [официальному сообщению Яндекс 360](https://360.yandex.ru/blog/news/daidzhest-sentyabrya-obedinili-telemost-i-messendzher-vipustili-alisu-ai-dlya-biznesa-dobavili-publichnie-viki-stranitsi/). Готовое рабочее место не является доказательством готового встраиваемого интерфейса PayPlanner.

Для собственного интерфейса CRM имеется [Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/) с API моделей. [Документация агентов](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/agents/) описывает поиск по файлам и вызовы инструментов. Из этого следует техническая возможность собственной интеграции, но CRM должна сама ограничивать данные и разрешённые действия. Ни один агент или модель не получает права администратора автоматически.

При выборе транспорта учитывать [политику хранения данных](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage): выключение логирования для улучшения качества не отключает все другие виды хранения. API с памятью, файлы/индексы и отдельно включённые трейсы имеют собственный жизненный цикл. Конкретный режим хранения и удаления требуется квалифицировать для выбранного API; обещать «данные нигде не сохраняются» нельзя. Тарифы, лимиты и условия договора повторно проверить в момент выбора; неподтверждённые цены не закладывать в бюджет.

- [decision] **38-02. Утвердить первый полезный сценарий и владельца приёмки.** Для сотрудников выбрать 3–5 задач: найти инструкцию, пояснить порядок CRM, составить черновик письма, суммировать разрешённые материалы. Для клиентов выбрать канал, категории вопросов и сотрудника, который проверяет ответ. Указать запрещённые обещания/действия и ожидаемый результат. Не включать самостоятельную юридическую оценку результата дела, распоряжение деньгами, изменение сроков или массовые рассылки в первый пилот.
- [decision] **38-03. Утвердить данные и их обработку.** Владелец определяет допустимые источники, сведения, которые нельзя передавать, основания/условия внешней обработки, сроки хранения/удаления и ответственного за проверку договора поставщика. Начать с обезличенных инструкций. Установить, допустимы ли реальные клиентские документы вообще; секреты, пароли, ключи и скрытые поля не попадают в контекст. Общая подписка поставщика не снимает ограничений CRM.
- [decision] **38-04. Выбрать поставщика, бюджет и измеримые пороги.** После 02–03 согласовать максимум расходов в день/месяц, размер запроса, скорость, доступность и владельца ключей. Сравнить 20–30 одинаковых примеров без реальных клиентских данных: правильность, ссылки на основания, честный отказ при недостатке сведений, русский язык, цена запроса, задержка. Зафиксировать модель/версию, регион/транспорт, лимиты, хранение и удаление. Если альтернативу ещё не квалифицировали, отметить пробел; не объявлять один сервис лучшим по рекламной странице.

Ключ хранить только на сервере, не в браузере/Git/логах. Ввести узкий интерфейс генерации/поиска, позволяющий сменить провайдера; таймаут, отмена запроса, контролируемый retry и лимит бюджета. Сохранение черновика отдельно от отправки. Не делать бесконечные повторные платные вызовы при обновлении окна.
- [ ] **38-06. Подготовить утверждённую базу знаний.** Для каждого документа: владелец, версия, дата, область доступа, источник и срок актуальности. Извлечение текста/разбиение ограничены по объёму, без исполнения макросов и произвольных ссылок. Поиск выполняется только по допустимым для пользователя источникам; отозванный доступ/удалённый материал исключаются до передачи модели. Не создавать единый общий индекс всех дел без доказанной фильтрации прав. Ответ содержит проверяемые ссылки на использованные доступные материалы.
- [ ] **38-07. Пилот сотрудникам.** Компактное окно вопроса/ответа, индикатор генерации, отмена, повтор после ошибки, источники, явная пометка черновика. При отсутствии основания — сообщение о недостатке данных. Вставка результата в письмо/документ требует действия сотрудника. Закрытие окна не теряет подготовленный текст. Длинная история ограничена; не отправлять весь файл/чат при каждом вводимом символе. Проверить 390/1024/1440, клавиатуру и существующий дизайн.
- [ ] **38-08. Черновики ответов клиентам.** Источник обращения и доступ к клиенту проверяет сервер до подготовки контекста. Предварительный просмотр показывает получателя, канал, текст и использованные основания; сотрудник редактирует и отдельно отправляет через существующий механизм. Сохранить автора проверки и фактически отправленный текст, не заменять его поздним ответом модели. Повтор отправки идемпотентен. Автоотправка не входит в этот этап и требует самостоятельного бизнес-решения и плана.
- [ ] **38-09. Защита и отказные сценарии.** Материалы и сообщения могут содержать инструкции злоумышленника; они являются данными, а не правом получить чужое дело, секрет или выполнить действие. Инструменты сервера проверяют разрешение каждой операции независимо от текста модели. Проверить чужого клиента/компанию, отзыв доступа во время генерации, устаревший документ, ложную ссылку, подмену получателя, попытку вытащить ключ/системные инструкции, HTML/script и вложенный вредный документ. Выдача скрытых данных должна быть невозможна до генерации, а не только скрыта в UI.
- [ ] **38-10. Эксплуатация и ограничение расходов.** Учитывать запросы/токены/стоимость по разрешённым пользователям и сценарию; не записывать полные защищённые тексты в обычный журнал. Определить хранение/удаление черновиков, audit и внешних ресурсов; подтвердить удаление выбранным API. 401/429/5xx/timeout/исчерпание бюджета дают понятный отказ и сохраняют пользовательский ввод. Ограниченная очередь/параллельность, без бесконечной генерации и общих cache-ответов для разных прав. Измерить задержку, число запросов, размер контекста и память.
- [ ] **38-11. Проверки и выпуск пилота.** Во время разработки — fake provider и синтетические данные, затем согласованный безопасный sandbox. Проверки контракта/прав на сервере и в UI, источников/отказов, бюджета, ретраев, отмены и идемпотентной отправки. В local backend обязательны `BackgroundServices__Enabled=false`, `Email__Enabled=false`; реальный SMTP не используется. Полные применимые frontend/backend/security gates перед выпуском, парные миграции только если меняются данные. Добавить пользовательскую заметку и проверять точную ревизию после установки. Выключатель пилота должен останавливать новые запросы без утраты уже сохранённых черновиков.
- [acceptance] **38-12. Приёмка пилота и следующий выбор.** Владелец сценария проверяет согласованные примеры, ошибки и ограничения, пользу сотрудникам, расходы и качество клиентских черновиков. Решение о дальнейшем автоматическом обслуживании клиентов оформляется отдельно; ответ YouGile сообщает только фактический результат.
