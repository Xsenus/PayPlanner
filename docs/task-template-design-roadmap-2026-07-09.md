## Проблема клиента

Клиент указал, что "бросили конструктив и дизайн шаблона задач" и есть риск забыть этот блок. Нужно выделить его отдельно, чтобы не потерять и довести до приемки.

## Целевое решение

Шаблоны задач должны быть отдельным понятным инструментом:

- шаблон легко создать и отредактировать;
- видно название, описание, срок, приоритет, исполнителей, согласующих, наблюдателей и теги;
- шаблон можно применить к задаче или сценарию дела;
- интерфейс компактный и рабочий, без лишнего декоративного пространства;
- правила шаблона одинаково применяются в старой и новой карточке задачи.

Рабочее решение зафиксировано в `docs/task-template-field-composition-2026-07-09.md`: в первую версию входят название, описание, тип, приоритет, плановый срок, теги, исполнитель, согласующие, наблюдатели, напоминания, каналы, привязка к сценарию и активность шаблона; чек-лист и файлы оставлены как расширение.
- `[x]` Спроектировать компактный UI списка шаблонов с быстрым поиском, фильтрами и видимыми ключевыми полями. Проект зафиксирован в `docs/task-template-list-ui-design-2026-07-09.md`: список должен иметь вход из журнала задач, компактную панель поиска и фильтров, desktop-таблицу, mobile-карточки, быстрые действия и состояния загрузки, пустого списка, ошибок и ограниченных прав.
- `[x]` Спроектировать форму создания и редактирования шаблона с теми же правилами выбора участников, что и в задаче. Проект зафиксирован в `docs/task-template-form-ui-design-2026-07-09.md`: форма поддерживает создание, редактирование и копирование, компактные секции основных данных, срока, участников, уведомлений, привязки и предпросмотра, а согласующие и наблюдатели выбираются, отображаются и удаляются по тем же правилам, что в карточке задачи.
- `[x]` Реализовать применение шаблона к новой задаче без потери ручных правок пользователя. Добавлен общий helper применения шаблонных значений к payload задачи: он заполняет пустые поля, умеет заменять только явно разрешенные поля, объединяет теги, напоминания, каналы и участников без дублей, а также поддерживает защищенные поля для ручных правок пользователя. Инициализация новой карточки задачи теперь использует этот helper для `defaults`.
- `[x]` Реализовать применение шаблона в сценариях дела, если шаблон привязан к этапу или типу дела. Сценарий создания задачи из карточки дела по шаблону переведен на общий helper применения шаблонных значений: связь с клиентом, делом, внутренностью и объектом защищена от перезаписи, а шаблон может передавать приоритет, плановое время, теги, напоминания, каналы, согласующих и наблюдателей.
- `[x]` Реализовать backend CRUD шаблонов задач: модель БД, API списка, просмотра, создания, редактирования, скрытия и удаления шаблона с участниками. Добавлены сущности, миграция, API `/api/tasks/templates`, клиентские API-методы и backend-проверки CRUD/валидации.
- `[x]` Покрыть тестами создание, редактирование, применение и сохранение шаблона. Расширен backend regression: шаблон после создания и редактирования читается обратно через API с сохраненными полями, массивами, участниками и автором. Добавлен frontend regression применения данных сохраненного шаблона к задаче без перезаписи защищенного контекста дела.
- `[acceptance]` Проверить вручную на локальной БД: шаблон создается, редактируется, применяется к задаче и выглядит понятно.

## Definition of Done

- Блок шаблонов задач не остается "висящим": есть согласованный состав полей, рабочий интерфейс и проверенный сценарий применения.
- Дизайн соответствует плотному CRM-стилю внутренних рабочих экранов.
- Согласующие и наблюдатели в шаблонах работают так же, как в обычной задаче.
