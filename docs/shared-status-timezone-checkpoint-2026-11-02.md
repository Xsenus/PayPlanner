## Изменения

Статусы документов используют существующий снимок справочника и связываются с текущими формой/страницей, ролью и разрешением просмотра во всех шести местах использования. Старые ответы и ошибки не попадают в новую карточку; закрытые формы и сеанс без авторизации не загружают справочник. Проверяется форма ответа, прежние правила названий/порядка/обязательных статусов сохраняются.

Общий часовой пояс связывается с текущим входом. Старый ответ не меняет следующий вход и не начинает новое автосохранение после закрытия компонента. Обычное обновление токена не перечитывает настройку, события справочников не затрагивают личный пояс. Инициализация объединяется между потребителями одного входа и не повторяет неизвестный исход автоматически. Отсутствие настройки в реальном backend возвращается как HTTP 204; сохраняется перевод в `null`, также поддерживается реальный 404. Отказ 403 с упоминанием другого HTTP-кода не считается отсутствием.

Обнаружена гонка автосохранения с ручным выбором. Для неё добавлен отдельный маршрут `PUT /api/user-settings/{key}/initialize`, который создаёт только отсутствующее значение текущего пользователя и не меняет существующее. Старый backend отклонит такой маршрут; перехода к обычному PUT нет. Обычное сохранение тоже использует атомарную запись по существующему уникальному ключу, чтобы одновременное первое создание не приводило к дублю. Существующие значения, ID и дата создания не переписываются инициализацией. Схема БД и политика аудита не меняются; UserSetting не входит в перечень аудируемых сущностей. UTC хранится по прежнему соглашению колонок без часового пояса.
