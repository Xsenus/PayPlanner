## Основание и сохранённая реализация

Полное [Word-ТЗ профиля](yougile-sources/2026-10-10/attachments/PAY-33-1791504767256-Specifikaciya_Profil_kompanii_filialy_CRM.docx), [поля и правила](yougile-sources/unified-2026-10-14/specifications-audit.md), [существующая матрица](company-profile-gap-matrix-2026-10-09.md), MAX-снимки печати. Все поля/состояния исходного ТЗ обязательны; этот план выделяет остаток, а не сокращает спецификацию.

Принято: профили общие для организации на `LegalEntities`, управление администратором через существующие роли; общий ИНН, отдельный необязательный КПП подразделения. Уже есть черновик/активна/архив, проверки реквизитов/дубля ИНН, DaData с ручным продолжением, подразделения и наследование, несколько счетов и основной активный, выбор продавца документа. Контрольные суммы сейчас показывают предупреждения: это не обещание жёсткой блокировки каждой импортированной записи.

Текущий `DocumentSellerService.ResolveAsync` при выдаче фиксирует текст и неизменяемые версии изображений по SHA; новое изображение профиля не меняет выпущенный документ. Старый снимок без `ImagesFrozen` продолжает прежнее поведение. Слишком большой снимок останавливает выдачу, вместо молчаливого «живого» документа. `DocumentSellerImmutabilityTests` находится внутри `DocumentSellerTests.cs`: реальные SQLite/PostgreSQL сценарии замены/удаления изображений и лимита. Остаток исходного плана нельзя описывать как отсутствие снимков.

C0 — исходники, безопасные макеты и mock API, без БД/VPS; подходит Claude Code без системного доступа. C1 — отдельные синтетические SQLite/PostgreSQL и локальный API, без рабочих секретов; также доступно Claude Code при предоставленной среде. C2 — VPS, внешний sandbox или реальные роли/бухгалтер: окончательная приёмка, не условие для независимой локальной части. Быстрый пакет — до рабочего дня при сохранённом контракте; средний — несколько дней; длительный — несколько связанных этапов/интеграция. Оценка не является обещанием срока.

В финансовом коде проверять сумму/точность/валюту, успех и отказ, прямой запрос ограниченной роли, чужую компанию, повтор/потерянный ответ, две параллельные транзакции, rollback и сохранность истории. Схема меняется только additive-путём с парными миграциями и clean/upgrade проверками. Использовать существующие модальные окна, права, уведомления и managed storage; не создавать второй денежный источник. Во время разработки адресные тесты, перед окончательным push полный применимый gate затронутых областей. Local backend явно: `BackgroundServices__Enabled=false`, `Email__Enabled=false`; SMTP/очереди из копии production отдельно отключены. Реальные деньги и внешние сообщения не используются как тестовый инструмент.

Закрытие `[x]`: весь указанный объём, применимые тесты/кодировка/данные и доказательство. Частичный механизм не закрывает весь пакет. Релизные заметки — пользовательским языком и общим форматом, согласованным ранее. YouGile: только локальный черновик по существенному изменению; публикация/перемещение после отдельной команды на конкретные карточки. После полной приёмки блока архивировать его отдельно.

## Дополнение CMP по профилю КУБ — 17 октября

Ранее отсутствовавший прямой образец теперь получен: [исследование КУБ](kub-reference-analysis-2026-10-16.md), [каталог форм F01–F12](yougile-sources/kub-audit-2026-10-16/forms-and-flows.md) F07, [оригинальные снимки](yougile-sources/kub-audit-2026-10-16/screenshots.md)12–16. Это уточняет прежнюю фразу о необходимости посмотреть профиль; доступ к образцу больше не блокирует C0. **Прогресс 0/6 (0%)**. Для CMP-02 уже выбрана настройка момента фиксации; реализация и проверки продолжаются. CMP-06 остаётся приёмкой.

**CMP-01/05:** единая форма с типом ИП/юрлица, автозаполнением ИНН и ручной коррекцией, названием, контактами, часовым поясом, юридическим/фактическим адресом, налоговыми параметрами и изображениями. Состав обязательных реквизитов зависит от типа; значения автозаполнения не заменяют проверку. Ручной отказ и ошибка сервиса оставляют ввод. В КУБ страна/базовая валюта открытого профиля заблокированы; правило нашей CRM согласовать с существующей моделью, не переносить ограничение по догадке.

**CMP-03:** отдельные настройки печати/подписи для разных документов и отправки, QR, положения допномера и отсрочки покупателя/поставщика. C0 — показать независимость настроек и предпросмотр; C1 — snapshot и реальные файлы. Нельзя менять общую настройку QR при исследовании открытого существующего счёта. Форматы/размеры/прозрачность остаются по исходному ТЗ и тестам CMP-01; одно изображение КУБ этого не подтверждает.

**CMP-04/05 + BANK-08:** один справочник собственных счетов: основной и дополнительные/резервные, отображаемое имя, БИК/банк/номер/корсчёт/валюта, компания/филиал и состояние. КУБ содержит пять счетов одного банка; название предназначено человеку, устойчивый ID — связям. Вложенное сохранение счёта должно ясно обозначать момент записи, чтобы отмена компании не создавала иллюзию rollback. Проверить смену основного, закрытие/архив/переименование, чужую компанию, дубли и повторный ввод; старые документы и операции сохраняются.

**CMP-02/06:** образец не определяет момент фиксации реквизитов и изображений в PayPlanner. Не закрывать решение по одному текущему PDF; проверить выбранное правило и совместимость прежних снимков, затем бухгалтерскую приёмку полного маршрута. Не создавать третий справочник компаний/банков ради похожего экрана.
