# Roadmap: раздел "Заметки" как рабочий стол напоминаний

Дата старта: 2026-06-16  
Критичность: средняя/высокая  
Контекст заказчика: нужен отдельный раздел заметок по примеру Webasyst Stickies. Это должен быть рабочий стол сотрудника для быстрых напоминаний, черновиков и рабочих моментов, чтобы не создавать полноценные задачи там, где достаточно стикера. Важно сразу учесть совместную работу: если заметка или доска доступна нескольким пользователям и кто-то меняет данные, остальные должны увидеть актуальное состояние.

## Как работать с этим roadmap

Статусы:

- `[ ]` не начато.
- `[~]` в работе.
- `[x]` выполнено и проверено кодом, тестами, кодировкой и локальной БД, если пункт требует БД.
- `[!]` заблокировано, причина указана рядом.
- `[decision]` требуется решение пользователя или бизнеса.
- `[acceptance]` требуется ручная приемка на реальных данных или в окружении заказчика.

Правила обновления:

- Перед реализацией открыть этот roadmap и проверить все связанные пункты.
- При начале работы заменить `[ ]` на `[~]`.
- Не отмечать `[x]`, пока не пройдены нужные проверки: backend tests, frontend tests, build, UTF-8, миграции, локальная БД, realtime-smoke, если пункт касается realtime.
- Если найден новый риск или бизнес-вопрос, добавить его сюда отдельным пунктом.
- После user-facing изменений добавить запись в `backend/AppReleases/releases.json`.

## Цели

1. Дать каждому сотруднику быстрый личный рабочий стол заметок без создания задач.
2. Поддержать общие доски, где несколько сотрудников видят и редактируют стикеры.
3. Сделать изменения заметок видимыми у других пользователей без ручного обновления страницы.
4. Сохранить компактный внутренний CRM-стиль: рабочий экран, не лендинг, без декоративной пустоты.
5. Разделить заметки и задачи: заметки не имеют обязательного исполнителя, срока, контроля, согласования и уведомлений как задача.
6. Обеспечить права доступа, аудит, восстановление после ошибок и понятную приемку.

## Входные примеры со скринов

- Левый список досок: "Разное", "Работа", "Офисные звонки", "Общее", "My stickies".
- Кнопка "New sticky".
- Кнопка "New board".
- Рабочее поле как пробковая/серая доска.
- Стикеры разных цветов и размеров.
- Свободное расположение стикеров на холсте.
- Пример общей доски: все сотрудники могут публиковать заметки.

## Ключевые бизнес-решения

- [x] Определить модель видимости досок. Итог: реализованы личные доски пользователя, общая доска и доски с участниками/ролями.
  - Вариант A: личные доски пользователя + общие доски для всех.
  - Вариант B: доски с участниками и ролями: владелец, редактор, читатель.
  - Рекомендация: сразу делать вариант B, но создать две системные доски по умолчанию: "Мои заметки" и "Общее".

- [x] Определить права раздела "Заметки". Итог: добавлена отдельная секция прав `notes`.
  - Вариант A: использовать существующее право `tasks`, потому что заметки похожи на напоминания.
  - Вариант B: добавить отдельную секцию `notes` в `RolePermissionCatalog`.
  - Рекомендация: отдельная секция `notes`, чтобы можно было дать заметки без доступа к журналу задач.

- [x] Определить политику редактирования чужих заметок. Итог: право редактирования на доске разрешает правки доступных стикеров, действия фиксируются в audit.
  - Вариант A: участник доски с `edit` может редактировать любые заметки на доске.
  - Вариант B: чужие заметки может редактировать только владелец доски/админ, остальные редактируют свои.
  - Рекомендация: для MVP `edit` на доске разрешает редактирование всех заметок на доске, действия фиксируются в audit.

- [x] Определить realtime-поведение при одновременном редактировании. Итог: используется optimistic concurrency с `409 Conflict` и UI разбора конфликта.
  - Вариант A: last-write-wins с полем `version`/`updatedAt` и мягким предупреждением о конфликте.
  - Вариант B: блокировка заметки на время редактирования.
  - Рекомендация: MVP на optimistic concurrency: `rowVersion`/`updatedAt`, конфликт возвращает `409`, UI предлагает перезагрузить или применить заново.

- [x] Нужны ли уведомления по заметкам. Итог: MVP работает без отдельных уведомлений, открытая доска обновляется через realtime.
  - Вариант A: без уведомлений, только realtime-обновление открытой доски.
  - Вариант B: уведомлять участников о новых заметках/упоминаниях.
  - Рекомендация: MVP без уведомлений, но оставить место для `@упоминаний` и optional notification events.

1. Отдельная секция прав `notes`.
2. Две доски: "Мои заметки" и "Общее".
3. CRUD заметок, drag/resize, цвет, autosave.
4. Realtime-события для открытой доски.
5. Optimistic concurrency через version/updatedAt.
6. Backend/frontend tests и проверка на локальной PostgreSQL.
7. Запись в "Что нового".

## Риски

- Realtime может стать шумным при частом drag/resize. Нужно debounce/batch layout updates.
- Одновременное редактирование текста может привести к потере данных без version conflict.
- Большие доски могут тормозить, если грузить все заметки без ограничений.
- Слишком широкие права общей доски могут раскрывать личные заметки, если перепутать visibility.
- На мобильном свободный холст может быть неудобен; нужен отдельный compact mode или горизонтальный canvas-scroll.

## Definition of Done

- Пользователь с правом `notes.canView` видит раздел "Заметки".
- Пользователь без `notes.canView` не видит раздел и не получает данные через API.
- Сотрудник может создать личную заметку без создания задачи.
- Общая доска позволяет нескольким пользователям работать с заметками.
- Изменение заметки одним пользователем отображается у другого на открытой доске без ручного refresh.
- Конфликт одновременного редактирования не приводит к тихой потере текста.
- Все изменения покрыты тестами, миграциями, UTF-8 check, build и локальной БД.
