# Защита публичных кабинетов и одноразовых ссылок

Дата актуализации: 5 августа 2026 года.

## Назначение

Документ фиксирует правила для анонимного согласования заказ-наряда, клиентского кабинета и отправки документов через мессенджеры. Эти маршруты доступны без JWT, поэтому каждый запрос обязан иметь собственный короткоживущий секрет, ограниченный размер и отдельный rate limit.

## Ограничения частоты и тела запроса

Политики сосредоточены в `PublicAccessRateLimitPolicies` и разделяются по внешнему IP после доверенного proxy-hop от локального nginx. Очередь отключена: лишний запрос сразу получает `429`, а не удерживает соединение.

| Поверхность | Лимит | Максимальное тело |
| --- | ---: | ---: |
| Согласование заказ-наряда | 10 запросов в минуту | 16 КиБ |
| Клиентский кабинет | 30 запросов в минуту | 16 КиБ |
| Одноразовый документ | 30 запросов в минуту | 4 КиБ для защищённого POST |
| Callback провайдера мессенджера | 300 запросов в минуту | 16 КиБ |

Токены ограничены 512 символами, идентификатор сообщения провайдера — 256 символами, статус — 32 символами, диагностический текст — 2000 символами. Некорректные модели отклоняются до бизнес-логики.

## Одноразовый документ

Новая ссылка имеет вид `https://crm.example/public/document/{publicId}#token={secret}`. Фрагмент после `#` браузер не отправляет nginx, backend, referrer или внешнему сайту. Страница сразу убирает секрет из адресной строки и хранит его только в `sessionStorage` до загрузки.

Файл не запрашивается автоматически. Получатель должен нажать «Скачать документ», поэтому preview-бот или антивирус мессенджера не расходует одноразовую ссылку. Frontend передаёт секрет в JSON-теле `POST /api/public/messenger-document-deliveries/{publicId}/download` с `no-store` и `no-referrer`.

Успешная выдача выполняет две SQL-команды:

1. компактная `AsNoTracking`-проекция проверяет срок, хеш токена, отмену и состояние ссылки;
2. условный атомарный `UPDATE` повторяет все условия и меняет счётчик `0 → 1`.

Поэтому ровно один из параллельных запросов получает файл. Токен длиннее 512 символов отклоняется без SQL. Ответ запрещает кэширование, range-повторы, индексирование, передачу referrer и MIME-sniffing. `Content-Disposition` явно открыт доверенному frontend через CORS, чтобы сохранить исходное имя файла.

Если тот же неизменяемый снимок отправляется повторно, сервис создаёт новый токен и начинает чистый цикл: сбрасывает прежние отметки очереди, отправки, доставки, чтения, ошибки, число попыток и загрузок. Старые даты не могут пометить новую ссылку уже прочитанной.

Старый GET с query-токеном временно сохранён только для уже отправленных ссылок. Новые сообщения и ответы подготовки его не создают и не возвращают секрет браузеру сотрудника. После истечения максимального срока старых ссылок (168 часов) маршрут можно удалить отдельным совместимым изменением.

`MessengerDocumentDelivery:PublicBaseUrl` должен содержать HTTPS-адрес frontend CRM, например `https://crm.elitpravo.com`, без `/api`.

## Callback провайдера

Callback принимается только для `telegram`, `max` и `whatsapp-business`. Неизвестный провайдер получает `404` до SQL. Секрет провайдера сравнивается в постоянное время; при отсутствующей настройке маршрут также отвечает `404`.

Состояние читается компактной проекцией и изменяется условным `ExecuteUpdateAsync`. Запоздалая ошибка или подтверждение доставки не может понизить уже сохранённое чтение. Повторный callback идемпотентен. Время провайдера, выходящее более чем на пять минут в будущее или раньше создания доставки, заменяется временем приёма сервером.

## Проверки

- отражением проверяются политики, размеры тел и ограничения моделей;
- реальные TestServer-запросы подтверждают точные пороги `429`;
- параллельный SQLite-тест доказывает однократное потребление ссылки;
- отдельные тесты подтверждают ноль SQL для слишком длинного токена и неизвестного провайдера;
- frontend-тест проверяет удаление фрагмента, отсутствие автоматического запроса и POST без секрета в URL;
- отдельный тест применяет все миграции к чистой PostgreSQL-БД и выполняет реальные атомарные callback и загрузку;
- аудит пакетных операций перечисляет все условные обновления callback и загрузки.
