# Roadmap: модернизация карточки задачи

Статус: `[!]` отложено. На 24 июня 2026 по этой задаче подготовлен только отдельный roadmap; реализация карточки задачи не начиналась, код и интерфейс по этому документу не менялись.

Последнее обновление: 24 июня 2026.

Документ фиксирует отдельную будущую задачу по обновлению карточки задачи. К реализации переходим только после закрытия старого недоделанного роадмапа или отдельного прямого решения пользователя.

## Цель

Сделать карточку задачи проще, компактнее и понятнее для ежедневной работы юристов и сотрудников, не меняя бизнес-логику задач без отдельного согласования.

Основная проблема от заказчика: текущая карточка задачи кажется сотрудникам сложной, из-за этого они неохотно заполняют задачи. Нужно обновить конструктив, добавить визуальные акценты, уменьшить лишние действия и оставить привычную логику работы там, где она уже используется.

## Принципы

- `[ ]` Сохранять текущую бизнес-логику задач, статусов, сроков, исполнителей, напоминаний, файлов и комментариев, если изменение не согласовано отдельно.
- `[ ]` Делать карточку компактной: основные действия должны быть видны без лишней прокрутки.
- `[ ]` Не перегружать форму обязательными полями для простых задач.
- `[ ]` Использовать цветовые акценты для статуса, приоритета, меток и важных действий.
- `[ ]` Поддержать два режима: компактный для быстрой работы и расширенный для подробной карточки.
- `[ ]` Проверять изменения на реальных сценариях: создание задачи, редактирование, завершение, комментарии, файлы, подзадачи, уведомления.

## Область Работ

### 1. Анализ Текущей Карточки

- `[ ]` Найти текущие компоненты создания и редактирования задачи.
- `[ ]` Описать текущие поля, обязательность, зависимости и права доступа.
- `[ ]` Проверить, какие поля реально используются в журнале задач, календаре, уведомлениях, делах и карточках клиентов.
- `[ ]` Зафиксировать, какие действия нельзя ломать: создание, изменение статуса, назначение исполнителя, перенос срока, завершение, файлы, комментарии, напоминания.
- `[ ]` Составить карту API и моделей, которые затрагивает карточка задачи.

Definition of done:
- `[acceptance]` Есть список всех текущих полей и действий карточки.
- `[acceptance]` Понятно, какие изменения являются только UI, а какие затрагивают бизнес-логику.

### 2. Новый Компактный Вид

- `[ ]` Сделать новый компактный вид карточки задачи.
- `[ ]` Разместить сверху путь/контекст: дело, доска или источник задачи.
- `[ ]` Сделать крупное поле названия задачи.
- `[ ]` Оставить описание задачи в основной области.
- `[ ]` В правую колонку вынести быстрые параметры: статус, исполнитель, дата, подзадачи, файлы, приоритет, пользовательские поля, метки, создатель и проект/дело.
- `[ ]` Сделать блок комментариев похожим на чат: поле ввода, кнопка отправки, прикрепление файла, упоминания.
- `[ ]` Проверить, что карточка помещается на типовых экранах без избыточной пустоты.

Definition of done:
- `[acceptance]` Сотрудник может быстро создать или открыть задачу и понять, что нужно заполнить в первую очередь.
- `[acceptance]` Основные параметры задачи доступны без поиска по длинной форме.

### 3. Расширенный Вид

- `[ ]` Добавить расширенный режим карточки.
- `[ ]` В расширенном режиме разделить карточку на две рабочие зоны: слева поля задачи, справа комментарии, файлы, таймер и активность.
- `[ ]` Добавить переключатель "Компактный вид" / "Расширенный вид".
- `[decision]` Решить, где хранить выбранный пользователем режим: локально в браузере, в профиле пользователя или в настройках роли.
- `[ ]` Запоминать последний выбранный режим после согласования места хранения.

Definition of done:
- `[acceptance]` Пользователь может переключаться между компактным и расширенным видом без потери данных.
- `[acceptance]` Выбранный режим не мешает текущим сценариям создания и редактирования задачи.

### 4. Связь Задачи С Объектами CRM

- `[ ]` Добавить удобный выбор связанного дела, клиента/контакта и организации.
- `[ ]` Если дело выбрано, автоматически подтягивать доступные связанные данные, где это безопасно.
- `[ ]` Если организация или клиент выбирается вручную, не перезаписывать выбор без подтверждения пользователя.
- `[ ]` Проверить права доступа к связанным объектам.
- `[decision]` Уточнить окончательный набор связей: дело, клиент, контакт, юридическое лицо, договор, счет или только часть из них.

Definition of done:
- `[acceptance]` Задачу можно связать с нужным рабочим объектом без длинного поиска по форме.
- `[acceptance]` Автоподстановка не создает неверных связей.

### 5. Исполнитель, Согласующие, Наблюдатели

- `[ ]` Сделать компактный выбор исполнителя через выпадающее окно с поиском.
- `[ ]` Поддержать выбор галочками, если поле допускает несколько сотрудников.
- `[ ]` После выбора показывать сотрудников компактными карточками или аватарами.
- `[ ]` Добавить удаление и замену выбранного сотрудника.
- `[ ]` Аналогично реализовать согласующих.
- `[ ]` Аналогично реализовать наблюдателей.
- `[decision]` Подтвердить ограничения: один исполнитель или несколько исполнителей для задачи.

Definition of done:
- `[acceptance]` Исполнителя, согласующих и наблюдателей можно выбрать быстрее, чем в текущей форме.
- `[acceptance]` Изменения корректно сохраняются и отображаются в журнале задач и уведомлениях.

### 6. Статус И Завершение Задачи

- `[ ]` Обновить визуальное отображение статуса.
- `[ ]` Добавить быстрый выбор статуса в правой колонке.
- `[ ]` Добавить отдельное действие завершения задачи.
- `[ ]` Поле "Результат" сделать недоступным до завершения задачи.
- `[ ]` При завершении задачи показывать поле результата или модальное окно ввода результата.
- `[ ]` Не разрешать сохранить результат заранее, если задача еще не завершена.
- `[decision]` Уточнить, результат обязателен при завершении или может быть пустым.

Definition of done:
- `[acceptance]` Результат нельзя заполнить раньше времени.
- `[acceptance]` При завершении задачи пользователь понимает, где ввести результат.
- `[acceptance]` Старые задачи с уже заполненным результатом отображаются корректно.

### 7. Дата, Время, Расписание, Длительность

- `[ ]` Сделать компактный блок даты.
- `[ ]` При выборе даты показывать календарь.
- `[ ]` Под календарем показывать время начала.
- `[ ]` Ниже показывать длительность.
- `[ ]` Сохранить существующие правила напоминаний, переносов и календарной синхронизации.
- `[ ]` Проверить работу с часовыми поясами.

Definition of done:
- `[acceptance]` Пользователь быстро задает дату, время и длительность без переходов по нескольким полям.
- `[acceptance]` Календарь и уведомления получают те же данные, что и раньше.

### 8. Подзадачи

- `[ ]` Показать подзадачи прямо в карточке.
- `[ ]` Добавить быстрое создание подзадачи.
- `[ ]` Поддержать чек-лист для простых подзадач, если полноценная связанная задача пока не нужна.
- `[decision]` Решить, подзадачи должны быть полноценными задачами CRM или легким чек-листом внутри задачи.
- `[ ]` Добавить быстрые действия по подзадаче: назначить, срок, открыть, удалить.

Definition of done:
- `[acceptance]` Пользователь может разбить задачу на простые шаги без выхода из карточки.
- `[acceptance]` Подзадачи не ломают текущие отчеты и журнал задач.

### 9. Файлы

- `[ ]` Сделать компактный блок файлов.
- `[ ]` Поддержать drag-and-drop.
- `[ ]` Показать список файлов с названием, размером, временем загрузки и автором.
- `[ ]` Добавить скачивание и меню действий по файлу.
- `[ ]` Убрать дублирующие кнопки загрузки, если уже есть общий центр загрузки.
- `[decision]` Подтвердить, нужна ли загрузка файлов прямо в карточке или достаточно общего центра загрузки.

Definition of done:
- `[acceptance]` Файл можно прикрепить и скачать из карточки задачи.
- `[acceptance]` Нет двух одинаковых способов загрузки, которые путают пользователя.

### 10. Комментарии, Упоминания, Активность

- `[ ]` Сделать комментарии в виде компактного чата.
- `[ ]` Поддержать прикрепление файла к комментарию.
- `[ ]` Поддержать упоминания через `@`.
- `[ ]` В окне упоминаний разделить результаты по вкладкам: сотрудники, команда, проекты, задачи, документы.
- `[ ]` Оставить вкладку активности с историей изменений.
- `[ ]` Оставить таймер, если он уже используется в задачах.

Definition of done:
- `[acceptance]` Комментарии удобно читать и писать.
- `[acceptance]` Упоминания создают корректные уведомления.
- `[acceptance]` История изменений остается доступной.

### 11. Приоритеты И Метки

- `[ ]` Сделать цветной выбор приоритета: без приоритета, низкий, средний, высокий, критический.
- `[ ]` Показать выбранный приоритет цветным индикатором.
- `[ ]` Сделать добавление меток через поиск.
- `[ ]` Отображать выбранные метки цветными чипами.
- `[ ]` Добавить создание новой метки, если у пользователя есть право.
- `[decision]` Проверить, метки общие для всей CRM или личные/командные.

Definition of done:
- `[acceptance]` Приоритет и метки видны сразу и не требуют открытия дополнительной формы.
- `[acceptance]` Метки сохраняются и отображаются в списках задач.

### 12. Верхняя Панель Действий

- `[ ]` Добавить кнопку запуска/таймера.
- `[ ]` Добавить просмотр или наблюдение за задачей.
- `[ ]` Добавить быстрые напоминания.
- `[ ]` Добавить повтор или цикличность, если это поддерживается текущей логикой.
- `[ ]` Добавить копирование ссылки на задачу.
- `[ ]` Добавить переключение вида карточки.
- `[ ]` Добавить меню дополнительных действий: добавить обложку, дублировать задачу, сделать подзадачей, отправить в архив, удалить.
- `[decision]` Подтвердить, какие действия реально нужны в первой версии, а какие можно оставить на второй этап.

Definition of done:
- `[acceptance]` Частые действия доступны с верхней панели.
- `[acceptance]` Редкие и опасные действия спрятаны в меню и имеют подтверждение, если нужно.

### 13. Настройки Уведомлений

- `[decision]` Решить, где хранить настройки уведомлений: в профиле пользователя или в настройках роли.
- `[decision]` Рекомендация по текущему ТЗ: хранить в профиле пользователя, чтобы не было конфликтов между персональными привычками и ролью.
- `[ ]` Вынести персональные настройки напоминаний из карточки задачи, если это подтверждено.
- `[ ]` В профиле пользователя добавить настройки: за 7 дней, за 3 дня, за день, за час, за 15 минут, в срок, каждый день просрочки.
- `[ ]` В профиле пользователя добавить каналы: в системе, Email, Telegram.
- `[ ]` Проверить, как эти настройки взаимодействуют с Web Push и центром уведомлений.

Definition of done:
- `[acceptance]` Пользователь управляет своими уведомлениями в одном месте.
- `[acceptance]` Карточка задачи не перегружена настройками напоминаний.
- `[acceptance]` Нет дублей уведомлений из-за конфликтующих настроек.

### 14. Права И Роли

- `[ ]` Проверить права на просмотр, создание, редактирование и удаление задачи.
- `[ ]` Проверить права на смену исполнителя.
- `[ ]` Проверить права на добавление согласующих и наблюдателей.
- `[ ]` Проверить права на файлы и комментарии.

- `[ ]` Проверить права на создание меток и пользовательских полей.

Definition of done:
- `[acceptance]` Новый UI не открывает действий, которые запрещены ролью.
- `[acceptance]` Backend также запрещает прямые запросы без прав.

- `[ ]` Проверить карточку на desktop.
- `[ ]` Проверить карточку на ноутбуке с меньшей высотой экрана.
- `[ ]` Проверить карточку на планшетной ширине.

- `[ ]` Проверить пустые состояния: нет файлов, нет комментариев, нет подзадач, нет исполнителя.

Definition of done:
- `[acceptance]` Карточка выглядит аккуратно и остается рабочей на основных размерах экрана.

- `[ ]` Проверить локальную БД после изменений.

Definition of done:
- `[acceptance]` Основные сценарии карточки покрыты тестами.
- `[acceptance]` Локальная проверка на БД проходит без ошибок.

### 17. Что Нового

- `[ ]` Описать для пользователей, где изменилась карточка задачи и что стало проще.
- `[ ]` Если настройки уведомлений будут вынесены в профиль, описать это отдельным пунктом.

Definition of done:
- `[acceptance]` Пользователи видят понятное описание изменений после релиза.

- `[ ]` Инвентаризация текущей карточки.
- `[ ]` Уточнение решений по спорным пунктам.
- `[ ]` Подготовка структуры компонентов без удаления старой логики.

### Этап 2. Компактный Вид

- `[ ]` Новый основной layout.
- `[ ]` Правая колонка быстрых параметров.
- `[ ]` Статус, исполнитель, дата, приоритет, метки.

### Этап 3. Правила Завершения

- `[ ]` Результат доступен только при завершении.

### Этап 4. Расширенный Вид

- `[ ]` Переключение компактного и расширенного вида.

### Этап 6. Финальная Приемка

## Открытые Решения

- `[decision]` Результат при завершении обязателен или необязателен.
- `[decision]` Исполнитель один или несколько.
- `[decision]` Подзадачи: полноценные задачи или чек-лист.
- `[decision]` Где хранить выбранный вид карточки: браузер, профиль пользователя или роль.
- `[decision]` Где хранить настройки уведомлений: профиль пользователя или роль.
- `[decision]` Нужна ли загрузка файлов прямо в карточке, если есть общий центр загрузки.
- `[decision]` Какие действия верхнего меню входят в первую версию.

## Не Входит В Первую Версию Без Отдельного Решения

- `[ ]` Полная переработка журнала задач.
- `[ ]` Изменение правил уведомлений для всей CRM.
- `[ ]` Изменение модели прав ролей.
- `[ ]` Новый модуль согласований, если текущие согласующие являются только участниками задачи.
- `[ ]` Массовая миграция старых задач.

## Условия Старта

- `[!]` Старый недоделанный роадмап должен быть закрыт или пользователь должен отдельно подтвердить приоритет этой задачи.
- `[ ]` Перед стартом открыть `docs/remaining-roadmap.md` и проверить, что нет более срочных незакрытых пунктов.
- `[ ]` Перед реализацией сделать отдельную ветку.
- `[ ]` Перед реализацией уточнить решения из блока "Открытые решения".
