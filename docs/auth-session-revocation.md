# Серверный отзыв пользовательских сессий

Дата: 5 августа 2026 года.

## Назначение

Обычный выход из CRM должен завершать доступ не только в текущей вкладке. Если JWT был скопирован, остался на другом устройстве или одновременно обновлялся браузером, после выхода он также обязан перестать работать.

## Правило работы

- у каждого пользователя хранится целочисленная версия серверной сессии `AuthTokenVersion`;
- JWT содержит снимок этой версии в claim `payplanner:auth-token-version`;
- уже существующая проверка пользователя сопоставляет версию JWT с базой одновременно с проверкой активности, одобрения и роли;
- `POST /api/auth/logout` одним условным SQL `UPDATE` увеличивает версию и записывает время выхода;
- все JWT со старой версией после этого получают `401 Unauthorized`;
- refresh принимает только токен с текущей версией и не может восстановить отозванную сессию;
- два параллельных logout не увеличивают версию повторно: изменить строку может только запрос с актуальной исходной версией.

## Совместимость публикации

JWT, выпущенные до появления claim, считаются токенами версии 0. Пока пользователь не выполнил новый серверный выход, такие токены продолжают работать. Первый logout увеличивает версию до 1 и тем самым отзывает также все старые JWT без claim. Это позволяет включить механизм без принудительного завершения всех действующих сессий во время деплоя.

## Клиентское поведение

При нажатии «Выйти» браузер сначала вызывает серверный logout, затем очищает офлайн-календарь и локальные копии токена. Если сеть недоступна, локальные данные всё равно удаляются, чтобы пользователь не остался визуально авторизованным на текущем устройстве.

## Производительность и хранение

- проверка версии добавлена в уже существующую SQL-проекцию пользователя и не создаёт отдельного запроса на каждый API-вызов;
- logout выполняет ровно одну SQL-команду и не загружает сущность пользователя;
- JWT и их хеши в базе не хранятся, поэтому таблица сессий и регламентная очистка не требуются;
- поле имеет значение по умолчанию 0, а миграции подготовлены отдельно для SQLite и PostgreSQL.

## Проверки

Автоматические тесты закрепляют выпуск версии в JWT, совместимость старого токена версии 0, отказ при неверной или дублированной версии, мгновенный отзыв, идемпотентный logout, запрет refresh после отзыва, порядок действий браузера и применение миграций на чистой PostgreSQL-БД.
