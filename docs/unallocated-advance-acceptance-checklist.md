# Чек-лист приемки нераспределенных авансов

Дата подготовки: 15.06.2026.

Цель: пройти с заказчиком полный сценарий контроля входящих денег без закрывающих документов: от предупреждения при создании платежа до принятия аванса, распределения в долг и отражения в акте сверки.

## Условия приемки

- Проверка проводится на согласованном тестовом стенде или копии актуальной базы.
- Роль проверяющего должна видеть разделы `Платежи`, `Деньги`, `Клиенты`, `Отчеты` и иметь право редактировать платежи для финансовых действий.
- Реальные платежи не менять без отдельного подтверждения заказчика.
- Отдельный платеж Винокурова из обращения проверять только на актуальной копии базы или продукционном стенде в read-only режиме до бизнес-решения.
- Перед ручным показом выполнить автоматическую приемку:

```powershell
npm run roadmap:advance-status
npm run test:advance-acceptance
```

Ожидаемый результат:

- roadmap показывает `Implementation: 100%`;
- открытых технических пунктов `0`;
- `npm run test:advance-acceptance` проходит без ошибок;
- в `artifacts/advance-acceptance` появляется JSON-отчет и Markdown-сводка приемки;
- рабочий `payplanner.db` не меняется, потому что smoke работает на временной SQLite-копии.

## Сценарий 1. Платеж без счета

1. Открыть раздел `Платежи`.
2. Создать входящий платеж клиента с фактическим получением денег.
3. Не выбирать счет, акт и закрывающий документ.
4. Сохранить платеж.

Ожидаемый результат:

- система показывает предупреждение `Нераспределенный аванс`;
- пользователь может вернуться к привязке документов;
- при подтверждении платеж сохраняется как аванс на разбор или как принятый аванс согласно выбранному действию;
- в истории платежа фиксируется решение по контролю аванса.

## Сценарий 2. Мониторинг платежей на разбор

1. Открыть раздел `Платежи`.
2. Найти блок `Нераспределенные авансы`.
3. Нажать фильтр `На разбор`.
4. Проверить строку созданного платежа.

Ожидаемый результат:

- платеж виден в списке контроля аванса;
- в строке понятен статус контроля;
- доступны действия по платежу с учетом прав пользователя;
- если у роли нет права редактирования платежей, финансовые действия недоступны.

## Сценарий 3. Индикатор в разделе Деньги

1. Открыть раздел `Деньги`.
2. Найти блок `Контроль авансов`.
3. Нажать `Открыть разбор`.

Ожидаемый результат:

- блок показывает количество и сумму платежей, требующих решения;
- переход открывает `Платежи` с фильтром платежей на разбор;
- пользователь не ищет такие поступления вручную.

## Сценарий 4. Принятие аванса

1. В разделе `Платежи` открыть платеж со статусом контроля `Требует решения`.
2. Нажать действие `Аванс` или `Принять как аванс`.
3. Указать причину решения.
4. Подтвердить действие.

Ожидаемый результат:

- статус контроля меняется на `Принят как аванс`;
- баланс клиента увеличивается на фактически полученную сумму;
- создается балансовая проводка `UnallocatedAdvance`;
- повторное принятие не создает дубль проводки.

## Сценарий 5. Распределение аванса в долг

1. Найти платеж со статусом `Принят как аванс`.
2. Нажать `Распределить`.
3. Выбрать открытый входящий платеж или долг этого же клиента.
4. Указать сумму не больше доступного остатка аванса и остатка долга.
5. Подтвердить зачет.

Ожидаемый результат:

- выбранный долг уменьшается или закрывается;
- баланс клиента уменьшается на сумму зачета;
- создается проводка `CreditApplied`;
- если аванс полностью распределен, исходный авансовый платеж получает статус `Распределен`;
- частично распределенный аванс остается доступным с остатком.

## Сценарий 6. Акт сверки

1. Открыть карточку клиента.
2. Перейти к акту сверки или финансовой истории.
3. Включить отображение `Авансы и корректировки`.
4. Проверить строки по принятому авансу и зачету.

Ожидаемый результат:

- принятый аванс отображается отдельной понятной строкой;
- сумма не задваивается с обычной оплатой;
- зачет аванса корректно влияет на итоговое сальдо;
- при отключении `Авансы и корректировки` авансовые строки скрываются.

## Сценарий 7. Спорный платеж Винокурова

1. Не изменять реальный платеж без подтверждения заказчика.
2. В разделе `Платежи` открыть блок `Нераспределенные авансы`.
3. Запустить диагностику по признакам из обращения: клиент `Винокуров`, дата `02.03.2026`, сумма `7 100`.
4. Зафиксировать результат диагностики.

Ожидаемый результат:

- диагностика работает read-only и не меняет деньги;
- видно, найден ли платеж в актуальной базе;
- видно, есть ли у платежа счет, акт, номер счета, статус контроля и балансовая проводка;
- дальнейшее действие выбирается отдельно: принять как аванс, распределить, вернуть или игнорировать.

## Критерии завершения

- Все автоматические проверки перед приемкой прошли.
- Сценарии 1-6 показаны заказчику без ошибок.
- По сценарию 7 получено решение заказчика или подтверждено, что платеж отсутствует в текущей копии базы.
- Все замечания заказчика занесены в roadmap как `[ ]`, `[!]`, `[decision]` или `[acceptance]`.
