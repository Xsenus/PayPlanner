# Мессенджер PayPlanner по требованиям YouGile

## Цель

Реализовать внутри PayPlanner рабочие чаты уровня, описанного в задаче PAY-1 компании PayPlanner в YouGile: чат задачи, командные каналы и личные диалоги, с файлами, ответами, реакциями, упоминаниями, поиском, уведомлениями и строгим доступом участников. Изменения в карточке задачи должны одинаково работать в старом и новом интерфейсе.

## Прогресс

- Всего пунктов: 31.
- Завершено: 29.
- В работе: 1.
- Заблокировано / требует решения / приемки: 1.
- Готовность: 94%.

## Требования и реализация

- [x] Изучить описание и обсуждение PAY-1 только в компании PayPlanner в YouGile.
- [x] Скачать production-БД с VPS, проверить контрольную сумму, восстановить в отдельную локальную БД и отключить в копии внешние отправки.
- [x] Спроектировать сущности чатов, участников, сообщений, файлов, реакций и состояний прочтения с индексами и ограничениями.
- [x] Добавить миграции SQLite и PostgreSQL и проверить чистую установку и обновление production-копии.
- [x] Реализовать чат задачи с автоматическим доступом участников задачи.
- [x] Реализовать командные каналы и управление их участниками.
- [x] Реализовать личный диалог строго между двумя пользователями без дублей.
- [x] Реализовать сообщения, редактирование и мягкое удаление только своих сообщений.
- [x] Реализовать ответы, реакции, упоминания и закрепление не более трех сообщений.
- [x] Реализовать безопасные вложения с проверкой доступа, размера и типа.
- [x] Реализовать курсорную загрузку по 50 сообщений и поиск по тексту, автору, дате и упоминанию. Текстовый поиск запускается по «Найти»/Enter без запроса на каждую букву; запоздалый ответ прежней загрузки не заменяет новый результат.
- [x] Реализовать отметку прочтения и счетчики непрочитанных: отметка принимается только для сообщения выбранного чата, а просмотр результатов поиска не сбрасывает непрочитанные сообщения вне результата.
- [x] Реализовать настройки уведомлений «все / упоминания / отключены» и уведомления об ответах, упоминаниях и созданных из сообщений задачах.
- [x] Реализовать обновления SignalR не позднее 10 секунд и системные сообщения об изменении статуса и исполнителя задачи.
- [x] Реализовать создание задачи из сообщения и обратную ссылку на нее в чате.
- [x] Добавить раздел «Мессенджер» с адаптивным интерфейсом, группировкой по датам и доступными действиями.
- [x] Добавить вкладку «Чат» в обе карточки задачи и проверить настройку выбора карточки администратором.
- [x] Отображать имена вместо технических номеров упоминаний и показывать участников в заголовке чата задачи.
- [x] Передавать время чата с признаком UTC и группировать сообщения по местной дате сотрудника, в том числе около полуночи.
- [x] Добавить backend- и frontend-тесты на права, негативные сценарии, границы, поиск и основные пользовательские потоки.
- [x] Добавить понятную запись в «Что нового» и выполнить финальные проверки backend, frontend, сборки и кодировки.
- [x] Добавить отдельные приглашения в чат задачи, не выдающие прав на саму задачу; постановщик управляет приглашёнными, отзыв сразу закрывает чтение сообщений и файлов.
- [x] Добавить личное скрытие и архив чата без удаления чужой переписки; скрытый чат возвращается с новым сообщением, архивный сохраняет непрочитанные.
- [x] Разделить список чатов по типам и архиву, подсветить непрочитанные, сделать ширину списка регулируемой.
- [x] Сделать название и упоминания номеров задач переходами к карточкам; пояснить видимость ответов и упоминаний и показывать имена прочитавших.
- [x] Сохранять незавершённый текст сообщения отдельно для каждого чата и сотрудника в пределах вкладки, восстанавливать после обновления страницы и удалять только после успешной отправки. Файлы при обновлении страницы браузер восстановить не может. Два пути автоматической перезагрузки при устаревших файлах интерфейса заменены на предложение ручного обновления после сохранения работы. Не доказано, что именно такой сбой вызвал обновление страницы на компьютере заказчика; для этого нужны журналы браузера во время повторения.
- [x] Не сбрасывать прокрутку и текст при новом сообщении; показывать новые сообщения внизу, если пользователь уже читает конец чата, и сохранять место чтения при загрузке истории. Чат открывается с первого непрочитанного даже при истории длиннее 50 сообщений, поддерживает догрузку вперёд и кнопку перехода в конец. Прочтение не отмечается при одном только открытии длинного чата или просмотре результатов поиска. Серверный курсор и общий компонент обеих карточек покрыты тестами; живой диалог двух сотрудников остаётся на приёмку.
- [x] При создании задачи из сообщения предложить отдельное краткое название и заполнить описание текстом исходного сообщения; позволить исправить оба поля до сохранения. Контракт API поддерживал описание ранее, компонентный и полный клиентский набор пройдены.
- [x] Включаемое автором сообщения напоминание «нет ответа»: первое через 24 часа после включения, далее не чаще раза в сутки, только автору в CRM, до прямого ответа другого участника или ручного отключения. Удаление сообщения и утрата доступа к чату прекращают напоминания. В комментарии PAY-1 заказчик предложил суточный интервал; точечные проверки прав и доставки, миграции SQLite и PostgreSQL на чистой базе и при переходе с прежней схемы прошли. Реальная приёмка двумя сотрудниками остаётся открытой.
- [~] Проверить новые сценарии доступа, обе карточки задачи, миграции, сборку и локальный интерфейс; обновить «Что нового» и комментарий PAY-1.
- [acceptance] Провести ручную приемку уведомлений, мобильного вида и сценария двух одновременно подключенных пользователей.

Новые пожелания PAY-1 от 24 сентября уточнены с заказчиком: приглашённые сотрудники участвуют только в чате задачи; скрытие и архив действуют лично для пользователя, без удаления сообщений у коллег.

Дополнительная проверка синхронизации выявила, что обычное редактирование задачи отзывает приглашение гостя чата. Исправлено: приглашение сохраняется после обновления задачи, ранее отозванное не восстанавливается. Добавлен серверный регрессионный тест; локальная визуальная проверка и ручная приёмка двумя пользователями остаются открытыми.

Локальная проверка 25 сентября на отдельной PostgreSQL-БД и в двух одновременно открытых браузерных сессиях выявила, что адресат не видит новый диалог до обновления страницы. Исправлены обновление списка чатов по уже существующему событию, оповещение о создании канала и приглашении участников, а также немедленное сохранение черновика при вводе. Повторный прогон подтвердил доставку сообщения, появление нового канала у приглашённого без перезагрузки, восстановление черновика, личный архив и отсутствие горизонтальной прокрутки на экране 390 px; ошибок консоли не было. Это локальная проверка тестовых пользователей, а не приёмка на рабочих учётных записях заказчика. Остались проверка обеих карточек задачи после этой правки, итоговые полные наборы и приёмка на рабочей версии.

При повторной проверке dev-сервер обнаружил дублирование одного сообщения в переписке при гонке ответа на отправку и realtime-загрузки. Добавлено объединение сообщений по их идентификатору при отправке и догрузке; регрессионный тест моделирует именно этот порядок событий. Повторные полный клиентский набор и браузерный прогон требуются после последней правки.

Итог после исправления: 2997 серверных и 1608 клиентских тестов, линтер, типизация, аудит кодировки и production-сборка прошли. Повторный браузерный прогон на двух тестовых сотрудниках подтвердил доставку, новый канал, черновик, личный архив, мобильный вид и отсутствие повторяющихся идентификаторов сообщений; ошибок в консоли браузера и свежем выводе локальных серверов не было. Отдельная PostgreSQL-БД после проверки удалена. В обеих карточках задачи используется один и тот же проверенный компонент чата, но ручная проверка открытия старой и новой карточки в рабочей среде и приёмка заказчиком остаются открытыми; поэтому пункт `[~]` и общий прогресс пока не закрываются.

Дополнительный компонентный тест проверяет настройку администратора для старой и новой карточки: в каждой открывается чат именно просматриваемой задачи. Он не заменяет ручную проверку рабочих учётных записей и двух одновременно подключённых сотрудников после публикации.

Новые комментарии и PNG заказчика от 24 сентября показали ещё три дефекта и пожелание: прокрутка перескакивает при каждом сообщении, перезагрузка страницы стирает недописанный текст, при создании задачи из сообщения не хватает отдельного описания, а автор хочет включаемый «колокольчик» при отсутствии ответа. Первые три изменения выполнены в общем компоненте обеих карточек и мессенджера: прошли 1571 клиентский тест, линтер, типизация, аудит кодировки и production-сборка. Причина фактической перезагрузки рабочего браузера пока не подтверждена, поэтому сохранение черновика не объявляется её устранением. Позднее добавлен включаемый автором суточный контроль отсутствия ответа; публикация и приёмка на двух пользователях ещё впереди.

Повторный аудит нашёл два собственных механизма CRM, которые автоматически перезагружали страницу при ошибке загрузки устаревшего файла интерфейса. Они заменены предупреждением с ручной кнопкой обновления; пользователь может сначала сохранить работу. Проверки охватывают оба пути и отсутствие реакции на постороннюю ошибку; полный клиентский набор (1581 тест), линтер, типизация, аудит кодировки и сборка прошли. Точное происхождение обновления на компьютере заказчика без журналов браузера остаётся неподтверждённым; напоминание без ответа не реализовано.

Повторная проверка показала, что открытие длинного чата сразу помечало последние сообщения прочитанными, а сервер не отдавал позицию первого непрочитанного. Добавлены курсор непрочитанного и загрузка вперёд; состояние обеих карточек задачи и мессенджера использует общий компонент. Прошли 2960 серверных и 1573 клиентских теста, линтер, типизация, аудит кодировки и production-сборка. Живой диалог двух сотрудников остаётся на приёмку.

Для выбранного автором сообщения добавлен «колокольчик» без ответа: первое напоминание через сутки после включения, последующие — не чаще раза в сутки. Прямой ответ другого участника, ручное отключение, удаление исходного сообщения или утрата доступа прекращают контроль. Кнопка действий у сообщения теперь видна и на сенсорном экране без наведения мыши. Полные наборы (2966 серверных и 1591 клиентский тест), линтер, типизация, аудит кодировки и сборка прошли. Миграции проверены на чистых SQLite и PostgreSQL и при переходе с предыдущей схемы; локальные тестовые базы удалены. Реальная доставка и вид на устройствах сотрудников остаются на приёмку после публикации.

## Связанные задачи YouGile

- PAY-1 — текущая реализация мессенджера.
- PAY-2 содержит только название раздела «Зарплата» без постановки и критериев приемки, поэтому не включена в реализацию до появления требований.
- PAY-3 сопоставлена с действующей дорожной картой `docs/tz-gap-court-providers-roadmap-2026-07-29.md`: интерфейс судебного раздела уже реализован, а внешние провайдеры требуют согласованных тестовых дел, фикстур и правомерного доступа.

## Определение готовности

Функция считается готовой после прохождения автоматических тестов, миграций на чистой и восстановленной production-БД, проверки обеих карточек задачи, отсутствия ошибок браузера и сервера, а также ручной проверки доступа и доставки событий между двумя пользователями.
