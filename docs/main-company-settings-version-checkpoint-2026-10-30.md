## Изменения

Два отрицательных baseline-сценария подтвердили: устаревшая форма принималась после изменения списка другим администратором как через полную форму, так и через прежний выбор основной компании. Такая полная замена могла удалить уже добавленную компанию и назначения сотрудников.

Чтение настроек теперь возвращает администратору непрозрачную `SettingsVersion`. Она вычисляется из четырёх существующих записей настроек: списка, основного и прежнего ID компании, правила фиксации снимков документов, включая метаданные записей. Новых столбцов или миграций нет. Состояние списка, правило и версия читаются одним SQL-запросом. Для администратора сведения о компаниях выбираются по этому же состоянию, а не по более раннему чтению при проверке доступа. Сотрудник по-прежнему видит только назначенные собственные компании и не получает административную версию.

Полная замена списка требует захваченную при открытии `ExpectedVersion`. Проверка выполняется внутри прежней собственной `Serializable`-транзакции после актуального доступа и до любых изменений. Отсутствующая, неверная или устаревшая версия возвращает `409` без актуального токена в ответе. Старый клиент без версии должен обновить страницу. Предварительная загрузка свежего токена непосредственно перед сохранением не используется. Прежний отдельный выбор основной компании остаётся добавляющим действием над актуальным списком внутри транзакции; он меняет версию и блокирует старые полные формы, но не заменяет их список по старому снимку.

Форма сохраняет выбор после отказа и не повторяет запрос автоматически. Кнопка «Загрузить сохранённые настройки» явно заменяет несохранённый выбор; предупреждение об этом видно рядом. После успешной записи следующая правка использует версию из ответа. Повторное нажатие во время сохранения не создаёт второй запрос. Нет подтверждённой версии — нет сохранения.

Форма привязана к пользователю, роли и идентичности сеанса через существующие средства владения асинхронными операциями. При смене владельца она создаётся заново; прежние ответы/ошибки не меняют новый список, не показывают успех и не обновляют справочник другого пользователя. Без действующего администратора форма не загружает настройки и не отправляет изменения. Серверная проверка актуальной роли и согласования сохранена; UI не заменяет её.
