# Яндекс.Календарь: подключение и синхронизация задач

## Где находится раздел

Подключение Яндекс.Календаря находится в профиле пользователя рядом с блоком Google Calendar.

Путь для пользователя: профиль пользователя -> блок "Яндекс.Календарь".

В блоке пользователь видит статус подключения, может открыть OAuth-авторизацию Яндекса, сохранить правила синхронизации, запустить обмен вручную, отключить подключение, посмотреть созданные календари и последние события синхронизации.

При отключении Яндекс.Календаря CRM сначала удаляет созданные PayPlanner календари и события во внешнем календаре. Если Яндекс не подтвердил удаление хотя бы одного календаря или события, подключение не отключается, а причина сохраняется в журнале синхронизации.

В настройках подключения можно указать дату начала синхронизации. Если дата задана, CRM создаёт и обновляет в Яндекс.Календаре только задачи со сроком выполнения начиная с этой даты. Уже созданные события по задачам раньше выбранной даты удаляются при следующей синхронизации, но при полном отключении подключения удаляются все созданные PayPlanner календари и события независимо от этой даты.

## Что нужно настроить администратору

Перед подключением пользователей администратор должен подготовить OAuth-приложение Яндекса и включить настройки Яндекса в CRM.

1. Создать OAuth-приложение в кабинете Яндекса.
2. Разрешить доступ к календарю и данным пользователя, которые нужны для OAuth-подключения.
3. Добавить redirect URI CRM:

   `https://<домен CRM>/api/yandex-calendar/auth/callback`

   Для локальной проверки используется адрес локального backend:

   `http://localhost:<порт backend>/api/yandex-calendar/auth/callback`

4. В CRM сохранить настройки OAuth Яндекса:

   - `auth.yandex.enabled` = `true`
   - `auth.yandex.clientId` = Client ID из приложения Яндекса
   - `auth.yandex.clientSecret` = Client Secret из приложения Яндекса

5. Для фоновой синхронизации должен быть включен флаг внешней календарной синхронизации:

   `FeatureFlags:Legal:ExternalCalendarSync = true`

Интервал фонового обмена можно настроить параметром:

`YandexCalendarSync:IntervalMinutes`

Если параметр не задан, сервис использует стандартный интервал 10 минут.

## Как работает синхронизация

Яндекс.Календарь работает по тем же правилам, что Google Calendar:

- обычный пользователь синхронизирует задачи, где он указан исполнителем или участником;
- администратор может синхронизировать все задачи и раскладывать их по календарям сотрудников;
- при создании или изменении задачи в CRM событие создается или обновляется во внешнем календаре;
- при удалении задачи CRM сначала удаляет связанные события из подключенных календарей, а затем удаляет саму задачу;
- при удалении пользователя CRM удаляет созданные для него системные календари PayPlanner.

В Яндекс.Календаре события создаются через CalDAV. В событие записывается служебная связь с задачей CRM, поэтому последующие обновления меняют существующее событие, а не создают дубликаты.

## Как работает обмен между Google и Яндексом

Если у пользователя подключены оба календаря, CRM становится центральной точкой согласования.

1. Пользователь меняет событие в Google Calendar.
2. CRM получает изменение при синхронизации Google.
3. CRM обновляет задачу.
4. После сохранения задачи CRM отправляет новое состояние в Яндекс.Календарь.
5. Обратная отправка в Google пропускается, потому что источником изменения был Google.

В обратную сторону схема такая же:

1. Пользователь меняет событие в Яндекс.Календаре.
2. CRM получает изменение при синхронизации Яндекса.
3. CRM обновляет задачу.
4. CRM отправляет новое состояние в Google Calendar.
5. Обратная отправка в Яндекс пропускается, потому что источником изменения был Яндекс.

Это защищает синхронизацию от бесконечного круга обновлений между календарями.

## Правила конфликтов

В настройках подключения можно выбрать правило конфликтов:

- "Последнее изменение главное" - применяется более свежая версия между CRM и календарем;
- "CRM главная" - спорные изменения из календаря не перезаписывают данные CRM;
- "Яндекс.Календарь главный" - спорные изменения из Яндекса могут обновлять задачу CRM.

Для Google Calendar используется аналогичное правило "Google главный".

## Где смотреть ошибки

Первые ошибки подключения видны в блоке "Яндекс.Календарь" в профиле пользователя.

Подробности сохраняются в журнале синхронизации Яндекс.Календаря. Там фиксируются успешные операции, ошибки OAuth, ошибки CalDAV, результаты ручного и фонового обмена, удаление событий и удаление календарей при удалении пользователя.
