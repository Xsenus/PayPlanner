# Чеклист ручной приемки юридического CRM-модуля

Дата подготовки: 21.05.2026.

Цель: пройти с заказчиком ключевые сценарии пилотного юридического контура на копии живой базы и зафиксировать, какие блоки готовы к эксплуатации, какие требуют доработки, а какие остаются выключенными feature flags.

## Условия приемки

- Frontend: `http://localhost:5173` или боевой домен заказчика.
- API: `http://localhost:5080/api` или боевой API-домен заказчика.
- Проверка проводится на копии живой базы либо на согласованном тестовом стенде.
- Внешние юридические интеграции, судебные источники, Google/Яндекс календарь и внешние каналы уведомлений остаются выключенными, если нет отдельного решения.
- Пароли, токены и иные секреты не фиксируются в этом документе.

## Маршруты для проверки

| Раздел | URL/переход | Что проверить |
| --- | --- | --- |
| Авторизация | `/login` или стартовая страница приложения | Вход под ролями заказчика, выход, отказ при неверных данных. |
| Реестр дел | `/cases` | Список дел, поиск, фильтры, сортировки, колонки, CSV/печать при наличии права. |
| Карточка дела | `/cases/{caseId}` | Summary, вкладки, история, участники, задачи, документы, финансы, суд, заказ-наряд. |
| Журнал задач | раздел задач/журнал задач | Задачи, внутренние задачи, фильтры, календарь, timeline, согласование. |
| Уведомления | центр уведомлений в шапке | Непрочитанные, архив, переход к объекту, фильтры. |
| Отчеты | раздел отчетов | Юридическая сводка, сроки, финансы, CSV, переходы в дела. |
| Роли | раздел ролей/настроек доступа | Матрица прав, broad scopes только у `admin`, CSV-аудит ролей. |
| Feature flags | настройки feature flags | Юридические внешние flags выключены, внутренние flags соответствуют плану пилота. |
| Настройки шаблонов | настройки -> шаблоны документов дела | Библиотека шаблонов, токены, preview, активность шаблона. |

## Сценарии приемки

### 1. Авторизация и базовая навигация

- [ ] Войти под администратором.
- [ ] Войти под юристом/исполнителем.
- [ ] Войти под руководителем, если роль есть в базе заказчика.
- [ ] Проверить, что пользователь видит только доступные ему разделы.
- [ ] Проверить, что после обновления страницы маршрут не ломается.

### 2. Реестр дел

- [ ] Открыть `/cases`.
- [ ] Проверить поиск по названию, клиенту, номеру дела, суду.
- [ ] Проверить фильтры по статусу, типу, ответственному, активности.
- [ ] Открыть карточку дела из реестра.
- [ ] Проверить массовые действия с audit reason.
- [ ] Проверить CSV/печать только для ролей с правом экспорта.

### 3. Карточка дела

- [ ] Открыть `/cases/{caseId}` на реальном деле.
- [ ] Проверить верхнюю summary-панель: срок, заседание, финансы, активность.
- [ ] Изменить допустимые поля дела и проверить запись в истории.
- [ ] Проверить скрытие дела от исполнителя и запрос доступа.
- [ ] Проверить вкладки: история, переписка, задачи, участники, документы, финансы, суд, заказ-наряд.

### 4. Задачи и согласования

- [ ] Создать задачу по делу.
- [ ] Создать внутреннюю задачу без контрагента.
- [ ] Назначить исполнителя, наблюдателя и согласующих.
- [ ] Отправить задачу на согласование.
- [ ] Согласовать задачу по очереди.
- [ ] Вернуть задачу на доработку с комментарием.
- [ ] Проверить аудит решений согласующих.
- [ ] Проверить календарный вид и timeline.

### 5. Участники и архив участников

- [ ] Добавить физическое лицо или организацию как участника дела.
- [ ] Проверить роль участника, комментарий и связь с делом.
- [ ] Архивировать участника с причиной.
- [ ] Включить показ архивных участников.
- [ ] Восстановить архивную связь.
- [ ] Проверить аудит архивации и восстановления.

### 6. Заказ-наряд и финансы

- [ ] Создать заказ-наряд по делу.
- [ ] Добавить услуги, исполнителей, сроки, количество и стоимость.
- [ ] Проверить итоговую сумму.
- [ ] Отправить заказ-наряд на согласование.
- [ ] Утвердить заказ-наряд.
- [ ] Вернуть заказ-наряд на доработку.
- [ ] Проверить блокировку редактирования в защищенных статусах.
- [ ] Создать счет из утвержденного заказ-наряда.
- [ ] Проверить, что счет связан с делом и отражается в финансовой сводке.
- [ ] Открыть печатную форму заказ-наряда.

### 7. Документы и шаблоны

- [ ] Загрузить документ в карточку дела.
- [ ] Загрузить новую версию документа.
- [ ] Изменить статус/тип документа.
- [ ] Открыть/скачать документ.
- [ ] Создать шаблон в библиотеке шаблонов.
- [ ] Привязать шаблон к типу дела.
- [ ] Проверить токены шаблона и preview.
- [ ] Сгенерировать документ из карточки дела.
- [ ] Проверить аудит: загрузка, генерация, новая версия, изменение, удаление.

### 8. Процессуальные сроки и календарь

- [ ] Заполнить в деле судебные даты и процессуальные сроки.
- [ ] Открыть календарь задач.
- [ ] Проверить блок `Сроки и суд`.
- [ ] Проверить фильтр по исполнителю.
- [ ] Проверить счетчики событий, сроков, судебных событий, близких и просроченных дат.
- [ ] Перейти из календарного события к делу, если сценарий доступен в UI.

### 9. Судебный блок первой очереди

- [ ] Заполнить суд, номер дела в суде, ближайшее заседание.
- [ ] Проверить судебную вкладку карточки дела.
- [ ] Проверить хронологию: иск, заседание, решение, процессуальные сроки.
- [ ] Убедиться, что внешняя синхронизация выключена.
- [ ] Зафиксировать, какие судебные события заказчику нужны в ручном контуре до внешних интеграций.

### 10. Уведомления

- [ ] Создать задачу и проверить уведомление исполнителю.
- [ ] Изменить статус задачи и проверить уведомления.
- [ ] Отправить на согласование и проверить уведомления согласующим.
- [ ] Проверить уведомление по запросу доступа к делу.
- [ ] Отметить уведомление прочитанным.
- [ ] Архивировать уведомление.
- [ ] Перейти из уведомления к объекту.

### 11. Отчеты и выгрузки

- [ ] Открыть юридические отчеты.
- [ ] Проверить фильтры по периоду, юристу, статусу и типу дела.
- [ ] Проверить отчет по текущим делам.
- [ ] Проверить отчет по срокам и просрочкам.
- [ ] Проверить финансовые показатели дел.
- [ ] Скачать CSV.
- [ ] Проверить, что пользователь без права экспорта не видит/не получает выгрузку.

### 12. Роли, аудит и feature flags

- [ ] Проверить матрицу ролей заказчика.
- [ ] Убедиться, что broad scopes есть только у `admin`.
- [ ] Проверить object-level видимость: дела, задачи, участники, документы, заказ-наряды, отчеты.
- [ ] Скачать CSV-аудит ролей.
- [ ] Проверить `/api/features`.
- [ ] Убедиться, что внешние юридические feature flags выключены.

### 13. Старые данные после миграций

- [ ] Открыть старого клиента.
- [ ] Открыть старый счет.
- [ ] Открыть старый платеж.
- [ ] Открыть старую задачу.
- [ ] Проверить, что старые данные не потеряли связи и корректно отображаются после миграций.
- [ ] Проверить несколько дел/клиентов из копии живой базы с разными ответственными.

## Итог приемки

- [ ] Критичных блокеров нет.
- [ ] Замечания заказчика записаны отдельным списком.
- [ ] Решено, какие внешние feature flags остаются выключенными.
- [ ] Решено, нужен ли полный `test:legal-release-gate`; для него требуется свежий токен или учетные данные.
- [ ] После зеленых проверок подготовлены логичные русские коммиты без `backend/appsettings.Development.json`.
