# Claude: подробные задания по макетам PAY-19–29 и PAY-32

[Общий индекс](claude-yougile-development-handoff-2026-10-10.md) связывает все 37 карточек. Оригинальные ссылки на изображения и уточнения заказчика сохранены в [папке исходной переписки](yougile-sources/2026-10-10/cards). Перед изменением конкретного экрана открыть его **последний макет в исходном размере**. В этой сверке прочитаны тексты и ссылки; точная визуальная геометрия и полнота изображений не объявлены проверенными. Не придумывать расположение невидимых элементов по заголовку карточки.

## Общие обязательные требования

Заказчик просит следовать присланному лаконичному дизайну, **левое меню на макетах не переносить**. Функции старого экрана сохраняются. Если прежний элемент не помещается в макет, сначала составить конкретное предложение его расположения; спорный вариант согласовать, не удалять возможность. Рабочие экраны компактны: обычный padding `p-3 lg:p-4`, gap/space-y около 3, карточки `p-3`, без декоративного свободного пространства.

Перед разработкой каждого экрана сохранить карту:

| Существующее действие | Роль/состояние доступности | Новый элемент/место | Handler/API | Сценарий проверки |
| --- | --- | --- | --- | --- |
| Заполняется по фактическому старому экрану | Просмотр/создание/изменение/специальное разрешение | Кнопка, меню или вкладка без потери возможности | Существующий путь, либо обоснованное изменение | Положительный и запрещённый сценарии |

Не считать карту полной по одному admin-screen. Проверить скрытые кнопки других ролей и разные состояния объекта. Общие компоненты select/modal/notifications/files/permissions/API использовать повторно. Не добавлять новый global store или polling из-за перестановки блока. Визуальный PR отдельно от изменения правил, если их можно разделить.

Общие состояния: loading, пустой результат, ошибка с повтором, запрещено, несохранённый ввод, публикация файла, частичный отказ. Старые данные и длинные значения не обрезают функциональные кнопки; фокус/Enter/Escape/клавиатурное меню работают. Узкий экран не теряет действия: horizontal scroll только там, где нужен таблице, ключевые controls остаются доступны. Проверить как минимум 390, 1024, 1440 px и фактический рабочий монитор заказчика; сравнивать с оригиналом, не с уменьшенной preview-ссылкой.

Для каждого видимого изменения подготовить пользовательскую запись «Что нового». Если задача включает несколько изменений, формат объединённой/раздельных записей согласовать по AGENTS, не переиспользовать опубликованную версию 1.14.58. Новые YouGile-ответы только отдельными одобренными черновиками.

## PAY-19

**Журнал задач.** [Источник и все макеты](yougile-sources/2026-10-10/cards/PAY-19.md). Заказчик считает текущую главную страницу перегруженной; нужен удобный рабочий журнал без потери возможностей. Исходная область — `src/components/Tasks/TaskJournal.tsx`, его тесты и нынешние дочерние компоненты. Перед выделением нового компонента проверить существующие, не переписывать монолит автоматически.

- Сопоставить заголовок, режимы таблица/доска/календарь/расписание, основные фильтры, поиск, кнопки создания и дополнительные действия с макетом. Второстепенные инструменты компактно сгруппировать, сохранив доступ и текущие права.
- Сохранить колонки/порядок/ширину PAY-6, сортировку срока, фильтры PAY-15, связанные клиент/дело/исполнитель и чтение статуса. Итоги/счётчики сверяются с серверным фильтром, а не с первой страницей.
- Календарь использует существующую настройку готовых задач PAY-37, расписание — занятость выбранного исполнителя PAY-4. Нельзя замаскировать ошибку загрузки пустым «свободно».
- Переход в карточку сохраняет контекст списка/фильтра/прокрутки. Быстрая задача PAY-10 и массовые операции не исчезают из redesign. Запоздалый response не перезаписывает новый поиск; debounce и отмена запросов остаются.

**Приёмка:** каждый прежний режим/действие есть в карте; 1 и много страниц; длинная строка; сохранённые колонки; пусто/ошибка; ограниченный исполнитель; возвращение из карточки; параметры после reload; клавиатура/мобильная ширина. Layout-only этап не запускает backend suite; изменение фильтра/контракта квалифицируется обеими сторонами.

## PAY-20

**Карточка задачи.** [Макет и последние вопросы](yougile-sources/2026-10-10/cards/PAY-20.md). Последний запрос: сообщить, когда дизайн готов **и подключён**. Уже существующее новое окно не считается принятым совпадением с макетом. Нужно доказать сохранение прежнего функционала по кнопкам.

Карта действий минимум охватывает фактически имеющиеся создание/сохранение/отмену, исполнителей/участников, клиента/дело, статус, приоритет/метки, срок/длительность/напоминание, запрос переноса/решение, результат/согласование, файлы/комментарии/подзадачи, шаблон/повтор, привязанный счёт/оплату, специальные контекстные меню. Это перечень для инвентаризации, а не заявление, что каждая кнопка всегда должна быть показана каждой роли.

Старая и новая формы сохраняют одинаковые правила и разрешения. Administrative setting выбирает форму для всех пользователей; проверить оба значения и новую сессию ограниченного сотрудника. Перенос кнопки в меню не меняет handler, состояние saving или право действия. Read-only view по-прежнему допускает специально разрешённый запрос переноса PAY-11, но не обычное редактирование.

Сложный текст/вложения не теряются на переключении раздела, realtime и обновлении авторизации. Ошибка сохранения оставляет введённое; повтор не создаёт вторую задачу/оплату. Файловая публикация показывает настоящий status и сохраняет отмену. Для PAY-16 сумма и счёт не меняются побочно от открытия или новой компоновки.

**Проверки:** обе формы × create/edit/view × admin/исполнитель/согласующий/участник/ограниченная роль, с фактически разрешёнными действиями; result approve/reject, request deadline, payment permissions, files pending/error, template/recurrence, unsaved close. Подключение для всех фиксируется отдельно после проверок, не включать новое окно глобально ради screenshot. Сообщение о готовности дизайна — только после фактического совпадения, включения и отдельно одобренной публикации.

## PAY-21

**Общий каркас карточки дела.** [Источник](yougile-sources/2026-10-10/cards/PAY-21.md). Следовать компактному макету; в **правом меню добавить/сохранить ЕФРСБ, Почта РФ, Финансы**. Левую навигацию макета не менять. Найти действующие case-detail компоненты и маршруты через `rg --files src/components/Cases`; не создавать вторую сущность дела ради оболочки.

Сопоставить название/номер/статус/ответственных, основные действия, сводку и right tabs. Из каждой вкладки есть прежние действия и deep link; смена вкладки не повторяет полный набор запросов без причины. Активная вкладка сохраняется допустимым существующим способом. Не загружать все документы/финансы при открытии основной вкладки; данные узких вкладок запрашивать по потребности с нынешним cache/invalidation.

**Приёмка:** все старые разделы и кнопки доступны соответствующим ролям; новое правое меню; длинное название/номер; скрытый финансовый раздел; переход по прямой ссылке; loading/error; несохранённый ввод; общая оболочка не ломает PAY-22–28. Недостающую в макете прежнюю функцию перенести в согласованное место.

## PAY-22

**Суд внутри дела.** [Источник с двумя редакциями макета](yougile-sources/2026-10-10/cards/PAY-22.md). Первый макет неполный: заказчик отдельно добавил **обжалование, апелляцию, кассацию, ВС РФ**, затем прислал обновлённый. Использовать последнюю редакцию, а не ранний рисунок. Связать с новой просьбой PAY-3 о параллельном дизайне.

Разделить инстанции/дела, движения/заседания, документы, результаты/обжалование и задачи так, как задаёт макет, сохранив прежние действия синхронизации и ручного ввода. Источники/дата обновления и частичная ошибка понятны. Неподтверждённая связь не показывается как достоверная. При подключении второй инстанции первая не пропадает; три суда на одно время не сливаются.

Проверить API-contract и правила [судебной спецификации](claude-yougile-operations-development-spec-2026-10-10.md#pay-3). Верстка не создаёт новый расчёт процессуального срока. Приёмка: первая/апелляция/кассация/ВС, отсутствующая нижняя инстанция, несколько заседаний, ручная дата, неполная синхронизация, ограниченный сотрудник, документ/задача по ссылке.

## PAY-23

**Документы дела.** [Источник](yougile-sources/2026-10-10/cards/PAY-23.md). Сверить последний макет со всеми старыми действиями: загрузка, создание из шаблона/доступного генератора, просмотр, скачать, версия, удалить/архивировать по нынешним правилам, публикация/отмена/повтор, подпись при поддержанном механизме. Отсутствующую функцию не удалять молча.

Использовать действующее managed storage, состояния публикации и права файлов. Pending upload не выглядит готовым документом. Не терять связанный файл/версию при перерисовке списка; повтор после ошибки не создаёт дубль. Preview/download не дают доступ чужой роли, public link не появляется автоматически. Списки постраничные, бинарные данные не включать в общий case-response.

**Приёмка:** новый/старый файл, preview unavailable, pending/success/fail/cancel/retry, версия, длинное название, role denial и прямое скачивание, переход обратно. Чисто визуальная работа не закрывает незавершённые отдельные планы управляемых документов.

## PAY-24

**Задачи дела.** [Источник](yougile-sources/2026-10-10/cards/PAY-24.md). Список/группы/фильтры по макету поверх того же TaskJournalItem и действующих ссылок. Сохранить создать/открыть/назначить/срок/статус/результат/согласование/счёт и фактические прежние context actions. Из дела открывается выбранная старая или новая форма по административному setting PAY-20.

Нельзя создавать задачу в чужом деле, скрывать согласование результатом простого drag/drop или терять связь при открытии журнала. Одно изменение обновляет список и счётчики без перечитывания всей CRM. Приёмка: пустой список, несколько страниц, связанная задача, ограниченный исполнитель, done/return, платная задача, обе формы, возвращение в ту же вкладку.

## PAY-25

**События дела.** [Источник](yougile-sources/2026-10-10/cards/PAY-25.md). По макету оформить действующий список/шкалу дат и actions; из одного изображения не выводить новое юридическое правило. Сохранить тип, дату/время, ответственного, связанное заседание/задачу/документ, прежние create/edit/delete-права и напоминания.

Дата без времени не превращается в произвольное UTC-заседание; проверить текущую модель all-day, часовой пояс, одинаковую минуту разных событий. Ошибка источника видна, ручное изменение не затирается. Приёмка: разные типы, прошлое/будущее, all-day/время, несколько событий одновременно, пустая/длинная история, ссылка на объект и запрещённое изменение.

## PAY-26

**ФССП.** [Источник](yougile-sources/2026-10-10/cards/PAY-26.md). Перенести существующие поиск/привязку/обновление, исполнительные производства, суммы/статусы/основания и историю в новый макет после фактической инвентаризации. Источник и дата актуальности остаются видны; ошибка/неподдержанный провайдер не выглядит как «долга нет».

Наличие ФССП-вкладки не доказывает действующий внешний API. Новый провайдер проходит отдельную квалификацию PAY-3. Не создавать денежное взыскание/платёж как часть редизайна. Приёмка: несколько производств, одинаковый должник, partial error, stale data, переход к делу/источнику, права и длинные суммы/номера.

## PAY-27

**Почта РФ.** [Источник](yougile-sources/2026-10-10/cards/PAY-27.md). По макету сохранить разрешённые отправления, трек-номер, статус и дату, отправителя/получателя, связь с документом/делом, историю, ручные действия и обновление. Адресные данные доступны только нужной роли; наружу не выводить персональный адрес через постоянную открытую ссылку.

Ручная регистрация не является подтверждённой отправкой через API. Ошибка трекинга не подменяется вручением; повтор обновления не дублирует историю. Приёмка: пустой/неизвестный трек, несколько отправлений, смена статуса, ошибка/повтор, длинный адрес, запрещённое дело, ссылка на документ.

## PAY-28

**Финансы дела.** [Источник](yougile-sources/2026-10-10/cards/PAY-28.md). Макет оборачивает существующие счёт/акт/оплату/долг/расходы/начисления; точный состав переносимых возможностей получить из карты старого экрана. Расчёты и серверные правила не переписывать для вида.

Просмотр, preview, экспорт, платёж, отмена и редактирование различаются. Сотрудник без финансовых прав не отправляет запрещённые запросы при открытии другой вкладки. Секретарь с правом счета может видеть список/preview разрешённых счетов, без автоматического grants к выгрузке/платежам; сохранить исправление Анны из main. Сводки используют тот же разрешённый scope и фильтр, суммы точны, валюта явна. Оплачено не выводится из цветовой метки или local state.

**Приёмка:** две компании/два дела, частичная оплата/возврат, долг, разные роли, запрет прямого endpoint, preview/export split, много страниц, stale response после смены дела. Изменение финансового handler/контракта — высокий риск с expanded и полными применимыми проверками, даже если началось с макета.

## PAY-29

**Редизайн внутреннего мессенджера.** [Источник, макет и полный список функций](yougile-sources/2026-10-10/cards/PAY-29.md). Использовать действующий PAY-1 и существующие chat-компоненты. В исходнике **аудио/видеозвонок опционален**, не объявлять обязательным нововведением или готовой возможностью.

Карта интерфейса: написать/создать диалог и группу, непрочитанное и напоминание, поиск по тексту/сотруднику/чату/дате, файл/preview/download, @, chat settings, online/typing, reply/edit/reactions, связанный CRM-объект, задача из сообщения/ответственный, pinned/archive/folders/sort, mute/quiet/snooze, шаблоны/быстрый ответ и экспорт при текущих правах.

Каждой функции дать статус «уже есть / частично / нет / опционально / decision», не рисовать активную пустую кнопку. Не удалять историю ради дизайна: исходник требует сохранения администратором и ограничения удаления по роли/времени. Любое новое действие очистки/выхода должно уважать действующий аудит и доступ к объекту.

Макет должен сохранять читаемый контекст адресата/участников, поиск/старую историю и неизменный редактор. Виртуализировать или использовать существующую пагинацию длинного списка; не загружать весь архив на каждый приход сообщения. Связанные объекты и файлы не раскрываются сотруднику, потерявшему право.

**Приёмка:** личный/группа/задача, новый/старый чат, >1 страницы, выбранное сообщение, muted/archived/pinned/folder, snooze, два пользователя/вкладки, offline/reconnect, unread, большой файл, отозванный участник, клавиатура и 390 px. Конкретные пробелы расширяют текущий план PAY-1, визуальная приёмка идёт отдельно от доставки email/MAX.

## PAY-32

**Карточка клиента — физлицо.** [Источник](yougile-sources/2026-10-10/cards/PAY-32.md). Правило заказчика: придерживаться основной карточки макета; **поля старой «Личной информации», которые не поместились, перенести в свёрнутый раздел «Дополнительная информация»**. Новые разделы будут присланы позже — не выдумывать их дизайн.

Исходная точка — существующая `src/components/Clients/ClientModal.tsx` и её текущие supporting-компоненты/схема. Инвентаризировать каждый старый персональный field и действие, validation, server property и доступ. Контакты/телефоны/email, документы, даты, ответственный и связанные объекты не теряют значения при новом расположении. Сворачивание блока не очищает поля и не снимает validation. Создание/редактирование/readonly/быстрый клиент сохраняют совместимые payload.

Основная карточка компактна; расширенные сведения раскрываются по запросу. Длинное ФИО/адрес, несколько контактов, пустое необязательное значение и masked protected fields не ломают верстку. Смена клиента/вкладки не переносит черновик другому человеку. Не загружать все документы/дела/историю в основное окно без потребности.

**Приёмка:** полный старый клиент без потери каждого значения, новый клиент, collapse/expand и сохранение, запрещённое поле, validation внутри закрытого блока, конфликт/ошибка сохранения, несколько телефонов, связанные дела, дубль и read-only. Проверить прямой серверный доступ к защищённым полям; перенос в «Дополнительную информацию» не делает их общедоступными.

## Результат каждого дизайнерского блока

Сохранить заполненную карту всех прежних действий, ссылку на выбранную редакцию макета, сравнительные screenshots по согласованным разрешениям, проверенные роли и поведение, актуальный статус глобального переключателя при его наличии. Указать недостающие функции и согласованные места явно. Адресные component tests во время разработки; перед frontend push — полный unit, lint, types, encoding, production build. Backend добавляется при изменении взаимодействия/контракта/прав или другой затронутой логики, а не по привычке после чистого CSS.

Не публиковать сообщения «дизайн готов» по наличию локальной формы. Результат должен соответствовать макету, сохранять функции, пройти проверки, быть установленным и включённым в нужном режиме; затем отдельное разрешение на текст YouGile.
