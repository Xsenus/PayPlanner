## Состав сообщения

1. Тип события в квадратных скобках, короткий заголовок и обозначение высокого или срочного приоритета события.
2. Номер задачи перед актуальным названием.
3. Суть события либо допустимые сохранённые метки изменений этой задачи.
4. Актуальный срок в часовом поясе получателя, статус, приоритет задачи и исполнитель.
5. Действие по типу события, включая явное «не требуется» для согласованной или отменённой задачи.
6. Доверенная каноническая ссылка на карточку задачи.
7. Строка кнопки «Открыть задачу» с действующей ссылочной кнопкой MAX.

Приоритет события берётся из каталога уведомлений. Приоритет задачи показан в строке данных. Часовые пояса загружаются действующим пакетным помощником для готовой порции задач. Текущая проекция задачи расширена сроком, приоритетом и именем исполнителя.

Из `MetadataJson` исходного уведомления с соответствующим получателем, ключом и ID задачи извлекаются только названия четырёх общих изменённых полей — срок, статус, приоритет и исполнитель. Значения этих полей показаны по актуальной разрешённой проекции задачи. Повреждённые, неподходящие и чрезмерные метаданные приводят к описанию типизированного события. Общие пользовательские шаблоны продолжают обслуживать свои каналы. MAX формирует содержание из проверенных полей задачи.

Каждое динамическое значение нормализуется в одну строку. Ограничение учитывает элементы Unicode и размер строки, сохраняет целые составные emoji и удаляет управляющие направлением письма знаки. Для уверенно распознанных типов задач с непрямой ссылкой на CRM действует нейтральный семистрочный вариант с прежним разрешённым переходом и подписью кнопки. Данные задачи в нём явно отсутствуют. Старые текстовые записи распознаются действующим декодером MAX.
