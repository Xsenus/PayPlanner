## Фактическое начало

После коммита `7da8c503` эффект вкладок задач/документов получает только страницу 1 из 50 задач. `total` отбрасывается, фильтры и счётчики считаются по массиву. Общий прогресс дела уже приходит в `caseItem.taskProgressPercent`, его нельзя подменять прогрессом страницы. Массив задач также используется для выбора источника документа: переход страницы таблицы не должен менять выбранную связь документа.

Существующие `/tasks` и `/tasks/summary` уже ограничивают данные правами и считают агрегаты в БД. Фильтры `active` и `overdue` поддерживаются до пагинации. Группа `done + cancelled`, используемая вкладкой дела, пока не имеет единого серверного фильтра. Summary не возвращает общий и завершённый счётчики. Нельзя заменять группу одним `done`, склеивать две независимо ограниченные страницы или загружать все задачи ради счётчиков.

Ответ пользователя на вопрос о флажках PAY-24: «делай сразу несколько вариантов». Реализованы три варианта: **CSV выбранных строк**, **смена исполнителя**, **смена статуса**. Это часть этапа 4, без закрытия всей карточки.

- **Охват.** Флажок заголовка выбирает только текущую видимую страницу, максимум 100 строк. Нет скрытого выбора всего дела/фильтра. Переход дела, фильтра, страницы, размера, новая загрузка/ответ или изменение прав сбрасывают выбор. Отмена подтверждения сохраняет выбор; ошибка записи позволяет повторить. Устаревший выбор во время подтверждения не отправляется.
- **Права.** App передаёт отдельные `tasks.canEdit/canExport`, по умолчанию новые права выключены. Экспорт не выводится без права экспорта задач. Разрешённый сервером просмотр дела не превращается в право изменять чужие задачи. Роль с правом создания задачи сохраняет прежнюю кнопку создания: право редактирования самого дела — отдельное правило.
- **Изменения.** Используется прежний POST `/tasks/bulk`, отдельно одно поле на операцию; не копировать правила карточек в таблицу. Перед отправкой показываются действие, новое значение и число задач. Исполнители загружаются один раз по требованию выбора соответствующего действия, не для каждой строки; ошибка справочника имеет повтор. Массового удаления нет.
- **Статусы.** Новая/в работе/ожидание/на согласовании/выполнена/отменена. Массовое решение согласующего недоступно. Результат, очередь согласования и ограничения сотрудника проверяет прежний backend; запрещённые и совпадающие изменения пропускаются. Для нового результата/рецензии/доработки открывать общую карточку.
- **Частичный результат.** Ответ API возвращает числа, а не IDs пропусков. Экран честно показывает «Изменено / Пропущено», сбрасывает весь выбор и перечитывает список, счётчики и прогресс дела. Не утверждать, что все строки изменились, и не притворяться, что известны точные пропущенные IDs. Сообщение сохраняется после перезагрузки карточки дела.
- **CSV.** Только уже выбранные видимые строки: ID, название, исполнитель, срок с явной пометкой UTC, читаемый статус, результат. UTF-8 BOM, `;`, кавычки/переводы строк; формульные пользовательские значения нейтрализованы. Объектный URL освобождается после передачи браузеру, временная ссылка удаляется. Нового запроса полного списка нет.
- **DoD этого объёма.** Роли чтения/экспорта/редактирования, частичный/нулевой ответ, ошибка/повтор, отмена/дубль, смена контекста и устаревшее подтверждение, справочник исполнителей, CSV-инъекции и настоящее скачивание, две темы и 390/1024/1440; затем полный frontend gate на окончательных хешах. API-контракт/схема не менялись; пять прежних адресных backend-сценариев массового изменения прошли на текущей API DLL. Это не нормальная полная backend-сборка.
