## Фактическое начало

После коммита `7da8c503` эффект вкладок задач/документов получает только страницу 1 из 50 задач. `total` отбрасывается, фильтры и счётчики считаются по массиву. Общий прогресс дела уже приходит в `caseItem.taskProgressPercent`, его нельзя подменять прогрессом страницы. Массив задач также используется для выбора источника документа: переход страницы таблицы не должен менять выбранную связь документа.

Существующие `/tasks` и `/tasks/summary` уже ограничивают данные правами и считают агрегаты в БД. Фильтры `active` и `overdue` поддерживаются до пагинации. Группа `done + cancelled`, используемая вкладкой дела, пока не имеет единого серверного фильтра. Summary не возвращает общий и завершённый счётчики. Нельзя заменять группу одним `done`, склеивать две независимо ограниченные страницы или загружать все задачи ради счётчиков.

### Найденная сквозная ошибка решения из отдельной карточки

Реальный ограниченный исполнитель создал запрос переноса по задаче 13; исходный срок остался прежним. Это ошибка общего входа, которую изолированные сценарии журнала не обнаружили.

Исправление должно применяться к **обеим формам**: отдельная карточка остаётся смонтированной при открытии решения по сроку/согласованию; один общий набор окон решений отображается в route-ветке и журнале. Отмена/отложить/ошибка сохраняют карточку; успешное решение возвращает в вызывающий раздел и перечитывает дело. Права/переходы/результат/причины решения проверяются существующим API. Нужны регрессии обоих видов, успех/ошибка/отложить и защита позднего ответа от закрытия другой карточки; повторить реальные old/new циклы. Этап 3 не закрывать до этого.
