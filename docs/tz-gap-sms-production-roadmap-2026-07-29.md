# Roadmap. Реальная отправка SMS

Дата создания: 29 июля 2026.
Статус: активный roadmap, детализация канала SMS.

## Цель

Заменить текущий `Skipped`-адаптер реальной, управляемой и контролируемой SMS-доставкой, не влияющей на email, Telegram, Web Push и внутренние уведомления.

## Текущее состояние

- `[x]` Канал SMS зарегистрирован в общем каталоге уведомлений.
- `[x]` Есть административные настройки провайдера, отправителя, токена и лимитов.
- `[x]` Есть шаблоны для срочных событий.
- `[x]` Есть личные и ролевые предпочтения.
- `[x]` Есть журнал доставок и общий retry-контур.
- `[x]` Без реального адаптера отправка безопасно фиксируется как `Skipped`.

## Решения заказчика

- `[x]` SMS утверждён как дополнительный production-канал: его отключение или сбой не влияет на email, Telegram, Web Push и внутренние уведомления.
- `[x]` Поддержать три популярных российских шлюза: SMS.RU, SMSC.RU и SMS Aero; активный договор и тариф выбирает администратор организации.
- `[!]` Передать sandbox/production credentials и зарегистрированное имя отправителя — внешние доступы пока не предоставлены, поэтому канал по умолчанию выключен.
- `[x]` Первый rollout ограничить allowlist сотрудников и одним утверждённым критическим событием; тихие часы по умолчанию 20:00–09:00 без автоматических исключений.

## Этап 1. Контракт провайдера

- `[x]` Определить интерфейс отправки, проверки статуса, баланса и health-check.
- `[x]` Нормализовать provider message id, accepted/delivered/failed/expired/rejected.
- `[x]` Реализовать idempotency key, чтобы retry не создавал повторное SMS.
- `[x]` Реализовать timeout, retry только для временных ошибок и circuit breaker.
- `[x]` Обработать HTTP, бизнес-коды, недостаток баланса, запрещенного отправителя и неверный номер.

## Этап 2. Телефоны и шаблоны

- `[x]` Нормализовать номера в E.164 и валидировать российские и согласованные зарубежные номера.
- `[x]` Определить приоритет рабочего, мобильного и резервного номера клиента/сотрудника.
- `[x]` Исключить отправку на пустые, служебные, неподтвержденные и opt-out номера.
- `[x]` Рассчитывать количество SMS-сегментов с учетом GSM-7/Unicode.
- `[x]` Проверять шаблон и длину до создания доставки.
- `[x]` Исключить паспортные данные, секреты и избыточную информацию о деле из SMS.

## Этап 3. Доставка и статусы

- `[x]` Реализовать production-адаптеры SMS.RU, SMSC.RU и SMS Aero по официальным HTTP API, с единым безопасным контрактом и явным выключенным состоянием без credentials.
- `[!]` Добавить callback/webhook статусов с проверкой подписи и replay-защитой — формат подписи зависит от выбранного провайдера.
- `[!]` Связать callback с `NotificationDelivery` по provider message id — зависит от формата callback и идентификатора выбранного провайдера.
- `[x]` Ограничить дневной бюджет, число сообщений одному получателю и burst rate.
- `[x]` Добавить quiet hours и исключение только для утвержденных критических событий.
- `[x]` Добавить ежедневное предупреждение о низком балансе или деградации канала.

## Этап 4. Администрирование

- `[x]` Добавить тестовую отправку из админки без раскрытия API-токена.
- `[x]` Показывать готовность, баланс, последние ошибки, delivered rate и очередь.
- `[x]` Добавить выключатель аварийной остановки и per-event выключатели.
- `[x]` Добавить аудит изменения провайдера, шаблонов, лимитов и отправителя.

## Безопасность и производительность

- Credentials хранить только защищенно, не возвращать в API и не писать в лог.
- Webhook ограничить подписью, timestamp, IP allowlist при поддержке провайдера.
- Отправлять через outbox/фоновые задания, не задерживать пользовательский запрос.
- Загружать получателей и предпочтения пачкой, исключить N+1.

## Проверки

- `[x]` Unit-тесты нормализации, сегментов, quiet hours, opt-out и idempotency.
- `[!]` Интеграционные тесты success/429/5xx/timeout/rejected/callback/retry — provider-независимые сценарии success, 429, 5xx, timeout, rejected и retry проходят; callback заблокирован до выбора провайдера и утверждения его формата и подписи.
- `[x]` Тест миграций и совместимости существующих доставок.
- `[x]` Проверка журналов на отсутствие токена и текста с чувствительными данными.
- `[acceptance]` Отправить тестовые SMS на согласованные номера разных операторов.
- `[acceptance]` Подтвердить delivered/failed статусы и отсутствие дублей после retry.

## Rollout

- Сначала sandbox провайдера, затем allowlist номеров команды.
- Далее только одно событие с малым дневным лимитом.
- После недели наблюдения расширить события и получателей.
- Аварийный откат возвращает канал в `Skipped`, не затрагивая другие уведомления.

## Definition of Done

- SMS реально доставляется, имеет конечный статус и не дублируется.
- Лимиты, quiet hours, предпочтения и права соблюдаются.
- Секреты защищены, ошибки видны администратору.
- Есть тесты, release note, успешный deploy и production smoke.

## История

- 2026-07-31: добавлены production-адаптеры SMS.RU, SMSC.RU и SMS Aero. Администратор выбирает шлюз, для SMS Aero указывает логин, а API-токен хранится в защищённом виде и никогда не возвращается в интерфейс. Запросы проходят через общий timeout/retry/circuit-breaker, credentials не попадают в URL, а неизвестные ответы провайдера заменяются безопасной причиной. Канал остаётся выключенным без явного включения и credentials; тихие часы по умолчанию изменены на согласованные 20:00–09:00. Контрактные тесты проверяют формат запросов, успешные ответы трёх провайдеров и отказ до сети для неверного российского номера. Закрыт 31 из 37 пунктов, прогресс 84%.
- 2026-07-30: завершён аудит безопасности SMS-журналов. Внешний текст ошибки провайдера теперь считается недоверенным по умолчанию и заменяется безопасной причиной до записи доставки; подробный текст разрешён только при явной отметке адаптера. Исключение SMS-провайдера больше не передаётся системному логгеру целиком: журнал получает только идентификатор доставки и тип исключения. Ключи событий в SMS-диагностике заменены стабильным коротким хэшем. Автотесты подтверждают отсутствие API-токена, номера телефона, чувствительного текста и внешнего исключения одновременно в системном журнале, ошибке доставки и превью сообщения. Закрыто 27 из 37 пунктов, прогресс 73%.
- 2026-07-30: добавлена проверка обновления локальной БД с уже существующим журналом доставок. Тест поднимает SQLite-схему до версии перед индексом SMS-лимитов, сохраняет старые email, Web Push и SMS-доставки с разными статусами, применяет оставшиеся миграции и подтверждает сохранность адресов, статусов, ошибок и содержимого. Обнаруженный разрыв между СУБД устранён отдельной PostgreSQL-миграцией; автоматическая проверка подтверждает одинаковый составной индекс канала и времени для SQLite и PostgreSQL. На локальной копии PostgreSQL миграция применена поверх 2665 существующих доставок без потери записей, а запрос лимитов использует Index Only Scan. Provider-независимые сценарии success, 429, 5xx, timeout, rejected и retry подтверждены существующими тестами; завершение callback-сценария отмечено заблокированным до выбора SMS-провайдера и его контракта подписи. Закрыто 26 из 37 пунктов, прогресс 70%.
- 2026-07-30: подтверждено полное unit-покрытие базовых SMS-правил. Отдельные наборы проверяют E.164-нормализацию российских и явно разрешённых зарубежных номеров, границы GSM-7/Unicode и emoji-сегментов, ночные интервалы и явное критическое исключение, отказ для opt-out до нормализации номера, а также стабильность и конфиденциальность idempotency key. Дополнительно проверены повтор неуспешной доставки с тем же ключом и независимая работа других каналов в тихие часы. Единый контрольный прогон из 78 сценариев прошёл полностью. Закрыто 25 из 37 пунктов, прогресс 68%.
- 2026-07-30: изменения SMS-провайдера, имени отправителя, лимитов, порога баланса, тихих часов, аварийной остановки, разрешённых событий и API-токена фиксируются в общем журнале аудита вместе с пользователем и временем. Изменение и сброс SMS-шаблонов также оставляют отдельную запись. Токен и фактические тексты шаблонов не сохраняются в истории: для них записывается только безопасный факт изменения и длина текста. Повторное сохранение без фактических изменений не создаёт лишнюю запись, а аудит настроек сохраняется одной транзакцией с самими настройками. Закрыто 24 из 37 пунктов, прогресс 65%.
- 2026-07-30: в административных настройках SMS добавлена аварийная остановка всего канала и отдельные выключатели разрешенных SMS-событий. Аварийная остановка блокирует новые рабочие и тестовые SMS до создания доставки и обращения к провайдеру, не затрагивая email, Telegram, Push и внутренние уведомления. Отключенное событие исключает только SMS из набора его каналов; настройки загружаются один раз на область выполнения и сохраняются без сброса при запросах старых клиентов API. Канал SMS подключен к фактическим уведомлениям задач, а неизвестные ключи событий не сохраняются. Закрыто 23 из 37 пунктов, прогресс 62%.
- 2026-07-30: административная карточка SMS дополнена оперативной диагностикой. Последний безопасный снимок ежедневной проверки сохраняет health и баланс без внешнего текста ошибок и секретов; интерфейс показывает время проверки, доступность, баланс, очередь, последнюю успешную доставку и последнюю ошибку. Delivered rate рассчитывается по конечным успешным и неуспешным доставкам за 30 дней вместе с размером выборки. Все показатели журнала получаются одним агрегатным SQL-запросом, снимок провайдера хранится в существующих системных настройках без новой таблицы и миграции. Закрыто 22 из 37 пунктов, прогресс 59%.
- 2026-07-30: в административных настройках SMS добавлена тестовая отправка на вручную указанный мобильный номер. Запрос использует общий серверный контур уведомлений: номер приводится к E.164 до создания доставки, текст проходит защиту и проверку длины, соблюдаются тихие часы и лимиты, результат фиксируется в журнале. API-токен остаётся на сервере и отсутствует в контракте тестового запроса и ответа. Невалидный номер отклоняется до обращения к провайдеру и записи в БД. Закрыт 21 из 37 пунктов, прогресс 57%.
- 2026-07-30: добавлен ежедневный provider-независимый мониторинг включенного SMS-канала. Проверка определяет неполную конфигурацию, отсутствие адаптера, недоступность провайдера, отсутствие данных о балансе и падение ниже настраиваемого порога; обращение к провайдеру ограничено общим timeout 30 секунд. Администраторы получают одно дедуплицированное предупреждение в CRM, toast и Web Push за локальный день без использования проблемного SMS-канала и без внешних текстов ошибок. Отключенный канал не вызывает запросов к провайдеру, а порог 0 отключает только контроль низкого баланса. Состояние запуска записывается в общий журнал фоновых заданий. Закрыто 20 из 37 пунктов, прогресс 54%.
- 2026-07-30: добавлены общие тихие часы SMS с настраиваемыми началом, окончанием и часовым поясом. Проверка выполняется сразу после единственной загрузки SMS-настроек и до защиты текста, выбора отправителя, запросов лимитов, создания доставки и обращения к провайдеру; поэтому ночное SMS не расходует квоту и не создает лишнюю нагрузку, а другие выбранные каналы продолжают работать. Критический обход требует отдельного явного признака утвержденного события; ни одно событие автоматически не получило это право до решения заказчика. Сохранение SMS-настроек оптимизировано до одной пакетной загрузки вместо отдельного запроса на каждое поле. Закрыто 19 из 37 пунктов, прогресс 51%.
- 2026-07-30: SMS защищены тремя настраиваемыми ограничениями до обращения к провайдеру: общий бюджет за скользящие 24 часа, число сообщений одному нормализованному номеру за 24 часа и общий burst-лимит за минуту. Проверка использует один агрегатный запрос по составному индексу `канал + время`; в пределах экземпляра сервиса проверка и создание `pending`-доставки выполняются под единым шлюзом, поэтому параллельные запросы не обходят лимит. `Skipped` не расходует квоту, остальные попытки учитываются для защиты бюджета. Настройки доступны администратору в разделе SMS. Три provider-зависимых пункта помечены заблокированными до выбора SMS-провайдера и его callback-контракта. Закрыто 18 из 37 пунктов, прогресс 49%.
- 2026-07-30: добавлен защитный контур содержимого SMS. Сообщения с признаком конфиденциальности, паспортными реквизитами, паролями, API-токенами и другими секретными маркерами заменяются нейтральным уведомлением без исходных данных. Многострочный текст свыше трех содержательных строк и сообщения длиннее 240 единиц GSM-7/Unicode также заменяются короткой ссылкой на подробности в CRM; безопасный обычный текст уплотняется без изменения смысла. Защита применяется отдельно к SMS, не меняет email и другие каналы, а нейтральная замена укладывается в один Unicode-сегмент. Закрыто 17 из 37 пунктов, прогресс 46%.
- 2026-07-30: SMS теперь проверяется до создания записи доставки: пустой текст, оставшиеся маркеры шаблона и превышение настроенного лимита единиц GSM-7/Unicode не попадают в очередь и не вызывают обращение к провайдеру. Диагностика сохраняет только безопасный код причины и агрегированные размеры без текста и номера; при смешанном наборе каналов отклонение SMS не мешает email и другим уведомлениям. Настройки SMS загружаются один раз на отправку и повторно используются при выборе отправителя. Закрыто 16 из 37 пунктов, прогресс 43%.
- 2026-07-30: добавлен единый расчет SMS-сегментов до обращения к провайдеру. Поддержаны односегментные и составные лимиты GSM-7 и Unicode, расширенные GSM-символы с двойной стоимостью, кириллица и emoji как UTF-16 пары. Расчет выполняется за один проход и возвращает кодировку, число единиц, сегментов и заполнение последнего сегмента для последующей проверки шаблонов и лимитов. Закрыто 15 из 37 пунктов, прогресс 41%.
- 2026-07-30: селектор SMS-номера исключает пустые и невалидные значения, явно служебные контакты, неподтвержденные номера и номера с opt-out до нормализации и обращения к провайдеру. Пользовательский запрет SMS по типу уведомления по-прежнему применяется общим контуром до доставки. Для каждого отклоненного кандидата сохраняется безопасная агрегированная причина без раскрытия самого номера, а выбор автоматически переходит к следующему допустимому контакту. Закрыто 14 из 37 пунктов, прогресс 38%.
- 2026-07-30: определен единый порядок выбора SMS-номера для сотрудников и клиентов: основной мобильный, затем рабочий, резервный и старый номер без указанного типа. Внутри одной категории основной номер имеет приоритет, затем сохраняется исходный порядок контактов. Невалидный или запрещенный по стране кандидат автоматически пропускается, одинаковые номера после E.164-нормализации не увеличивают число доступных вариантов; текущий телефон сотрудника подключен как основной мобильный. Закрыто 13 из 37 пунктов, прогресс 35%.
- 2026-07-30: SMS-контур переведен на строгую нормализацию телефонов в E.164. Российские номера в форматах `8...`, `7...`, десять цифр, `+7...` и `007...` приводятся к единому `+7...`; неверная длина, буквы, неоднозначный международный формат и повторный `+` отклоняются до обращения к провайдеру. По умолчанию разрешено только направление `+7`, а согласованные зарубежные коды подключаются явной политикой allowlist. Закрыто 12 из 37 пунктов, прогресс 32%.
- 2026-07-30: добавлена единая классификация HTTP-ответов и бизнес-кодов SMS-провайдеров. Недостаток баланса, запрещенное имя отправителя, неверный номер и ошибка авторизации получают отдельные постоянные коды без автоматического повтора; ограничения частоты, timeout и недоступность провайдера считаются временными и совместимы с retry-контуром. Неизвестный внешний код и чувствительные детали ответа не попадают в безопасное сообщение журнала, а `Retry-After` учитывается только для временных ошибок. Закрыто 11 из 37 пунктов, прогресс 30%.

Постоянные ошибки получателя не повторяются; HTTP-сбой и timeout возвращают безопасные диагностические коды без текста внешнего исключения.
