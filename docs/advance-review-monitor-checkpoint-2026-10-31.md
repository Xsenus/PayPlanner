## Реализация

Фоновый монитор авансов использует существующую BalanceApplicationLease: отдельный системный вход без вымышленного сотрудника, собственная чистая Serializable-транзакция и те же блокировки платежей, что у ручных действий. Интерактивный вход по-прежнему фиксирует пользователя, роль, права и доступ к компаниям; его проверки не перенесены в системный режим. Чужие открытые транзакции и несохранённые изменения не присваиваются, не сохраняются и не отбрасываются.

Партия ограничена прежней настройкой 1–500, порядок дата/ID сохранён. ID выбираются отдельно, затем PostgreSQL одним параметризованным запросом блокирует только выбранные платежи по ID с NOWAIT. SQLite сохраняет существующую BEGIN IMMEDIATE. Кандидаты перечитываются под блокировкой; их изменение или занятость любой строки прерывают всю партию. Действующие решения Accepted/Ignored/Refunded не перезаписываются. До commit меняются только поля контроля и аудит: суммы, оплаты, связи, баланс и денежные операции не затрагиваются.

Уведомления ответственным и эскалации администраторам запускаются после commit и освобождения транзакции. Ограниченный запрос перечитывает только выбранные платежи, ещё ожидающие решения, с владельцами и делом для прежнего выбора адресатов. Никаких сетевых отправок под блокировками нет. При отсутствии сервиса уведомлений постановка сохраняется без лишней загрузки графа адресатов. Правила адресатов, пользовательские запреты и дедупликация остаются в существующем модуле уведомлений.

При ошибке записи или отмене до сохранения решение и аудит откатываются, отправки не начинаются. Потеря подтверждения уже выполненного commit и ошибка создания уведомления не отменяют сохранённое решение и не превращаются в безопасный повтор записи по догадке. На следующем запуске источник перечитывается; уже установленное состояние не переписывается, недостающее уведомление проверяется отдельно. Повтор доставки уже созданного сообщения по каналам остаётся обязанностью существующей очереди доставки; новый outbox и гарантия exactly-once не добавлены. Сбой фоновой партии остаётся ошибкой задания, а не ложным успешным нулевым результатом.
