# Инструкция по юридическому модулю CRM

Дата актуализации: 19.05.2026

Документ описывает рабочие сценарии для администраторов, руководителей и сотрудников после внедрения блока "Дела + Задачи + Календарь".

## 1. Роли пользователей

### Администратор

- настраивает роли и видимость данных;
- ведет справочники, включая отделы;
- задает настройки журнала задач, уведомлений и автоконтроля дел;
- проверяет диагностику фоновых процессов;
- разбирает спорные права доступа и audit-log.

### Руководитель / старший юрист

- контролирует реестр дел, задачи, согласования и просрочки;
- смотрит отчеты по юридическому блоку;
- принимает решения по запросам доступа к скрытым делам;
- отслеживает неактивные дела и эскалации.

### Юрист / исполнитель

- работает со своими задачами и видимыми делами;
- фиксирует результат работы;
- отправляет задачи на согласование, если это требуется процессом;
- использует календарь и расписание для выбора времени.

### Секретарь / сотрудник поддержки

- создает задачи и документы в рамках доступных прав;
- видит только назначенные или разрешенные объекты по настройкам роли;
- не должен получать полный доступ к клиентам, делам и финансовым документам без явного правила видимости.

## 2. Дела

### Реестр дел

Реестр используется как основной список юридических дел. В нем доступны поиск, фильтры, настройки колонок, сохраненные представления, массовые действия и экспорт.

Ключевые признаки:

- ответственный;
- статус;
- стадия;
- приоритет;
- клиент или юридическое лицо;
- индикатор активности;
- признак скрытого дела;
- включен или выключен автоконтроль.

### Карточка дела

Карточка дела собирает операционную работу по делу:

- основные параметры;
- участники;
- документы и версии;
- задачи;
- финансовый блок;
- платежный календарь;
- судебная хронология;
- история изменений;
- внутренняя переписка.

Если дело скрыто от исполнителя, пользователь без доступа увидит экран запроса доступа. Решение руководителя фиксируется уведомлением и audit-log.

## 3. Задачи

### Создание задачи

Задача может быть связана с клиентом, юридическим лицом и делом. Для внутренних поручений включается опция "Внутренняя задача"; тогда клиент и дело не обязательны.

При выборе дела список должен показывать только незакрытые дела. Дата и время задачи выбираются с учетом расписания на день.

### Участники задачи

В задаче есть:

- основной исполнитель;
- дополнительные исполнители;
- согласующие;
- наблюдатели.

Дополнительные участники добавляются из справочника пользователей. Основной исполнитель не дублируется в списках дополнительных исполнителей.

### Согласование

Основной поток:

1. Исполнитель выполняет задачу и отправляет ее на согласование.
2. Система переводит задачу в статус "На согласовании".
3. Согласующие принимают решение по очереди, если задан порядок.
4. При согласовании задача получает статус "Согласовано".
5. При отказе задача возвращается на доработку.

Срок согласования задается отдельно от срока выполнения задачи.

## 4. Автоконтроль дел

Автоконтроль создает контрольную задачу, если по делу давно не было движения.

Система учитывает:

- активные задачи;
- дату последней задачи;
- просмотр карточки дела;
- ручное подтверждение активности;
- выключатель автоконтроля по конкретному делу.

Настройки находятся в разделе "Настройки" -> "Журнал задач":

- включить или выключить автоконтроль;
- период без движения;
- лимит задач за запуск;
- резервный исполнитель;
- срок эскалации;
- ответственный за эскалации.

В этом же блоке есть диагностика:

- включен ли автоконтроль;
- сколько дел сейчас попадает в кандидаты;
- сколько дел уже в зоне эскалации;
- сколько задач создано за последние 7 дней;
- последнее срабатывание;
- выбранные ответственные.

Если автоконтроль ошибочно создает задачи на не того сотрудника, сначала проверьте ответственного по делу, клиенту или юридическому лицу, затем резервного исполнителя в настройках.

## 5. Календарь и нагрузка

В календаре задач доступны:

- список;
- доска;
- календарь;
- нагрузка.

В карточке задачи рядом с выбором даты есть расписание на выбранный день. Оно помогает не ставить задачи в занятое время.

Цвета задач зависят от статуса, типа и роли в процессе. Выполненные задачи визуально отделяются от активных.

## 6. Уведомления

Центр уведомлений показывает события по задачам, согласованиям, запросам доступа, комментариям и автоконтролю.

Доступные действия:

- отметить прочитанным;
- открыть связанный объект;
- отправить в архив;
- удалить;
- фильтровать по типу и статусу.

Пользователь может настроить, какие типы уведомлений получать. Для ошибочных доставок администратор может выполнить повтор отправки.

## 7. Отчеты

В разделе отчетов доступны юридические отчеты первой очереди:

- юридический отчет по делам;
- диагностика активности и неактивности дел;
- CSV-выгрузка;
- переход из строки отчета в карточку дела.

Отчеты учитывают права видимости. Пользователь не должен видеть дела и финансовые документы, которые не доступны ему по роли.

## 8. Проверка прав доступа

При настройке роли проверьте:

- какие разделы видны в меню;
- может ли пользователь создавать, редактировать, удалять и экспортировать;
- какое правило видимости выбрано: только ответственный, отдел ответственного или все;
- назначен ли отдел пользователю;
- назначен ли ответственный клиенту, делу, счету, акту, договору или платежу.

Если пользователь видит лишние объекты, проверьте правило видимости роли и ответственных. Если не видит нужное, проверьте назначение ответственного и отдел.

Для согласования с заказчиком откройте панель "Аудит готовности ролей" в разделе ролей и выгрузите CSV. Файл фиксирует готовность ролей, проблемные секции и правила широкой видимости, чтобы сверить реальные роли перед включением feature flags. Широкая видимость не всегда является ошибкой: для роли `admin` она согласована как ожидаемое поведение, а для остальных ролей strict-проверка считает ее блокирующим замечанием до письменного согласования.

Если у заказчика уже согласован список рабочих ролей, перед dry-run можно задать его в `PAYPLANNER_READINESS_EXPECTED_ROLES` или хранить список в файле `PAYPLANNER_READINESS_EXPECTED_ROLES_FILE`. Readiness сверит список с аудитом ролей и остановит запуск, если в базе отсутствует ожидаемая роль. Для финальной приемки можно использовать `npm run test:legal-roles:assigned`: он дополнительно проверит, что на ожидаемые роли назначены пользователи.

## 9. Минимальный smoke-тест после выкладки

Перед ручным проходом можно запустить автоматизированный smoke:

```powershell
$env:PAYPLANNER_E2E_FRONTEND_URL = "https://<crm-домен>"
$env:PAYPLANNER_E2E_API_URL = "https://<api-домен>/api"
$env:PAYPLANNER_E2E_TOKEN = "<jwt тестового пользователя>"
npm run test:legal-e2e
```

Для dry-run на копии боевой базы удобнее запускать сводный отчет:

```powershell
$env:PAYPLANNER_READINESS_FRONTEND_URL = "https://<crm-домен>"
$env:PAYPLANNER_READINESS_API_URL = "https://<api-домен>/api"
$env:PAYPLANNER_READINESS_TOKEN = "<jwt тестового пользователя>"
npm run test:legal-readiness
```

Если отчет запускается не под администратором, отключите проверку БД и backup: `$env:PAYPLANNER_READINESS_SKIP_DATABASE_SUMMARY = "true"`.

1. Войти администратором.
2. Открыть реестр дел и карточку тестового дела.
3. Создать задачу по делу.
4. Добавить согласующего и отправить задачу на согласование.
5. Согласовать задачу другим пользователем.
6. Проверить уведомления у исполнителя и согласующего.
7. Открыть календарь и режим нагрузки.
8. Открыть отчеты и перейти из отчета в карточку дела.
9. Открыть настройки журнала задач и обновить диагностику автоконтроля.
10. Проверить роль ограниченного пользователя: он должен видеть только разрешенные объекты.

## 10. Частые проблемы

### Не появляется дело в задаче

Проверьте, что дело не закрыто и пользователь имеет право его видеть.

### Автоконтроль создал задачу не тому пользователю

Проверьте ответственного по делу, ответственное лицо клиента/юрлица и резервного исполнителя в настройках журнала задач.

### Пользователь видит лишние документы

Проверьте правило видимости роли и ответственных у связанных объектов.

### В отчете нет данных

Проверьте период отчета, права на раздел "Отчеты" и object-level видимость дел/финансовых документов.
