# PAY-36 — сверка с официальными API банков (пункт 4) и матрица существующего кода (пункт 2)

Состояние на 9 октября 2026. Доступа к личным кабинетам, ключам и sandbox банков в этом окружении нет, реальные вызовы банков не выполнялись.

## Что подтверждено публичной документацией

**СберБизнес (Sber API)** — по [описанию авторизации](https://developers.sber.ru/docs/ru/sber-api/start/oauth), [OAuth authorize](https://developers.sber.ru/docs/ru/sber-api/specifications/oauth/oauth-authorize-get) и [сценарию выписок РКО](https://developers.sber.ru/docs/ru/sber-api/scenarios/rko/statements/overview):

- Все запросы выполняются от имени пользователя СберБизнес с access token; схема — ссылка авторизации → `code` → обмен на токен, при необходимости подписание согласия.
- Access token живёт около 60 минут, refresh token — 180 дней (по FAQ рекомендуется обновлять заранее); `client_secret` имеет срок 40 дней и требует планового обновления.
- Выписка: `/fintech/api/v2/statement/transactions`, инкремент за текущий день: `/fintech/api/v2/statement/increment`; требуется право `GET_STATEMENT_ACCOUNT`. Токен обновляется через `/ic/sso/api/v2/oauth/token`.
- Не подтверждено (нужно открыть спецификацию методов): постраничность и лимиты ответа, формат статусов счетов, способ получения списка счетов, подпись/сертификаты, песочница.

**Точка** — публичная страница [tochka.com/public-api](https://tochka.com/public-api/) подтверждает наличие API (выписки, счета), но технической документации (OAuth, список счетов, асинхронная выписка, webhook-подпись) в доступных источниках найти не удалось; документация и доступы выдаются через кабинет или по запросу на public-api@tochka.com. Сторонние библиотеки не считаются источником.

Вывод: числа и пути из Word-ТЗ остаются **требованиями к сверке**. Реальные адаптеры Точки и Сбера не написаны, чтобы не угадывать контракт.

## Что реализовано независимо от конкретного банка

Код: `backend/Services/Banking/*`, `backend/Models/BankConnection.cs`. Адаптер банка реализует `IBankProvider` (список счетов и страница выписки); всё остальное общее и покрыто тестами `BankSyncServiceTests` на поддельном банке.

| Требование плана | Как решено |
| --- | --- |
| п. 5: токены | Только в защищённом виде (DataProtection, отдельная «цель»); сбой расшифровки → понятная ошибка; отказ банка → статус `ReauthRequired`, дальнейшие загрузки не идут. Сам OAuth-обмен кодом/обновление — в адаптере, не реализован. |
| п. 6: счета | Идемпотентное сопоставление по `(подключение, внешний id счёта)`; счёт с чужим ИНН владельца не привязывается; повторная загрузка без дублей. Скрытие и флаг выписок — поля `IsHidden`, `StatementsEnabled` (интерфейса пока нет). «Основной счёт» остаётся в профиле компании. |
| п. 7: статусы | Open/Limited/Preliminary/Closed/Unavailable; неизвестный статус банка → `Unavailable`; счёт, пропавший из ответа, **не** удаляется и не закрывается; новый документ допустим только для `Open` (`AllowsNewDocuments`). |
| п. 8–9: выписки | Постраничное чтение с лимитом страниц; повторное окно в 3 дня; уникальный индекс `(счёт, внешний id операции)`; незавершённая операция обновляется, подтверждённая не меняется; отметка «загружено до» сдвигается только после записи и не заходит за незавершённые; ошибка счёта изолирована. Не сделано: фоновое расписание, backoff, ограничение параллельности, webhook. |
| п. 10: разнесение | Не реализовано (ждёт решения п. 3). |
