# Журнал стабилизации поиска

Дата: 7 апреля 2026

## Повод

Пользователь сообщил, что строка поиска в разделе клиентов ведет себя нестабильно:
- ввод ощущается как "сбрасывающийся" после каждого символа;
- поиск срабатывает слишком резко;
- список дергается во время ввода.

Дополнительно был проведен аудит остальных поисковых строк в основных разделах CRM.

## Найденная причина

### 1. Клиенты

В разделе клиентов поиск был привязан напрямую к серверному запросу:
- каждое изменение `query` сразу попадало в параметры загрузки списка;
- при каждой перезагрузке списка хук клиентов переходил в полный `loading`;
- экран заново переключался в состояние загрузки вместо мягкого обновления.

Это давало плохое ощущение от ввода и создавало эффект "сброса" строки поиска.

### 2. Платежи

В разделе платежей ситуация была мягче, но поиск тоже уходил на сервер без задержки:
- серверный фильтр менялся на каждый символ;
- страница сбрасывалась слишком агрессивно;
- поиск не давал пользователю спокойно допечатать фразу.

## Что изменено

### Клиенты

Файлы:
- `src/components/Clients/Clients.tsx`
- `src/hooks/useClients.ts`

Сделано:
- ввод поиска оставлен локальным и контролируемым;
- применяемое значение поиска переведено на `debounce` с задержкой `400ms`;
- серверный запрос теперь использует только отложенное значение;
- пагинация сбрасывается на первую страницу только после применения отложенного поиска;
- повторная загрузка списка переведена в режим `refreshing`, без полного сброса экрана;
- добавлена защита от устаревших ответов, чтобы старый запрос не мог перетереть более новый.

### Платежи

Файл:
- `src/components/Payments/Payments.tsx`

Сделано:
- добавлен `debounce` для поискового запроса;
- серверный фильтр и локальный фильтр страницы синхронизированы через одно "примененное" значение поиска;
- сброс страницы теперь происходит после паузы во вводе, а не на каждый символ.

## Что проверено по остальным разделам

Проверены основные разделы, где есть поиск:
- `Клиенты`
- `Платежи`
- `Счета`
- `Акты`
- `Договоры`
- `Юридические лица`
- `Деньги`
- `Календарь`
- `Журнал активности`
- `Справочники`

Вывод:
- в `Счетах`, `Актах`, `Договорах`, `Юридических лицах`, `Деньгах`, `Журнале активности` уже использовался `useDebouncedValue`;
- в `Календаре` уже использовался `useDeferredValue`;
- в `Справочниках` поиск локальный и не требует серверного debounce;
- доработка потребовалась именно для `Клиентов` и `Платежей`.

## Проверки после изменений

- `npm run lint` — успешно
- `npm run build` — успешно
- `dotnet build backend/PayPlanner.Api.csproj -o backend/.codex-build/search-fix-check /p:UseAppHost=false` — успешно

## Итог

Поиск теперь работает по схеме:
- пользователь вводит текст;
- интерфейс не сбрасывает экран на каждый символ;
- запрос отправляется после короткой паузы;
- устаревшие ответы не перетирают новые.

Это дает более спокойный и предсказуемый UX в поисковых строках CRM.
