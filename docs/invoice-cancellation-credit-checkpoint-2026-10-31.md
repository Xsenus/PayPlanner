## Реализация и границы

`InvoicesController.Cancel` (`POST /api/Invoices/{id}/cancel`) использует существующий `BalanceApplicationLease`: чистый контекст, актуальный активный согласованный сотрудник, блокировка прав, Serializable/BEGIN IMMEDIATE. Accounts/CanEdit и видимость источника/цели проверяются до блокировки их данных. Существующие агрегаты блокируются NOWAIT; неявные ожидания, включая старую целевую запись без InvoiceId, ограничены двумя секундами текущей транзакции. Другие методы счетов и их прежний lock helper не менялись.

Основная запись уже может содержать итог рассрочки: совпадающие положительные суммы компенсируются один раз. Если положительные итоги отличаются, требуется сверка, а не автоматический выбор исторической суммы. Если одна сторона ещё не содержит оплаты, сохраняется известная положительная сумма другой стороны. До отмены `PaymentCreditInvariantScope.IncludePayments` явно проверяет покрытие прежних дебетов источника. При переносе отдельный scope защищает целевой агрегат после сохранения нового списания, до commit. Корректно компенсируемый источник не объявляется ошибочным из-за последующего обнуления PaidAmount: старый дебет и квитанция сохраняются.

В режиме отмены только неоплаченных взносов scope охватывает пересчёт основной записи и проверяется после Save до commit. Если пересчёт потерял зачёт, откатываются отменённые взносы и история дела. Оплаченные строки не переписываются для обхода проверки.

Повторная отмена показывает текущую отменённую запись без нового возврата/аванса/списания. Уведомление выполняется только после нового успешного действия, commit и освобождения транзакции. Сохранённый результат прежнего зачёта остаётся доступен как replay; новый зачёт в аннулированный платёж или счёт отклоняется общим `ClientBalanceService` для клиентов/организаций и обоих форматов запросов. Структуры DTO и маршруты не расширялись; frontend, схема и миграции не менялись.

Проверки используют серверные группировки и прежние ограниченные запросы общего guard, без чтения всей истории и N+1. Новое IncludePayments не меняет прежние вызовы scope. Набор генераторных платежей загружается только для выбранного счёта; фильтры видимости и неоднозначных исторических владельцев применены до чтения целевого документа. Частичное сохранение денег, возврата, аванса и истории не допускается.
