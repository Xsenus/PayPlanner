# Roadmap: финансовые права, касса и происхождение операций

Дата старта: 2026-06-16  
Критичность: высокая  
Контекст заказчика: пользователи сообщили, что без ожидаемых прав могут видеть платежи и финансовые операции через карточки клиентов, закладки, раздел "Деньги: касса" и связанные документы. Нужно закрыть обходы доступа и сделать происхождение кассовых операций понятным.

## Как работать с этим roadmap

Статусы:

- `[ ]` не начато.
- `[~]` в работе.
- `[x]` выполнено и проверено кодом, тестами, кодировкой и локальной БД, если пункт требует БД.
- `[!]` заблокировано, причина указана рядом.
- `[decision]` требуется решение пользователя или бизнеса.
- `[acceptance]` требуется ручная приемка на реальных данных или в окружении заказчика.

Правила обновления:

- Перед началом новой задачи открыть этот файл и проверить все связанные пункты.
- При начале работы заменить `[ ]` на `[~]`.
- После реализации добавить строку `Выполнено:` с кратким фактом, тестами и ссылкой на коммит, если он уже есть.
- Не отмечать `[x]`, пока не пройдены нужные проверки: backend/frontend tests, сборка, UTF-8, локальная БД, ручная приемка, если она явно указана.
- Если найден новый обход или риск, добавить его сюда отдельным пунктом.
- После user-facing изменений добавить запись в `backend/AppReleases/releases.json`.

## Цели

1. Пользователь без права на платежи не видит платежи, кассу, денежные операции, остатки, гонорары, долги и финансовые итоги через любые UI- или API-обходы.
2. Права на счета, акты, договоры и платежи применяются отдельно, но связанные финансовые сводки не раскрывают данные из закрытых разделов.
3. Кассовые ордера ПКО/РКО имеют понятное происхождение: из платежа, денежной операции, возврата, инвентаризации или ручного ввода.
4. Отчеты и экспорты не раскрывают финансовые данные тем, у кого нет соответствующих прав.
5. Все изменения закреплены тестами, проверены на локальной БД и описаны в "Что нового".

## Текущие факты из анализа

- Разделы меню `Деньги: банк`, `Деньги: касса`, `Деньги: карты`, `Деньги: E-money`, `Деньги: итого` в UI открываются через `permissions.payments.canView`.
- API денежных операций `/api/money-operations` читает данные через видимость раздела `payments`.
- API кассовых ордеров `/api/cash-orders` сейчас защищен только `[Authorize]`; отдельной проверки `payments.canView/canCreate/canEdit/canDelete/canExport` не найдено.
- Кассовые отчеты `cash` и `cash-orders` в `ReportsController` проверяют право на отчеты, но не проверяют право на платежи.
- В локальной PostgreSQL БД роль `Секретарь`: `payments.canView = false`, `reports.canView = false`.
- В локальной PostgreSQL БД роль `Юрист`: `payments.canView = false`, `accounts.canView = false`, `acts.canView = false`, `contracts.canView = false`, `reports.canView = false`.
- Данные со скрина совпали с локальной БД: ПКО `ПКО-2026-0012`, `ПКО-2026-0011`, `ПКО-2026-0010`, `ПКО-2026-0004`, `ПКО-2026-0003`, `ПКО-2026-0002` связаны с платежами.
- В локальной БД 30 кассовых ордеров, все связаны с платежами; 27 проведенных ПКО дают остаток `967 560 ₽`.
- Большинство ПКО со скрина созданы пользователем `Кожеваткин Андрей Владимирович`.

## Milestone 3. Раздел "Деньги" и денежные операции

Цель: синхронизировать UI и backend-права для ручных денежных операций, импортов и действий.

  - Текущий риск: чтение использует `payments.canView`, экспорт использует `payments.canExport`, но создание/переводы/импорт/редактирование/удаление требуют отдельной проверки.
  - DoD: составлена таблица endpoint -> требуемое право -> тест.
  - Выполнено: действия разделены по `payments.canCreate`, `payments.canEdit`, `payments.canDelete`, `payments.canExport`; чтение осталось на `payments.canView`.

- [x] Добавить проверки прав в `MoneyOperationsController`.
  - Создание ручной операции: `payments.canCreate`.

  - Редактирование, сверка, игнорирование, привязка к счету: `payments.canEdit`.
  - Удаление: `payments.canDelete`.
  - Импорт банковской выписки, повторная обработка, rollback: `payments.canCreate`/`payments.canEdit`; точное правило закрепить в тестах.

  - Скрывать/блокировать удаление без `payments.canDelete`.
  - Скрывать/блокировать создание ПКО без `payments.canCreate`.
