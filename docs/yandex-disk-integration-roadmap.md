# Роадмап интеграции с Яндекс.Диском

## Этап 1. Отдельный раздел "Я.Диск"

- Добавить админский раздел "Я.Диск" в навигации.
- Сохранить OAuth-токен и корневую папку Яндекс.Диска в системных настройках.
- Сделать файловый менеджер: просмотр папок, создание папок, загрузка, скачивание, удаление, копирование, перемещение и переименование через перемещение.
- Добавить редактирование текстовых файлов через скачивание содержимого и повторную загрузку.
- Покрыть backend-контур тестами на настройки, пути и вызовы REST API.

## Этап 2. Безопасность и права

- Выделить отдельные права роли для Яндекс.Диска: просмотр, создание/загрузка, редактирование/перемещение, удаление и скачивание.
- Добавить журналирование операций с файлами, чтобы администратор видел, кто изменил или удалил ресурс.
- Добавить защиту от случайного удаления вне выбранной корневой папки.

## Этап 3. Синхронизация документов CRM

- Описать правила, какие сущности CRM отправляются на диск: счета, акты, договоры, документы дела, вложения задач.
- Добавить шаблон структуры папок по клиенту, делу, договору и типу документа.
- Сделать ручную отправку выбранного документа в Яндекс.Диск из карточек CRM.
- Сохранять ссылку на выгруженный файл и статус последней синхронизации.

## Этап 4. Фоновая синхронизация

- Добавить очередь синхронизации с повторными попытками при сетевых ошибках.
- Добавить диагностику в "Настройки" -> "Обслуживание базы данных" -> "Фоновые сервисы".
- Добавить dry-run режим, чтобы перед включением увидеть, какие файлы будут созданы, обновлены или удалены.
- Добавить правила конфликтов: CRM главная, Яндекс.Диск главный или ручное подтверждение.

## Этап 5. Приемка и мониторинг

- Проверить сценарии с настоящим OAuth-токеном на тестовой папке.
- Добавить отчеты по ошибкам синхронизации и последнему успешному обмену.
- Добавить пользовательские подсказки для случаев нехватки места, неверного токена, отсутствия прав и недоступности Яндекс.Диска.
