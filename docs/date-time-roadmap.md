# Роадмап проверки дат и времени

Цель: привести все даты и время в PayPlanner к единому правилу, проверить проблемные места и закрыть риск сдвига времени у пользователей из разных регионов.

## Базовое правило

- [x] Точные события хранить как UTC: закреплено helper-тестами, задачами, календарями, делами, журналами и экспортами.
- [x] Показывать точные события пользователю через `timezoneId` из профиля: проверено для backend-formatter, frontend-formatter и основных журналов.
- [x] Локальные даты без времени не переводить как UTC-момент: закреплено для платежных дат, отчетных дат и date-only значений.
- [x] Календарные диапазоны строить по локальному дню пользователя: проверено для задач, отчетов и фильтров синхронизации.
- [x] Внешние календари должны получать точное время и timezone события/исполнителя: проверено Google/Yandex regression-тестами.
- [x] Убрать фиксированные смещения вроде `+07:00`: в рабочем коде остались только тестовые фикстуры и диагностические сравнения.
- [x] Не использовать timezone браузера там, где правило требует timezone профиля: закреплено `timeZoneDate`, `dateUtils`, `caseTaskPayload` и UI-тестами задач.

## Типы дат

- [x] `InstantUtc`: точный момент времени, например создание, обновление, срок задачи, судебное заседание; нормализация закреплена helper- и controller-тестами.
- [x] `LocalDate`: дата без времени, например дата счета, дата акта, дата рождения, дата платежа; не сериализуется как UTC-инстант.
- [x] `LocalDateTime + TimeZoneId`: пользователь вводит локальное время, система переводит его в UTC; проверено frontend/backend-тестами.
- [x] `System/Audit Time`: техническое время системы, хранится UTC, показывается через timezone пользователя; проверено audit/system-journal проходом.
