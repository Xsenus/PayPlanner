## Причины и изменения

В режиме просмотра завершённой задачи поле результата принимало текст, но команды сохранения не было. Это воспроизведено тестами обеих карточек. Добавлена общая команда «Сохранить результат» для пользователей, имеющих право редактировать задачу. Без такого права поле результата недоступно для изменения. Используется существующий PATCH статуса; нового API нет. Карточка после исправления остаётся открытой, история обновляется. Пустой обязательный результат не отправляется; повторный клик во время запроса не создаёт вторую запись. При отказе текст остаётся для повторной попытки.

Обнаружен связанный финансовый дефект: повторное сохранение завершённого статуса вызывало синхронизацию выплаты и могло отменить существующую неоплаченную запись. При исправлении результата без изменения статуса/срока выплата больше не синхронизируется. В полном редакторе существующая выплата сохраняется, если не изменены её исходные данные: компания/клиент/дело, название, исполнитель и условия выплаты. При действительном изменении условий прежняя синхронизация продолжает работать. Сохранены проверки прав, история, обычные переходы статуса и правила завершения.

Подготовлены отдельные неактивные записи «Что нового» **1.14.103** и **1.14.104**. Прежняя 1.14.102 о скачивании счёта остаётся неактивной.

## Печать в браузере

Существующий изолированный финансовый browser-сценарий дополнен открытием настоящей карточки счёта после генерации из заказ-наряда. Проверяются реальные ответы HTML, оба варианта печати, настоящее окно печати и вызов браузерной печати. Из каждого окна формируется PDF A4; отдельно скачиваются PDF и Word из карточки. Ответы генератора не подменяются.

Финальная проверка использует синтетическую организацию с реквизитами, QR, изображениями подписи и печати. Браузер подтвердил загрузку изображений и их отсутствие в обычном варианте. Просмотрены три растровых представления: обычная и подписанная печать, скачанный PDF. Все три формы помещаются на одной странице A4, текст, позиции, сумма 35 рублей и реквизиты читаются без обрезания; подпись и печать видны только в соответствующем варианте. Это настоящая браузерная печать локального приложения; физический принтер и рабочие шаблоны на VPS не проверялись.

Тест разрешает только один дополнительный PUT пользовательской настройки таблицы `accounts_table_settings` после перехода к счёту: это штатное сохранение настроек списка. Все остальные неожиданные бизнес-записи и внешние сетевые запросы остаются запрещены. Первые попытки остановились именно на этой дополнительной настройке уже после формирования файлов; они не объявлены успешными. Короткая проверка не означает пользовательскую приёмку всех длинных печатных форм и рабочих шаблонов.

Браузерные данные синтетические, БД одноразовая. Почта и фоновые службы явно отключены; в БД отключены email-уведомления. Восстановленная домашняя и производственная БД не используются для разрушающих проверок.
