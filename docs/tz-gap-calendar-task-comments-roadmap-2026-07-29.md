# Roadmap. Комментарии внешнего календаря и задачи

Дата создания: 29 июля 2026.
Статус: активный roadmap, требуется уточнение бизнес-семантики комментариев.

## Цель

Связать комментарии задачи и внешнего календарного события без дублей, циклов синхронизации, потери автора и раскрытия внутренних сообщений.

## Текущее состояние

- `[x]` Google и Яндекс двусторонне синхронизируют основные поля задач.
- `[x]` В CRM есть отдельная лента комментариев задачи.
- Описание календарного события не является общей лентой комментариев.

## Решения заказчика

- `[decision]` Определить, какие комментарии экспортируются: все, только внешние либо явно отмеченные.
- `[decision]` Выбрать представление во внешнем календаре: описание события или отдельный блок с журналом.
- `[decision]` Определить, могут ли внешние участники добавлять комментарии и как подтверждается автор.

## Модель данных

- `[ ]` Добавить внешний visibility-флаг комментария.
- `[ ]` Хранить provider, calendar id, event id, external comment/revision id и sync hash.
- `[ ]` Разделить автора CRM, владельца календаря и неподтвержденного внешнего автора.
- `[ ]` Хранить tombstone удаленного внешнего комментария без физического удаления истории.
- `[ ]` Ввести cursor/version для инкрементального чтения.

## Синхронизация CRM → календарь

- `[ ]` Формировать стабильный машинно-размеченный блок, не перезаписывая пользовательское описание.
- `[ ]` Экспортировать только разрешенные комментарии и безопасный минимум данных.
- `[ ]` Добавлять маркеры id/hash для идемпотентного обновления.
- `[ ]` Ограничить длину и корректно обрабатывать обрезку провайдером.
- `[ ]` Не отправлять внутренние вложения; использовать разрешенные защищенные ссылки.

## Синхронизация календарь → CRM

- `[ ]` Распознавать только поддерживаемый блок и изменения после cursor.
- `[ ]` Создавать комментарий один раз при повторных sync.
- `[ ]` Помечать внешний источник и уровень доверия автора.
- `[ ]` Не позволять внешнему событию менять системную историю и решения согласования.
- `[ ]` Обрабатывать удаление блока по утвержденной политике без потери аудита.

## Конфликты и циклы

- `[ ]` Выбрать правило для одновременного изменения.
- `[ ]` Использовать coordinator между Google и Яндекс, чтобы изменение не ходило по кругу.
- `[ ]` Сравнивать semantic hash, игнорируя форматирование и служебные маркеры.
- `[ ]` Показать конфликт пользователю вместо молчаливой потери текста.

## Производительность и безопасность

- Загружать комментарии одной проекцией по batch task ids.
- Не выполнять отдельный внешний запрос на каждый комментарий.
- Не логировать текст комментариев на информационном уровне.
- Проверять право пользователя на задачу и разрешение экспорта.

- `[ ]` Интеграционные тесты Google и Яндекс: create/update/delete/duplicate/conflict.

## Definition of Done

- Разрешенные комментарии двусторонне синхронизируются один раз и сохраняют источник.
- Внутренние данные не покидают CRM.
- Нет циклов, N+1 и информационного log spam.
- Есть тесты, release note, успешный deploy и production-приемка.
