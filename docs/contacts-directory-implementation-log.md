# Журнал реализации раздела "Контакты"

Дата: 7 апреля 2026

## Что реализовано

- Добавлена новая сущность `ExternalContact` для сторонних контактов, которые не должны попадать в основную таблицу клиентов.
- Добавлен единый backend API `api/contacts` для агрегированного списка контактов:
  - `Все`
  - `Клиенты`
  - `Сторонние`
- Клиентские контакты читаются поверх существующих данных `Client` и расширенного профиля из `Notes`.
- Сторонние контакты хранятся отдельно и могут быть связаны с `LegalEntity` и ответственным пользователем.
- Реализовано редактирование:
  - контакта клиента
  - стороннего контакта
  - создание нового стороннего контакта
- Для сторонних контактов поддержан выбор ответственного пользователя.
- Добавлен экспорт Yealink XML через `GET /api/contacts/exports/yealink`.
- В экспорт встроена нормализация номеров с вариантами `7...` и `8...`.
- Раздел `Контакты` добавлен в приложение и в боковую навигацию.
- Для обязательных полей добавлены секции:
  - `contacts-client`
  - `contacts-external`

## Как работает текущая модель

### Клиенты

- Источником истины остаётся существующая сущность `Client`.
- В разделе `Контакты` клиент отображается как физическое лицо.
- Если клиент привязан к организации, в контактах показывается организация и связанные поля.

### Сторонние контакты

- Источником истины является `ExternalContact`.
- Такие контакты можно использовать для телефонной книги и для связки с организациями, не превращая их в клиентов.

### Телефония

- CRM формирует Yealink-совместимый XML.
- Администратор уже может скачать файл вручную.
- XML генерируется на основе общего справочника контактов, а не из отдельного Excel-файла.

### Импорт текущей телефонной книги Yealink

- Добавлен админский импорт `RemotePhonebook.xml` через `POST /api/contacts/imports/yealink`.
- Импорт сравнивает записи по нормализованным телефонам, а не по ФИО, потому что в старой книге есть исторические имена и ручные правки.
- Для российских номеров `7...` и `8...` используется один ключ сравнения по последним 10 цифрам, чтобы не создавать дубль одного и того же телефона.
- Уже существующие телефоны в клиентах и сторонних контактах не перезаписываются и не дублируются.
- Контакты, которых нет в CRM, создаются как `ExternalContact`, чтобы не смешивать сторонний телефонный справочник с реальными клиентами.
- Контакты без телефонов и повторы внутри самого XML пропускаются и попадают в отчет импорта.
- Для старых файлов с испорченной UTF-8/Windows-1251 кодировкой имена и группы дополнительно нормализуются перед сохранением.
- В интерфейсе импорт выполняется в два шага: сначала dry-run анализирует файл, затем администратор подтверждает реальную запись в БД.

## Что отложено на следующий этап

- Быстрое создание клиента или юрлица прямо из раздела `Контакты`.
- Добавление представителя организации прямо из карточки `LegalEntity`.
- Выкладка XML на FTP/SFTP по кнопке или по расписанию.
- Фоновая проверка удалённого XML-файла и сравнение с CRM.
- Отдельный журнал синхронизации телефонии.
- Разделение Yealink-экспорта на несколько книг, если это понадобится для разных аппаратов или отделов.

## Что важно для дальнейшей разработки

- Не делать FTP-файл источником истины.
- Источником истины должна оставаться только CRM.
- Yealink XML, FTP-выгрузка и любые внешние файлы должны быть только экспортом из CRM.
