# Журнал реализации раздела "Контакты"

Дата: 7 апреля 2026
Обновлено: 13 августа 2026

## Завершение единого справочника (13 августа 2026)

- В левом меню оставлен один раздел `Контакты`; отдельные пункты `Клиенты` и `Юридические лица` убраны из основного меню, но старые маршруты сохранены для совместимости и переходов из документов.
- В одном списке отображаются физические лица, организации и быстрые контакты.
- Быстрый контакт поддерживает тип `Person` или `Organization`, ИНН организации и роли `Contact`, `Client`, `Supplier`, `Agent`.
- Физическое лицо можно связать с уже созданным юридическим лицом либо с быстрой карточкой организации.
- Быструю запись можно оформить как полноценного клиента или юридическое лицо. Повторная строка в общем списке не создаётся.
- При оформлении организации её сотрудники автоматически получают связь с созданным юридическим лицом.
- Добавлен защищённый динамический Yealink Remote Phone Book: `GET /api/contacts/phonebook/yealink/{token}`.
- Токен задаётся переменной окружения `PAYPLANNER_PHONEBOOK_TOKEN`. Если токен не настроен или не совпадает, endpoint отвечает `404` и не раскрывает наличие телефонной книги.
- В телефонную книгу попадают только активные физические лица с включённой синхронизацией; отдельные карточки организаций не экспортируются.

## Что реализовано

- Добавлена новая сущность `ExternalContact` для сторонних контактов, которые не должны попадать в основную таблицу клиентов.
- Добавлен единый backend API `api/contacts` для агрегированного списка контактов:
  - `Все`
  - `Клиенты`
  - `Сторонние`
- Клиентские контакты читаются поверх существующих данных `Client` и расширенного профиля из `Notes`.
- Сторонние контакты хранятся отдельно и могут быть связаны с `LegalEntity` и ответственным пользователем.
- Реализировано редактирование:
  - контакта клиента
  - стороннего контакта
  - создание нового стороннего контакта
- Для сторонних контактов поддержан выбор ответственного пользователя.
- Добавлен экспорт Yealink XML через `GET /api/contacts/exports/yealink`.
- При экспорте привычные варианты `8...`, `+7...` и десятизначный номер приводятся к единому телефонному формату `7XXXXXXXXXX`; введённое пользователем значение в карточке при этом не меняется.
- Раздел `Контакты` добавлен в приложение и боковую навигацию.
- Для обязательных полей добавлены секции:
  - `contacts-client`
  - `contacts-external`

## Как работает текущая модель

### Клиенты

- Источником истины остаётся существующая сущность `Client`.
- В разделе `Контакты` клиент отображается как физическое лицо.
- Если клиент привязан к организации, в контактах показывается организация и связанные поля.
- Изменения телефонов и email в разделе контактов обновляют реальные данные клиента.

### Сторонние контакты

- Источником истины является `ExternalContact`.
- Такие контакты можно использовать для телефонной книги и связи с организациями, не превращая их в клиентов.
- Сторонний контакт можно добавить вручную из раздела `Контакты`.

### Телефония

- CRM формирует Yealink-совместимый XML.
- Администратор может скачать файл вручную.
- XML генерируется на основе общего справочника контактов, а не из отдельного Excel-файла.
- В будущих этапах XML можно будет выгружать на FTP/SFTP по расписанию или вручную.

## Импорт телефонной книги Yealink

- Добавлен админский импорт `RemotePhonebook.xml` через `POST /api/contacts/imports/yealink`.
- Импорт сравнивает записи по нормализованным телефонам, а не по ФИО.
- Для российских номеров `7...` и `8...` используется один ключ сравнения по последним 10 цифрам.
- Контакты без телефонов и повторы внутри XML пропускаются и попадают в отчёт.
- Существующие контакты не дублируются.

### Новый безопасный сценарий импорта

1. Администратор выбирает XML-файл в разделе `Контакты`.
2. Сначала выполняется dry-run анализ файла без записи в БД.
3. После чтения файла открывается модалка предпросмотра.
4. В модалке по каждой строке видно:
   - имя из XML
   - телефоны из XML
   - найденный контакт в CRM, если он уже есть
   - действие, которое будет выполнено
5. Для новых контактов можно выбрать:
   - `Создать сторонний`
   - `Создать клиента`
   - `Не переносить`
6. Для уже найденных контактов можно выбрать:
   - `Оставить как есть`
   - `Обновить существующий`
7. Перед реальной записью в БД показывается отдельное окно подтверждения.
8. После импорта показывается toast с итогами: сколько создано, обновлено, оставлено без изменений и пропущено.

### Правила обновления существующих контактов

- По умолчанию существующий контакт остаётся без изменений.
- Если выбрать `Обновить существующий`, CRM объединяет телефоны из XML с текущими телефонами контакта.
- Для клиента обновление включает синхронизацию с телефонной книгой в расширенном профиле.
- Для стороннего контакта обновление включает `SyncToPhonebook` и сохраняет объединённый список телефонов.
- ФИО не перезаписывается, если в CRM оно уже заполнено.

## Что требует данных от поставщика телефонии

- Выкладка XML на FTP/SFTP по кнопке или по расписанию.
- Отдельный журнал синхронизации телефонии.
- Разделение Yealink-экспорта на несколько книг, если это понадобится для разных аппаратов или отделов.
- Настройка конкретных аппаратов или приложения провайдера требует адреса панели, модели/прошивки телефонов и выданных поставщиком реквизитов. Базовый прямой HTTPS-канал со стороны CRM уже готов.

## Что важно для дальнейшей разработки

- Не делать FTP-файл источником истины.
- Источником истины должна оставаться только CRM.
- Yealink XML, FTP-выгрузка и любые внешние файлы должны быть только экспортом из CRM.
- Для импорта старых файлов всегда сначала использовать предпросмотр и подтверждение, чтобы не создать массовые дубли.
