## Существующий PostgreSQL и отдельная роль

Использован существующий `postgresql-x64-17`, PostgreSQL 17.2, loopback порт 5433. Роль `payplanner_ci`: LOGIN/CREATEDB, без SUPERUSER/CREATEROLE/REPLICATION/BYPASSRLS, без членства в других ролях, до 40 соединений. Тесты создают и удаляют собственные одноразовые базы с существующими префиксами `pp_`/`payplanner_` и 32-значным GUID. Нового экземпляра PostgreSQL, контейнера или постоянной тестовой БД нет.

Перед прежними правилами `pg_hba.conf` добавлен отдельный блок для этой роли: SCRAM на loopback к служебной `postgres`, явный запрет шести ранее существовавших БД, SCRAM к синтетическим именам, затем запрет всех остальных адресов и БД. Это существенно: в старой конфигурации было общее правило trust. Оно не менялось для прочих приложений, но тестовая роль до него не доходит. Изменение проверено через `pg_hba_file_rules`, применено reload без перезапуска сервера. Резервная копия прежнего HBA лежит в защищённом каталоге runner.

Случайный пароль не попадал в репозиторий. Соединение хранится как GitHub Actions secret `PAYPLANNER_XSENUS_TEST_POSTGRES`; локальная копия пароля зашифрована Windows DPAPI для текущего пользователя. Не выводить её в журнал и не копировать в исходники. Клиенты берутся из существующего `C:/Program Files/PostgreSQL/17/bin`. При каждом test/browser job preflight проверяет роль, сервер и отказ в доступе к `payplanner`. Учтена локализация ошибок PostgreSQL.

Во всех локальных backend-проверках явно выключены почта и фоновые сервисы. База `payplanner`, её данные, SMTP и финансовые записи не изменялись. Создавались только отдельные синтетические базы; их очистка подтверждена.
