### DOC-04 сохранение — продолжать работу с открытой карточкой

**Приоритет и доступ:** P1, средний риск и объём; независимый C0 этап с mock API подходит Claude Code без БД. C1 только если меняется контракт сохранения/канонической выдачи. Ускорение интерфейса не должно зависеть от завершения банковского объединения.

Сохранение частичной оплаты с переносом остатка не выполняется повторно при следующем нажатии. Действие закрытия явно и сохраняет родительские фильтры/страницу/прокрутку. Конкретное название дополнительной кнопки — согласуемый вариант; не превращать его в обязательное бизнес-правило без ответа.

**Проверки и DoD:** create→save→edit→save, частичная оплата/аванс/рассрочка/связанный счёт, медленный ответ/ошибка/двойной клик/lost ACK, потеря прав и закрытие с несохранённым вводом. C0 — исходники, безопасные макеты и mock API, без БД/VPS; подходит Claude Code без системного доступа. Реальные деньги и внешние сообщения не используются как тестовый инструмент.

Закрытие `[x]`: весь указанный объём, применимые тесты/кодировка/данные и доказательство. Частичный механизм не закрывает весь пакет. Релизные заметки — пользовательским языком и общим форматом, согласованным ранее. YouGile: только локальный черновик по существенному изменению; публикация/перемещение после отдельной команды на конкретные карточки. После полной приёмки блока архивировать его отдельно.

**DOC-07/08:** акт ссылается на основание и переносит позиции, показывает дату/номер и самостоятельные статусы передачи/подписания. Быстрые действия рядом с карточкой: печать, PDF, PDF с подписью, Word и связанные документы. ПКО использует выбранную дату факта; в основании существующие счёт/акт/договор с номерами и датами, пояснение рассрочки после них. Реальные ссылки/права/версия обязательны, поиск «последнего договора по клиенту» не заменяет связь. Проверки: каждая комбинация отсутствующих оснований, скрытая ссылка, длинная цепочка и A4/масштабирование, повторная печать после смены профиля. Последняя жалоба на ПКО не объявляется исправленной этим исследованием.

**DOC-10:** форма акта сверки различает базу по счетам и по актам/накладным/УПД, учётные/неучётные/все оплаты, период и дату подписи. Сначала бухгалтер утверждает основу и начальное сальдо; затем реализовать раскрытие строк, авансы/распределения/возврат и совпадающую печать. Пакетная выгрузка имеет период, типы/направления, «только новые» и историю результата; использовать существующее хранилище, ограниченный фоновый пакет, ошибки/повтор/права, не произвольную выгрузку чужих документов.

**DOC-12:** C0 — компактная форма/fixtures/визуальное сравнение; C1 — весь цикл на синтетических двух БД и роли; C2 — бухгалтер/владелец на согласованном наборе. Текущее исследование — образец и происхождение требований, не ручная приёмка записи/расчётов PayPlanner.
