## Реализовано локально

В общем PaymentModal прямой зачёт в текущий платёж клиента/организации и зачёт в выбранный платёж рассрочки используют guarded API. Callback ClientDetail теперь возвращает тот же proof-bearing результат без прежнего незащищённого фонового refresh; тип callback не допускает старый ответ только с двумя суммами. Прямая панель распределения аванса в Payments пока остаётся следующим этапом, её legacy-вызовы не выданы за исправленные.

Общий компактный блок `BalanceApplicationRecovery` находится вне disabled fieldset. До принятия результата прежней попытки сохранение и остальные финансовые действия заблокированы, закрыть карточку можно. Доступны явные проверка и закрытие попытки; закрытие уже исполненного зачёта получает его результат, не возвращает деньги. История пользователя/контрагента читается из ограниченной metadata, поэтому неизвестный целевой платёж показывается после переоткрытия даже при исчезновении из списка долгов. Собственное появление metadata/занятости не меняет владельца активного действия.

Успешный ответ и повторная проверка заменяют финансовую часть формы каноническими суммой, оплатой, статусом, датами оплаты и системными заметками. Описание, обычные заметки и остальные введённые поля сохраняются. Актуальный баланс отделён от исторического остатка операции. Локальный минимум зачтённой оплаты устанавливается из канонических заметок; прибавления к старой форме и повторного увеличения при replay нет. Список рассрочки получает канонический целевой платёж и убирает закрытый долг. Принятие/очистка metadata сохраняет проверку точного proof, пользователя, карточки, прав и текущей записи.

Обнаружен и исправлен отдельный дефект: сервер пишет «Зачтено с баланса контрагента», а прежний разбор распознавал только «клиента». Общий parser теперь поддерживает оба варианта и прежнюю строку без уточнения, не считает возвраты и отрицательные значения. Исторические строки и суммы не переписываются.

## Между вкладками

Удаление metadata другой вкладкой само по себе не разрешает сохранить старую финансовую форму. Ограниченный кеш наблюдений хранит такую попытку в текущем UI до явного чтения подтверждённого исхода и канонических данных; отзыв/возврат права не снимает эту защиту. При смене auth session наблюдения сбрасываются; чужие записи не показываются. В кеше не более64 записей, новые неизвестные исходы не запускают автоматические опросы. Неподтверждённый результат оставляет форму заблокированной.

Новый `openAcknowledgedBalanceApplication` — только чтение. Он требует ту же учётную запись/API и отсутствие именно той локальной записи на всём пути; новый ключ/запись или поздний ответ запрещают принятие. Он не создаёт metadata и не отправляет Apply/Cancel. После подтверждённого Committed загружает канонические платёж/баланс; Cancelled не меняет оплату. Нельзя принять ответ вместо новой попытки. Кнопка отмены для исчезнувшей записи не показывается. Собственное принятие финансовых данных отмечается отдельно, поэтому собственная очистка не переводит уже обновлённую форму в состояние чужого устаревшего окна.

Для принятия канонического платежа дополнительно проверяются допустимый статус и настоящий boolean признака оплаты. Неизвестный/неполный JSON сохраняет неизвестный исход вместо записи некорректного состояния в форму.
