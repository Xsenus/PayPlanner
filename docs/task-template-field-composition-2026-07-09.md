# Состав полей шаблона задачи

Дата фиксации: 9 июля 2026.
Статус: рабочее решение для реализации roadmap 4.

## Зачем фиксируем

Клиент отдельно отметил, что конструктив и дизайн шаблонов задач нельзя оставлять незавершенными. Чтобы дальше проектировать интерфейс и реализацию без разночтений, фиксируем минимальный состав полей, который закрывает текущие замечания по задачам, согласованиям, наблюдателям и рабочим сценариям дела.

Если заказчик позже добавит новые требования, шаблон можно расширить без ломки базовой модели.

## Обязательные поля шаблона

Эти поля должны быть в первой рабочей версии:

- Название шаблона.
- Описание задачи.
- Тип задачи: задача, контроль, согласование или другой уже поддерживаемый тип.
- Приоритет.
- Плановый срок: фиксированный период от даты создания или от выбранной базовой даты.
- Теги.
- Исполнитель по умолчанию.
- Согласующие.
- Наблюдатели.
- Напоминания и каналы уведомлений.
- Привязка к сценарию: без привязки, этап дела или тип дела.
- Активность шаблона: активен или скрыт из выбора.

## Дополнительные поля

Эти поля не блокируют первую реализацию, но модель и интерфейс должны оставлять место для расширения:

- Чек-лист.
- Файлы или ссылки на типовые документы.
- Правила автосоздания задачи при переходе этапа дела.
- Плановый результат задачи.
- Подсказка для исполнителя.
- Роль ответственного вместо конкретного сотрудника, если исполнитель должен определяться из дела.

## Правила применения шаблона

- Шаблон не должен стирать ручные правки пользователя без явного действия.
- При применении к новой задаче пустые поля можно заполнить из шаблона автоматически.
- Если пользователь уже изменил поле, система должна сохранить ручное значение или явно спросить о замене.
- Согласующие и наблюдатели применяются тем же механизмом, что и в обычной задаче.
- Старое и новое окно задачи должны получать одинаковый результат применения шаблона.
- В сценариях дела шаблон должен подставлять связь с клиентом, делом и юридическим лицом так же, как текущие подсказки по этапу дела.

## Минимальный UI для первой версии

В списке шаблонов должны быть видны:

- название;
- тип;
- приоритет;
- плановый срок;
- исполнитель;
- количество согласующих и наблюдателей;
- теги;
- привязка к этапу или типу дела;
- статус активности.

В форме шаблона должны быть:

- компактные секции основных данных, срока, участников, уведомлений и привязки;
- выбор согласующих и наблюдателей тем же компонентом, что используется в задаче;
- видимые выбранные пользователи под кнопкой выбора;
- удаление выбранных пользователей без пересоздания шаблона;
- предпросмотр того, какие поля попадут в задачу.

## Что не входит в первую версию

- Сложные условия вида "если сумма больше X" или "если клиент из группы Y".
- Конструктор произвольных бизнес-процессов.
- Отдельная система прав только для шаблонов, кроме уже действующих прав на задачи и настройки.
- Массовое применение шаблона к существующим задачам.

## Definition of Done для этого решения

- Состав полей достаточен для проектирования списка, формы и применения шаблона.
- Согласующие и наблюдатели включены в обязательную часть, потому что это отдельное замечание клиента.
- Чек-лист и файлы отнесены к расширению, чтобы не блокировать первую рабочую поставку.
- Правило сохранения ручных правок зафиксировано до начала реализации.
