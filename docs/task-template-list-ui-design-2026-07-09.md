# UI списка шаблонов задач

Дата фиксации: 9 июля 2026.
Статус: проект интерфейса для реализации roadmap 4.

## Цель экрана

Список шаблонов задач должен быть рабочим инструментом, а не справочной страницей. Пользователь должен быстро найти типовой шаблон, понять его назначение, увидеть ключевые параметры и выполнить основное действие: применить, открыть, изменить, скрыть или создать новый шаблон.

Экран должен визуально совпадать с внутренними разделами CRM: компактные отступы, плотная таблица на desktop, карточки на mobile, фильтры сразу под заголовком.

## Место в интерфейсе

Рекомендуемое размещение:

- основной вход: раздел "Журнал задач", кнопка или вкладка "Шаблоны";
- дополнительный вход: настройки задач для административного управления;
- быстрый вход: из окна создания задачи через кнопку "Выбрать шаблон".

Если шаблоны открываются из журнала задач, экран должен использовать тот же контекст прав, что и задачи.

## Верхняя панель

В первой строке:

- заголовок "Шаблоны задач";
- счетчик найденных шаблонов;
- кнопка "Создать шаблон";
- кнопка обновления;
- кнопка настроек колонок, если используется табличный режим.

Во второй строке фильтров:

- поиск по названию, описанию, тегам и привязке;
- фильтр активности: активные, скрытые, все;
- фильтр типа задачи;
- фильтр приоритета;
- фильтр исполнителя;
- фильтр привязки: без привязки, этап дела, тип дела;
- кнопка сброса фильтров.

Панель должна помещаться в компактный блок `p-3`, `gap-3`, без больших декоративных отступов.

## Таблица desktop

Основной desktop-вид: таблица с фиксированным набором колонок.

Обязательные колонки:

- название шаблона;
- тип;
- приоритет;
- плановый срок;
- исполнитель;
- согласующие;
- наблюдатели;
- теги;
- привязка;
- активность;
- действия.

Поведение колонок:

- название, исполнитель и привязка не должны обрезаться до полной нечитаемости;
- согласующие и наблюдатели показываются счетчиком и первыми именами;
- теги показываются короткими бейджами;
- активность отображается переключателем или бейджем;
- действия представлены иконками: применить, открыть, копировать, скрыть, удалить.

## Mobile-вид

На мобильных ширинах таблица заменяется карточками.

В карточке должны быть:

- название и статус активности;
- тип, приоритет и плановый срок в первой строке метаданных;
- исполнитель;
- счетчики согласующих и наблюдателей;
- привязка к этапу или типу дела;
- теги;
- кнопки действий в нижней строке.

Карточка не должна превращаться в длинную анкету. Полная настройка открывается только при редактировании шаблона.

## Быстрые действия

Основные действия:

- "Применить" - открывает новую задачу с предварительно заполненными пустыми полями.
- "Открыть" - показывает детали шаблона без перехода в режим редактирования.
- "Изменить" - открывает форму редактирования.
- "Копировать" - создает новый шаблон на основе текущего.
- "Скрыть" или "Вернуть" - меняет активность шаблона.
- "Удалить" - доступно только если шаблон не используется или если backend поддерживает мягкое удаление.

Опасные действия требуют подтверждения.

## Состояния экрана

Нужно предусмотреть:

- загрузка списка;
- пустой список шаблонов;
- нет результатов по фильтрам;
- ошибка загрузки;
- нет прав на управление шаблонами;
- шаблон скрыт, но виден администратору;
- шаблон устарел из-за удаленного исполнителя или участника.

## Правила плотности и читаемости

- Использовать compact CRM-ритм: `p-3`, `gap-3`, `space-y-3`.
- Не использовать hero-блоки, большие декоративные карточки или маркетинговые описания.
- Кнопки действий делать компактными, с иконками и доступными `aria-label`.
- Фильтры должны переноситься по строкам без горизонтального переполнения.
- Текст в бейджах и кнопках не должен накладываться на соседние элементы.
- На desktop приоритет у плотной таблицы, на mobile - у коротких карточек.

## Definition of Done для списка

- Пользователь видит все ключевые поля шаблона без открытия карточки.
- Поиск и фильтры позволяют быстро найти шаблон.
- На desktop список работает как таблица, на mobile - как компактные карточки.
- Основные действия доступны из строки или карточки.
- Интерфейс повторяет существующие паттерны журнала задач и реестра дел.
