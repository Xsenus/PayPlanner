## Уже обнаруженные новые требования

- PAY-32: после опубликованного ответа заказчик указал расхождения с макетом — цвета, расположение, безрамочный текст и иконки; важна меньшая зрительная перегрузка. Сомнительное размещение блоков и кнопок нужно обсуждать до реализации. Идентификаторы сообщений: `1791960634844`, `1791960707329`, `1791960740864`, `1791960861752`, `1791960945696`, `1791961080486`.
- PAY-25 и PAY-23: новые сообщения прямо распространяют эти замечания PAY-32 на события и документы дела (`1791961014201`, `1791961090176`). Наличие таблицы/поиска не означает принятого дизайна.
- MAX, «СРМ — РАЗРАБОТКА»: бухгалтерский приоритет — нумерация счетов/актов по годам, отображение НДС и формы по КУБ, оперативные документы и расположение кнопок; права секретаря на просмотр счетов; остатки счетов и сверка денег в «Операционке». Текстовые источники и безопасные изображения приложены; дополнительные фотографии группы сверяются по отдельному каталогу.
- Визуальная сверка MAX: повторные ссылки одного счёта у клиента, расхождение полной суммы/оплат/графика в печати, служебный JSON в комментариях, сохранение акта/счёта и первичное/рассрочное обязательство. Исторические снимки подтверждают жалобу на свою дату; каждый сценарий нужно сопоставить с текущим исправлением, тестом и остатком, без автоматического объявления всех старых дефектов действующими.
- PAY-34/PAY-18: проверить прямое создание/обновление акта ограниченной ролью с чужим счётом, клиентом или договором. В просмотренном пути `ActsController` есть проверка действия и существования объектов, но доступность выбранного источника не установлена. При подтверждении исправить до расширения финансовых действий, используя текущие фильтры доступа. Синтетические данные, отсутствие записи/раскрытия при отказе, разрешённый акт без счёта и финансовая неизменность — обязательные критерии. [Код и конкретные тесты](yougile-sources/unified-2026-10-14/implementation-evidence.md).

Быстрый пакет — до рабочего дня при неизменном контракте, средний — несколько дней, длительный — несколько этапов. Это классификация сложности, а не обещание срока. Быстрый визуальный результат можно делать независимо от неразблокированного внешнего провайдера. Перед началом каждого пакета читать его основание/зависимости, сопоставлять current code и выполнять только оставшийся объём.

Для Codex и Claude одинаковые правила: один основной владелец каждого требования, собственные синтетические данные, обязательная безопасность локальной почты, обе формы задач при изменении их поведения, компактный UI и полный применимый gate перед окончательным выпуском. Не включать production flags, не выполнять backfill и не публиковать YouGile по одной отметке roadmap.

## Правила будущих заданий

Новая работа с YouGile в рамках этой сверки — только чтение. Авторизация MAX дана пользователем для изучения названных четырёх чатов; сообщения, реакции и изменения настроек не требуются.
