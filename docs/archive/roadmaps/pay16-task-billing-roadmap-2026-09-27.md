# PAY-16 — изменение учёта задачи и связь с ранее выставленным счётом

Источник: карточка PAY-16 компании PayPlanner, сообщение и скриншот от 25 сентября 2026 года. На скриншоте готовая платная задача с меткой «Не выставлен счёт»; заказчик просит изменить её на неоплачиваемую или внутреннюю, когда счёт больше не нужен, и привязать задачу к счёту, выписанному раньше без связи с задачей.

Прогресс: **5 из 5 пунктов завершены (100%)**.

- [x] Сверить текущие правила задач, счетов, прав и обеих карточек; зафиксировать безопасный сценарий изменения.
- [x] Дать уполномоченному редактору отдельное действие для изменения типа оплаты уже созданной задачи с записью в историю. Задача, связанная с действующим счётом, не может стать неоплачиваемой незаметно для учёта.
- [x] Дать пользователю с правом работы со счетами выбор ранее выставленного счёта того же контрагента; проверять тип, статус и связь с делом на сервере. Привязка сама по себе не меняет сумму и состав счёта, что нужно явно показать пользователю.
- [x] Добавить одинаковое действие в старую и новую карточки задачи, включая режим просмотра и настройку администратора, переключающую карточку.
- [x] Проверить разрешённые и запрещённые переходы, права, отменённые/чужие счета, историю, локальную БД, обе карточки и полные применимые тесты; после этого подготовить запись «Что нового» и черновик ответа PAY-16. Без отдельной команды ничего не публиковать в YouGile.

Итог локальной проверки: 3060 серверных и 1637 клиентских тестов прошли; линтер, типизация, аудит кодировки и production-сборка прошли. Серверные тесты используют изолированную тестовую БД; схема БД не менялась. На рабочий сервер PAY-16 ещё не установлена, приёмка на рабочих данных не проводилась.

Безопасное правило для уже включённой в действующий счёт задачи: сначала исправить или аннулировать счёт через предусмотренный финансовый сценарий. Простая смена метки задачи не должна скрывать выставленную клиенту сумму. Ранее реализованное возвращение задачи в очередь после полного аннулирования счёта сохраняется.
