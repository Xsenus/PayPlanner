## Поведение и границы

В `CompanyBankBindingsSection` внутри существующего банковского раздела сверка загружается по запросу, без автоматического запроса на каждое подключение. Выбираются отдельно банковский источник и полный строковый ID счёта профиля; даже единственный кандидат не выбирается автоматически. Одинаковые номера разных источников различаются по источнику; одинаковые названия профилей — по полному ID. Списки кандидатов общие для группы, вывод связей порциями по 20. Нет новых N+1 запросов, слияния ручных MoneyAccount или изменений истории.

Метаданные источника добавлены в существующий DTO из уже загруженных строк того же согласованного снимка и v2-версии. Ни одного дополнительного запроса или изменения модели/миграций; исходные реквизиты остаются в fingerprint. Ограничения полей ответа сохраняют предел JSON <200000 байт даже на максимальном наборе, избыточные исторические значения возвращают ограничение вместо огромного текста. UI не подставляет старый номер/БИК/валюту из прежнего списка по совпадающему ID.

Команда использует существующие API, диалог с AbortSignal и общий владелец операции. После подтверждения сервером выполняется новая сверка: toast успеха разрешён только при совпадении результата с выбранными ID, либо подтверждённом отсутствии отозванной связи. Неоднозначный результат не повторяет POST автоматически; нужен новый явный выбор. Отмена диалога не пишет, повторное чтение отменяет старый ответ. Компания, права, сеанс и несохранённый draft ограничивают lifetime. У делегированного редактора профиля банковский раздел не читает API. Архивный и бывший собственный профиль допускают чтение/отзыв без новой связи.
