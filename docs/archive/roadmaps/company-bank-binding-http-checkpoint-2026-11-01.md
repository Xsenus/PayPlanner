## Поведение и контракт

- GET `/api/bank-connections/{id}/profile-account-matches`: прежние кандидаты плюс CanBind и ActiveBindings. Последние содержат ID подтверждения, полный локальный ID, банковский ID, сохранённые номер/БИК/валюту и время. Это активные подтверждения всей компании выбранного подключения, не неограниченная история и не автоматическое разрешение нового документа.
- POST `/api/bank-connections/{id}/profile-account-bindings`: BankAccountId, ProfileAccountId, ExpectedVersion; возвращает BindingId, State, IsReplay. Нельзя передать владельца, автора, статус или произвольный снимок подтверждения.
- POST `/api/bank-connections/{id}/profile-account-bindings/{bindingId}/revoke`: ExpectedVersion; подтверждение должно принадлежать компании выбранного подключения. Чужой банковский/локальный ID или JSON-поле не создают полномочий.
- Обе команды используют прежние Serializable-границу, чистый tracker, блокировки пользователя/роли/реестра/компании/подключения, текущие одобрение, роль и AuthTokenVersion. Политика Admin и action filter сохранены. Повтор известного результата заново проверяет права. Отзыв старого подтверждения не снимает последующую связь.
- Bind по-прежнему требует активную собственную компанию и доступный явно выбранный источник с известной идентичностью. Revoke меняет только собственное типизированное подтверждение, поэтому разрешён и после архивирования/исключения из реестра. Для чтения бывшей собственной компании нужна серверная история подтверждений; похожий JSON не подходит.
- В режиме очистки CanBind=false, кандидаты/банковские/денежные строки не обходятся: возвращаются только ограниченные сохранённые подтверждения. Некорректный или чрезмерный старый список профиля не блокирует отзыв. Снимок версии включает статус и принадлежность компании. История и последний ID сохранены; удаления/реактивации нет.
- Формат ответов: 400 для неверного выбора/модели, 401/403 для отсутствия допуска, 404 для недоступных ID/профиля, 409 для устаревшей версии/блокировки/предела сверки. Чтения и команды no-store; отмена не маскируется успешным ответом. Токены подключения и авторизационные данные не возвращаются.

Ручные MoneyAccount не объединяются, номера/валюты/суммы/связи документов и банковская история не переписываются. Нет банковских запросов или синхронизации. Дополнительная проверка истории использует прежний индекс компании; история не материализуется. Ограничения отчёта и общий компактный набор кандидатов сохранены. Новый API пока не подключён к UI и не меняет печать ранее выданного документа.
