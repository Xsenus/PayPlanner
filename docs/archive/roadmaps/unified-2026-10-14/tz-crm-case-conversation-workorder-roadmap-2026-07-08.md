## Цель

Довести карточку дела до сценариев ТЗ по обсуждению в рамках дела и согласованию заказа клиентом.

## Рабочие пункты

- `[x]` Проверить текущую переписку дела: модель сообщений, права, уведомления, история, связь с пользователями. Итог аудита сохранен в `docs/case-conversation-current-state-2026-07-08.md`, права и видимость закреплены backend-тестом.
- `[x]` Добавить вложения к сообщениям переписки, если текущая модель хранит только текстовые записи. Сообщение можно отправить с файлами из вкладки "Переписка"; API принимает multipart-запрос и возвращает вложения в ленте.
- `[x]` Связать вложения переписки с документами дела без дублей и с понятным источником файла. Файлы сохраняются как документы дела с типом "Переписка" и скачиваются из ленты по id документа.
- `[x]` Добавить уведомления участникам дела о новом сообщении и вложении. Ответственные участники дела получают уведомления типа "Переписка дела"; автор сообщения не получает уведомление самому себе.
- `[x]` Добавить frontend-тесты переписки: отправка сообщения, вложение, ошибка загрузки, права доступа. Покрыты отправка текста, отправка вложения, ошибка загрузки файла и режим просмотра без права редактирования.
- `[x]` Способ клиентского согласования утверждён и реализован: одноразовая ссылка из email, шестизначный OTP и дополнительная безопасная доставка ссылки через MAX при наличии подтверждённой привязки.
- `[x]` Состав внешних данных утверждён: организация, клиент, дело, версия, услуги, количество, цена, итог, сроки и только явно выбранные документы; внутренние заметки, себестоимость и исполнители исключены.
- `[x]` Реализован внешний сценарий согласования неизменяемой версии заказ-наряда с возвратом замечаний и безопасным выключателем.
- `[x]` Решение записывается в историю дела и предлагает создание счёта, договора или акта без автоматического дублирования.
- `[x]` Аудит хранит подтверждённый контакт, канал, версию, решение, время, hash IP и user agent без открытого токена.
- `[x]` Права переписки и публичного согласования проверены прямыми API/service-тестами, включая чужое дело, перебор, повтор решения и отозванную ссылку.
- `[acceptance]` Проверить согласование на реальном сценарии клиента заказчика.
- `[x]` Для клиента без аккаунта CRM создана отдельная модель безопасности: token hash, OTP, immutable snapshot, узкий публичный DTO, rate limit и короткоживущие grants вложений.

## Definition of Done

- Переписка по делу хранит текст, вложения и историю без потери прав доступа.
- Заказ-наряд можно согласовать выбранным заказчиком способом, а результат виден в карточке дела.
- Roadmap перенесен в архив после приемки переписки и клиентского согласования.

## История

- 2026-08-05: защищённые действия внешнего согласования получили прямые controller-тесты чтения статуса, создания и отзыва. Проверки права операции и видимости дела используют один снимок доступа в рамках запроса; сценарий чтения статуса закреплён двумя SQL-командами без повторного чтения роли. Трансляция снимка проверена на чистой PostgreSQL-БД. Статус roadmap не изменён: для закрытия по-прежнему нужна ручная приёмка на реальном клиентском контакте.
- 2026-07-31: координационный roadmap синхронизирован с завершённым внешним согласованием: приняты email magic link + OTP, ограниченный состав данных и отдельная публичная модель безопасности; история, аудит, API-права и предложения финансовых документов реализованы и проверены. Остаётся только ручная приёмка на реальном клиентском контакте. Закрыто 12 из 13 пунктов, прогресс 92%.
- 2026-07-08: закрыт аудит текущей переписки дела. Подтверждено, что текущая переписка собирается из истории дела, работает только с текстом, требует `CanView` для чтения и `CanEdit` для отправки, а также применяет видимость дел. Добавлен backend-тест прав и видимости; следующий технический шаг - отдельная модель сообщений для вложений и уведомлений.
- 2026-07-08: добавлены вложения к сообщениям переписки. Файлы сохраняются как документы дела с типом "Переписка", возвращаются в ленте сообщения и скачиваются через существующий документный endpoint; добавлены backend- и frontend-тесты основного сценария.
- 2026-07-08: добавлены уведомления участникам дела о новых сообщениях переписки и сообщениях с вложениями; получатели проверяются по правам просмотра и видимости дела.
- 2026-07-08: закрыты frontend-тесты переписки: отправка текста, вложения, ошибка загрузки и read-only режим. Вкладка переписки больше не показывает форму отправки пользователю без права редактирования.
- 2026-07-08: задачи клиентского согласования заказ-наряда отмечены заблокированными до выбора способа согласования, состава данных для клиента и канала подтверждения.
