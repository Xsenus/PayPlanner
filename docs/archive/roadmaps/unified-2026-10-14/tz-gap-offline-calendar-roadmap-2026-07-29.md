## Цель

Обеспечить предсказуемый календарь при нестабильном интернете: просмотр ранее загруженных событий и, если утверждено, безопасное создание/изменение с последующей синхронизацией.

## Текущее состояние

- `[x]` Есть service worker для Web Push.
- `[x]` Интерфейс календаря адаптивен и синхронизируется с API онлайн.
- Кэш приложения, IndexedDB-модель, очередь изменений и разрешение offline-конфликтов отсутствуют.

## Решения заказчика

- `[x]` Выбран первый уровень: только просмотр, без локального создания, редактирования и удаления.
- `[x]` Утверждено хранение снимка до 7 дней, не более 1000 событий и 10 МБ.
- `[x]` На обычном устройстве сохраняются даты и нейтральные подписи; названия задач и исполнителей доступны только после явного включения режима доверенного устройства.

## Этап 1. Архитектура PWA

- `[x]` Отделить push worker от versioned application cache без конфликта scope.
- `[x]` Добавить manifest, installability и стратегию обновления версии.
- `[x]` Кэшировать только статические assets и безопасный app shell.
- `[x]` Создать IndexedDB schema для минимальных calendar DTO и sync metadata; outbox намеренно отсутствует в read-only уровне.
- `[x]` Версионировать локальную схему; версия 1 не содержит очереди изменений и допускает безопасную замену снимка.
- `[x]` Минимизировать локальные данные: не сохранять клиентов, дела, описания, результаты, комментарии, документы, участников, напоминания, каналы и платёжные сведения.

## Этап 2. Офлайн-чтение

- `[x]` Сохранять до 1000 ближайших по сроку событий после успешной загрузки календаря или недельной нагрузки.
- `[x]` Показывать время последней синхронизации, срок действия и явный offline badge.
- `[x]` Не выдавать старые данные за актуальные: снимок действует 7 дней, после истечения удаляется и не открывается.
- `[x]` Очищать кэш при logout, истечении сессии и смене пользователя; выключенный feature flag удаляет рабочий снимок.
- `[x]` Не кэшировать документы, комментарии и персональные карточки без отдельного решения.

## Этап 3. Офлайн-изменения

- `[x]` Не создавать client-generated id и outbox-команды в утверждённом read-only уровне.
- `[x]` Запретить create/update/move/duration/delete при работе со снимком.
- `[x]` Не хранить base version/etag, поскольку локальных изменений нет.
- `[x]` Не запускать retry/backoff и фоновую отправку: очередь в read-only уровне отсутствует.
- `[x]` После logout или смены пользователя удалять весь локальный снимок и настройки доверия прежнего пользователя.
- `[x]` Не показывать экран зависших изменений: система гарантирует, что такие изменения не создаются.

## Этап 4. Конфликты

- `[x]` Не применять server-wins/client-wins/manual: локальная версия неизменяема.
- `[x]` Показывать пользователю только время сохранения снимка и явно отделять его от актуальных серверных данных.
- `[x]` Не менять согласование, статус или участников из офлайн-снимка.
- `[x]` Не создавать локальные переносы, поэтому после восстановления сети нет неподтверждённых пересечений.
- `[x]` Не передавать данные снимка во внешние календари.

## Производительность и безопасность

- Ограничить диапазон, число событий и размер записи; не хранить полные задачи.
- Синхронизировать дельту по cursor/version, а не перечитывать весь журнал.
- Избегать фонового spin/retry при отсутствии сети.
- Учитывать общие и чужие компьютеры: короткий TTL и remote wipe/revocation.

## Проверки

- `[x]` Unit-тесты IndexedDB: минимизация, TTL, лимит 1000 событий, доверенное устройство, изоляция пользователей и полная очистка.
- `[x]` UI-тест online→ошибка API→read-only snapshot; сценарий edit исключён утверждённой моделью.
- `[x]` Тест обновления versioned service worker без очереди изменений.
- `[x]` Тест logout/смены пользователя и очистки снимка; удалённые на сервере задачи исчезают при следующей успешной замене снимка.
- `[x]` Production build и PWA-ограничения проверены автоматически; физические устройства вынесены в ручную приёмку ниже.
- `[acceptance]` Проверить ноутбук и телефон при полном отключении сети.
- `[acceptance]` Подтвердить понятность конфликтов и отсутствие потери изменений.

## Rollout и Definition of Done

- Сначала read-only offline, затем черновики, затем редактирование.
- Каждый уровень включать отдельным feature flag.
- Готовность: нет утечки между пользователями, очередь идемпотентна, конфликты не теряют данные, обновление PWA безопасно, тесты и production smoke успешны.

## История

- 2026-07-30: подготовлена безопасная PWA-основа без локального хранения рабочих данных. Один корневой service worker обслуживает прежний Web Push, но push и versioned app-cache разделены на независимые модули без конфликта scope. Добавлены manifest и installability, очистка старых версий app-cache, сетевой приоритет для навигации с офлайн-fallback на app shell и cache-first только для сборочных файлов `/assets/`. API, документы, комментарии, карточки, запросы записи и внешние адреса worker не перехватывает. Целевые тесты, lint и production build прошли. Остальные 23 технических пункта явно заблокированы до выбора уровня офлайн-режима, срока/объёма хранения и допустимости локальных названий дел и задач. Закрыто 6 из 34 пунктов, прогресс 18%.
- 2026-07-31: реализован утверждённый read-only уровень. Календарь и недельная нагрузка сохраняют в IndexedDB минимальный снимок до 7 дней, 1000 событий и 10 МБ. По умолчанию данные обезличены; реальные названия включаются только пользователем на доверенном устройстве. При сбое API интерфейс показывает дату снимка и блокирует создание, перенос, изменение длительности, согласование и завершение. Кэш очищается при выходе, истечении сессии, смене пользователя и выключении feature flag. Добавлены unit/UI-тесты и production build. Закрыто 32 из 34 пунктов, прогресс 94%; остаётся ручная приёмка на реальных ноутбуке и телефоне.
