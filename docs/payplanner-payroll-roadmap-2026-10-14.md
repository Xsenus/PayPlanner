# PAY-2 — зарплата и расчёт по работе

Блок [единого плана](payplanner-unified-roadmap-2026-10-14.md). **Прогресс: 0/4 (0%)**: всего 4 пакетов, завершено 0, в работе 0, не начато 2, заблокировано 0, решений 1, приёмки 1. Процент относится к полному объёму блока, не к готовности всей CRM.

## Основание и сохранённая реализация

Карточка PAY-2 не содержит законченного ТЗ, но [MAX-переписка](yougile-sources/unified-2026-10-14/max-requirements-audit.md) задаёт учёт работы/условий оплаты сотрудников. Пустая карточка не удаляется из плана и не считается готовой.

Точное условие MAX 29 мая 22:49: платёж исполнителю создаётся после принятия работы. Это связь результата и планового расхода, а не утверждённая формула всей зарплаты. Примеры оклада/процентов ниже — варианты для решения владельца, не найденные в карточке готовые ставки.

Не подтверждён законченный модуль зарплаты с утверждёнными расчётами. Существующие сотрудники, роли, задачи/услуги/тарифы, денежные операции и отчёты — основы для повторного использования. Сумма счета клиенту не равна зарплате юриста, оплаченный клиентом акт не равен начислению сотруднику.

## Приоритет и зависимости

SAL-01 прежде кода расчёта. C0 экран/эталонные примеры возможны независимо, реальные базы/начисления не нужны для подготовки. Не ставить весь PAY-2 в быстрые интерфейсные задачи.

## Подробные пакеты

### SAL-01 — Условия начисления и роли

- [decision] Условия начисления и роли.

**Нужно согласовать:** фиксированная/почасовая/процентная часть, основание выполненной работы, принятие результата, период, аванс/удержание/премия/отмена/расходы, валюта/округление, разные юристы/соисполнители, выплаты и отчёт. Отдельно налоговый/кадровый контур и допустимость его автоматизации. **Доступ/размер:** бизнес-решение, C0 примеры, длительный. **DoD:** полная матрица исходных MAX-условий и синтетические эталоны, права самого сотрудника/руководителя/бухгалтера; не угадывать формулу по названию карточки.

### SAL-02 — Начисления и неизменяемое основание

- [ ] Начисления и неизменяемое основание.

**FE:** компактный журнал сотрудника/периода, расшифровка источника/тарифа/суммы. **BE:** существующие данные работы, frozen тариф/условия и уникальность основания, расчёт не делает вторую клиентскую оплату; корректировки отдельным событием. **Доступ/размер:** C1 после SAL-01, длительный. **DoD:** один результат/несколько исполнителей/возврат на доработку/повтор/смена тарифа/закрытый период и две транзакции, exact decimal, чужие персональные начисления недоступны.

### SAL-03 — Выплата и связь с денежным/налоговым учётом

- [ ] Выплата и связь с денежным/налоговым учётом.

**FE:** начислено/аванс/удержано/выплачено/остаток отдельно, подтверждение и первичка. **BE:** существующая денежная операция, связь с начислением и TAX по согласованным правилам; не отправлять банковский платёж автоматически. **Доступ/размер:** C1, длительный. **DoD:** частичная/полная/отменённая выплата, два сотрудника/компании, нет двойной записи расходов, доступ/история/экспорт и переплата видны.

### SAL-04 — Приёмка расчёта сотрудником и бухгалтером

- [acceptance] Приёмка расчёта сотрудником и бухгалтером.

**Доступ:** C2 с согласованным безопасным периодом. **DoD:** эталон начислений и выплаты по нескольким условиям совпадает, права/коррекции/история подтверждены; размер клиентского счёта не подменяет заработок. До согласования формул задача не объявляется закрытой.


## Доступ, проверки и закрытие

C0 — исходники, безопасные макеты и mock API, без БД/VPS; подходит Claude Code без системного доступа. C1 — отдельные синтетические SQLite/PostgreSQL и локальный API, без рабочих секретов; также доступно Claude Code при предоставленной среде. C2 — VPS, внешний sandbox или реальные роли/бухгалтер: окончательная приёмка, не условие для независимой локальной части. Быстрый пакет — до рабочего дня при сохранённом контракте; средний — несколько дней; длительный — несколько связанных этапов/интеграция. Оценка не является обещанием срока.

В финансовом коде проверять сумму/точность/валюту, успех и отказ, прямой запрос ограниченной роли, чужую компанию, повтор/потерянный ответ, две параллельные транзакции, rollback и сохранность истории. Схема меняется только additive-путём с парными миграциями и clean/upgrade проверками. Использовать существующие модальные окна, права, уведомления и managed storage; не создавать второй денежный источник. Во время разработки адресные тесты, перед окончательным push полный применимый gate затронутых областей. Local backend явно: `BackgroundServices__Enabled=false`, `Email__Enabled=false`; SMTP/очереди из копии production отдельно отключены. Реальные деньги и внешние сообщения не используются как тестовый инструмент.

Закрытие `[x]`: весь указанный объём, применимые тесты/кодировка/данные и доказательство. Частичный механизм не закрывает весь пакет. Релизные заметки — пользовательским языком и общим форматом, согласованным ранее. YouGile: только локальный черновик по существенному изменению; публикация/перемещение после отдельной команды на конкретные карточки. После полной приёмки блока архивировать его отдельно.

## Сохранённая оплата привлечённому исполнителю

В обеих формах TaskJournal уже есть contractorPaymentOnResult и задержка после результата (0–365 дней, значение по умолчанию 5). TasksController для оплаты по результату требует статус done и рассчитывает дату от перехода в завершённое состояние с часовым поясом исполнителя; существующий оплаченный/Completed платёж не перезаписывается. Profile/Users показывают ожидание результата. Это действующая основа планового расхода, не весь модуль зарплаты. SAL-01 уточняет условие «после принятия работы» отдельно от простой отметки done; SAL-02/03 сохраняют существующие деньги, stable task marker и неизменность оплаченного. Источник 8 сентября требует штатных/внештатных, отчётов и ведомостей, но обещанная методика ещё не представлена как утверждённая формула.
