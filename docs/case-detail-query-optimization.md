# Запросы карточки и связанных блоков дела

Дата проверки: 5 августа 2026 года.

## Проверенный контур

Проверены защищённые маршруты полной карточки, компактной сводки, финансов,
участников судебного процесса, хронологии и внутренней переписки:

- `GET /api/v2/cases/{id}`;
- `GET /api/v2/cases/{id}/summary`;
- `GET /api/v2/cases/{id}/finance`;
- `GET /api/v2/cases/{id}/court-parties`;
- `GET /api/v2/cases/{id}/timeline`;
- `GET /api/v2/cases/{id}/conversation`.

Для каждого маршрута сначала подтверждаются активный пользователь, роль, право
раздела и область видимости. Admin-claim из старого токена сам по себе не даёт
доступа. Право просмотра финансов также проверяется по актуальной роли в БД.

## Устранённые повторные запросы

### Права

Обычная проверка права раздела ранее последовательно читала пользователя, строку
права и, при её отсутствии, наличие других прав роли. Теперь существующий
пользователь, роль, нужная строка права и признак legacy-роли читаются одной
SQL-командой. Исторические значения по умолчанию для роли без настроек сохранены.

Полная карточка использует уже загруженное право раздела «Дела» для решения,
можно ли показывать контактные данные. Повторные запросы к `Users` и
`RolePermissions` для той же операции исключены. Результат права на финансы
кэшируется только на время текущего HTTP-запроса.

### Участники судебного процесса

Проверка видимости дела и выборка участников объединены. Проекция начинается с
видимого дела и возвращает его упорядоченную коллекцию участников, поэтому пустой
список существующего дела по-прежнему отличается от ответа `404`, но отдельный
`Any` больше не выполняется.

### История и переписка

Timeline и переписка выбирают только идентификатор дела, строку истории и
настройку часового пояса пользователя. Часовой пояс входит в ту же SQL-команду
скалярным подзапросом. Полная сущность дела и отдельный запрос к `UserSettings`
не загружаются. Метаданные вложений переписки выбираются одной дополнительной
пакетной командой только при наличии ссылок на документы.

### Сводка и финансы

Компактная сводка выбирает только поля, которые реально присутствуют в ответе:
идентификаторы, название, номер, статус, приоритет, стадию, сроки, ответственного,
владельца, стоимость и отметку просмотра. Описание, стратегия, реквизиты суда и
прочие поля полной карточки в этот запрос не входят.

Финансовый маршрут также получает только название дела, стоимость и имя владельца.
Договоры, связанные через счета и платежи, объединяются `UNION ALL` в одной
SQL-команде, а словарь в памяти устраняет повтор одного договора. Платежи остаются
ограничены конкретным делом и отфильтрованы по действующим правилам видимости.

## Зафиксированные бюджеты SQL

Количество не зависит от числа участников, записей истории или договоров:

| Сценарий | SQL-команд |
| --- | ---: |
| Полная карточка без платежей | 5 |
| Компактная сводка без платежей | 5 |
| Участники процесса | 2 |
| Хронология | 2 |
| Переписка без вложений | 2 |
| Переписка с вложениями | 3 |
| Финансовый блок с договорами по счёту и платежу | 6 |

Полная карточка намеренно сохраняет расширенную проекцию, потому что используется
для редактирования всех полей. Сводка, история и финансы используют отдельные
компактные проекции и не подменяют контракт полной карточки.

## Автоматические проверки

- SQLite-тесты фиксируют права, ответы, скрытие финансов и контактных данных,
  бюджеты SQL и отсутствие лишних полей в компактных проекциях;
- отдельный тест создаёт чистую PostgreSQL-БД, применяет все миграции, проверяет
  перевод проекций участников, истории и сводки, а также `UNION ALL` договоров;
- после теста временная PostgreSQL-БД удаляется и соединения освобождаются;
- профильные наборы контроллера дел и матрицы прав проходят полностью.
- полный backend-набор содержит 2621 успешный сценарий; frontend-наборы содержат
  1261 unit- и 286 integration-тестов, production-сборка проходит без ошибок.
