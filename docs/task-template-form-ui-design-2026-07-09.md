# UI формы шаблона задачи

Дата фиксации: 9 июля 2026.
Статус: проект интерфейса для реализации roadmap 4.

## Цель формы

Форма создания и редактирования шаблона должна быть похожа на карточку задачи, но не копировать ее полностью. Пользователь настраивает повторяемые правила будущей задачи: что заполнить, кого добавить, какие уведомления поставить и к какому сценарию дела привязать шаблон.

Главное требование: выбор согласующих и наблюдателей должен работать так же, как в обычной задаче, включая множественный выбор, видимый список выбранных пользователей и удаление без сброса остальных участников.

## Режимы формы

Форма должна поддерживать три режима:

- создание нового шаблона;
- редактирование существующего шаблона;
- копирование шаблона с новым названием.

Для просмотра без редактирования можно использовать ту же форму в read-only режиме или отдельную компактную панель деталей.

## Структура формы

Форма делится на компактные секции:

- основные данные;
- срок и приоритет;
- участники;
- уведомления;
- привязка к сценарию;
- предпросмотр применения.

Каждая секция должна быть раскрыта по умолчанию в desktop-режиме. На маленьких экранах допускается вертикальная прокрутка, но без вложенных карточек внутри карточек.

## Основные данные

Поля:

- название шаблона;
- описание задачи;
- тип задачи;
- теги;
- активность шаблона.

Правила:

- название обязательно;
- описание может быть пустым, но форма должна явно показывать, что тогда задача создастся без описания;
- теги вводятся так же, как в задаче, чтобы не появлялись разные форматы.

## Срок и приоритет

Поля:

- приоритет;
- плановый срок;
- единица срока: минуты, часы, дни;
- базовая дата: дата создания задачи, дата перехода этапа дела или выбранная пользователем дата;
- время по умолчанию, если срок считается в днях.

Правила:

- срок должен сохраняться как правило, а не как конкретная дата;
- если шаблон применяется вручную, система рассчитывает дату от момента применения;
- если шаблон применяется из дела, система рассчитывает дату от события дела.

## Участники

Поля:

- исполнитель по умолчанию;
- согласующие;
- наблюдатели.

Правила:

- для согласующих и наблюдателей использовать тот же подход, что в карточке задачи;
- после выбора пользователь сразу видит выбранного человека под кнопкой или select;
- можно выбрать несколько согласующих и несколько наблюдателей;
- удаление одного участника не удаляет остальных;
- повторный выбор уже добавленного пользователя блокируется или игнорируется без дубля;
- основной исполнитель не должен дублироваться как дополнительный участник без явного правила;
- порядок согласующих сохраняется, потому что он влияет на согласование задачи.

## Уведомления

Поля:

- каналы уведомлений;
- напоминания;
- признак "важный шаблон", если будущая задача должна создавать заметное уведомление.

Правила:

- значения по умолчанию можно брать из настроек задач;
- пользователь должен видеть, какие уведомления попадут в задачу;
- отключение уведомлений в настройках задач не должно ломать сам шаблон.

## Привязка к сценарию

Поля:

- тип привязки: без привязки, этап дела, тип дела;
- выбранный этап или тип дела;
- режим применения: вручную или предлагать при событии;
- подсказка для пользователя при применении из дела.

Правила:

- шаблон без привязки доступен в общем списке;
- шаблон с этапом дела должен появляться в подсказках этапа;
- шаблон с типом дела фильтруется по выбранному делу;
- привязка не должна мешать применить шаблон вручную, если права позволяют.

## Предпросмотр применения

Форма должна показывать короткий предпросмотр:

- какие поля будут заполнены;
- какой срок получится при применении сегодня;
- кто будет исполнителем, согласующим и наблюдателем;
- какие поля не заполнены и останутся ручными.

Предпросмотр нужен, чтобы пользователь понимал эффект шаблона до сохранения.

## Сохранение

Кнопки:

- сохранить;
- сохранить и применить;
- отменить;
- удалить или скрыть для существующего шаблона.

Правила:

- при изменении активного шаблона существующие задачи не меняются;
- при скрытии шаблон исчезает из выбора, но остается доступен администратору;
- удаление требует подтверждения и зависит от backend-правил хранения.

## Definition of Done для формы

- Форма покрывает все обязательные поля из состава шаблона.
- Согласующие и наблюдатели выбираются, отображаются и удаляются так же надежно, как в карточке задачи.
- Пользователь видит предпросмотр будущей задачи.
- Режимы создания, редактирования и копирования различаются понятными заголовками и действиями.
- Форма остается компактной и не выбивается из плотного CRM-стиля.
