# PAY-8/PAY-9 — исходники телефонии

Карточки различаются: PAY-8 — события и звонки АТС, PAY-9 — телефонная книга. Прежнее решение не подключать их сохраняется; новая сверка и постановка плана не включают реальную телефонию.

## Источники

- PAY-8, сообщение `1790229624064`: владелец перечислил 11 возможностей — история/записи, всплывающая карточка, распределение входящих, click-to-call, сделки/контакты по звонкам, задача пропущенного, встроенные звонки с гарнитурой, «Неразобранное», несколько воронок. Это полный объём запроса, а не только один callback.
- [Указанная статья onlinePBX](https://onlinepbx.evateam.ru/docs/docs/DOC-000104#amo-cz-rm-amo-crm-kommo), `1790229638993`: прочитана в браузере целиком, включая настройки, исключения «Неразобранного», web-клиент, ручную догрузку и диагностику. Она описывает готовую интеграцию amoCRM/Kommo, а не контракт PayPlanner. Для реализации нужны официальный API, сопоставление сотрудников/внешних номеров и явно выбранные правила создания сущностей. Поведение и задержки старого виджета не становятся автоматически правилами новой CRM.
- [PDF аппарата](https://items-attachments.s1.citilink.ru/1428155/61e9139cbc8cb.pdf), `1790229695000`: оригинал получен, SHA256 `8edba910124881e96d6ac2399c2438389dd12d9645e26280213229c2f38c52ee`, восемь страниц просмотрены визуально (PDF сканированный, текст не извлекается). Это краткое руководство **Yealink SIP-T30/SIP-T30P**, версия ПО **124.85.0.1 и выше**. Оно объясняет устройство/настройку SIP/обычные звонки и локальную записную книгу; не подтверждает точный формат серверной remote XML-книги или текущую прошивку аппарата. Проверить реальную модель/прошивку перед пилотом, не менять SIP-настройки в подготовке.
- PAY-9, `1790229135020`: просмотрен экран «Удалённая записная книга», URL и включённые удалённые имена, период обновления **3600 секунд**. Снимок содержит пароль внутри старого URL: оригинал хранится вне Git, сам URL и учётные данные не копируются в план/ответ. Период чтения телефоном не равен частоте публикации CRM; оба параметра согласуются отдельно.
- MAX, владелец, 6 апреля: просмотрены список прежних файлов с `RemotePhonebook.xml` и расположение contacts/report/webhooks/widgets. Это контекст существующей системы, не разрешение переносить секреты.

## Что уже есть в PayPlanner

`ContactsController.DownloadYealinkXml` проверяет экспорт и область видимости; строит UTF-8 XML, исключает повтор связанных клиентских контактов. `GetYealinkRemotePhonebook` — отдельный rate-limited путь с секретным конфигурационным токеном; без него ответ не открывается. Выбираются активные физические контакты с разрешением синхронизации и телефонами, отдельная группа «КОНТАКТЫ». Есть import/dry-run/решения строк и preview. `RemoteYealinkPhonebook_RequiresTokenAndExportsPeopleOnly` и `DownloadYealinkXml_ExportsOnlyVisibleContacts_ForUserWithExportPermission` — конкретные существующие проверки. Это не доказательство обновления файла на REG.RU или чтения реальным аппаратом.

Следующий пакет должен повторно использовать экспорт, а не писать второй справочник. Проверить защиту URL в логах/диагностике, предел числа контактов/байтов и своевременное исключение отозванной записи. Выбор публикации файла или существующего защищённого endpoint — отдельное решение; исходную книгу и рабочую АТС не менять без утверждённого пилота.
