## Конфликты и уточнения, которые нельзя терять

1. Примеры процессуальных сроков требуют утверждённых правил по виду производства и основанию отсчёта. Не распространять один пример на все дела.
2. Долг по договору и долг по счетам — разные показатели. ТЗ использует оба; финальный интерфейс должен объяснять основание каждого.
3. Последний согласующий по раннему ТЗ автоматически завершает задачу; позднее заказчик попросил выбор между завершением и возвращением исполнителю. Сохранить позднее правило и проверить обе формы.
4. ТЗ упоминает автоматическое закрытие задач при закрытии дела; PAY-31 требует предварительных проверок. Запретить молчаливую потерю незавершённой работы, определить окончательный маршрут.
5. Рабочая неделя пн–пт в виде календаря не равна производственному календарю для расчёта срока и рабочей нагрузки.
6. Не путать отсутствие задач, отсутствие просмотра и отсутствие новых действий. Для каждого механизма нужны отдельные условия, переключатели и доказательства.

Дальше каждой строке MAX-TZ-01…33 назначается пункт единого плана или подтверждённое доказательство закрытия. Только после этого можно архивировать старые активные roadmap.
