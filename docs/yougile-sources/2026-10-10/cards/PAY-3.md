## Описание из полного снимка 9 октября

ТЗ: Раздел «Судебные дела»
Назначение
Раздел предназначен для автоматизированного учёта, мониторинга и ведения судебных дел компании. Обеспечивает синхронизацию с внешними судебными источниками (КАД Арбитр, ГАС «Правосудие», ФССП), автосоздание задач по процессуальным событиям, контроль сроков и уведомление ответственных.

Алгоритм синхронизации
text
1. Инициализация дела
   ├── Юрист добавляет дело по номеру (А40-12345/2025) или ИНН контрагента
   ├── Система ищет дело в КАД / ГАС «Правосудие»
   ├── Найденная карточка импортируется в систему (поля, участники, движение)
   └── Дело ставится на мониторинг (подписка на обновления)

2. Периодический опрос (cron / sheduler)
   ├── Раз в 1–3 часа: запрос актуального состояния по активным делам
   ├── Раз в сутки (ночью): полный обход всех отслеживаемых дел
   ├── Сравнение хэша последнего состояния с сохранённым
   └── Если есть изменения → обработка дельты (см. п. 3)

3. Обработка изменений (дельта)
   ├── Новое событие в движении дела → создание системного события + задача
   ├── Новый документ (судебный акт) → скачивание, распознавание, прикрепление
   ├── Смена статуса дела → обновление статуса в карточке
   ├── Новое заседание назначено → создание события в календаре + задача
   ├── Перенос заседания → обновление даты, уведомление
   ├── Подача апелляции / кассации → создание новой стадии дела
   └── Исполнительное производство (ФССП) → связывание с делом + задача

4. Завершение мониторинга
   ├── Статус «Рассмотрение дела завершено» + 10 дней без изменений → снимаем с активного опроса
   └── Архивируем, но сохраняем историю

Важные ограничения синхронизации
Арбитражные суды публикуют акты на следующий день после принятия; суды общей юрисдикции — в срок до одного месяца.
Событие (заседание назначено) может появиться раньше документа (текст акта) — система должна разделять три состояния: событие → статус → документ.
Часть актов не публикуется вовсе (предусмотрено законом) — статус дела обновляется по событию, а не по документу.

6. Действия исполнителя (юриста)
6.1. При получении нового дела
Открыть карточку дела → изучить исковые требования, стороны, сумму, дату заседания.
Проверить реквизиты → сверить данные из КАД / ГАС с внутренними данными (ИНН, договоры).
Определить стратегию → заполнить поле «Позиция по делу» в карточке (текст + выбор из шаблонов).
Привязать договор → связать дело с внутренним договором / контрагентом для отчётности.
6.2. При назначении заседания
Проверить готовность документов → отметка в задаче «Документы подготовлены».
Запросить полномочия → если требуется доверенность на участие → задача на оформление.
Подготовить процессуальные документы → отзыв, ходатайства, доказательства (через шаблоны системы).
Запланировать поездку → если суд в другом городе → задача на командировку.
6.3. После заседания
Заполнить результат → в карточке дела: «Результат заседания» (отложено / рассмотрено по существу / принято промежуточное решение).
Прикрепить документы → загрузить полученные в заседании документы (протокол, определения).
Обновить позицию → при необходимости скорректировать стратегию, добавить комментарий.
Проверить следующую дату → подтвердить дату следующего заседания (или ждать синхронизацию).
6.4. После вынесения решения
Изучить текст решения → скачать из системы (документ уже импортирован при синхронизации).
Принять решение об обжаловании → в карточке выбрать: «Обжаловать» / «Не обжаловать» / «Согласовать с руководителем».
При обжаловании → создать задачу «Подготовить апелляционную жалобу», дедлайн — за 7 дней до истечения срока.
При согласии → сменить статус дела, создать задачу на получение исполнительного листа.
6.5. На стадии исполнения
Получить исполнительный лист → отметка в карточке, загрузка скана.
Подать в ФССП / банк → создать задачу, отслеживать статус через синхронизацию с ФССП.
Контролировать взыскание → периодически проверять статус ИП, фиксировать частичные погашения.
Закрыть дело → при полном исполнении или невозможности взыскания → статус «Завершено», формируется отчёт.

9. Технические требования
Синхронизация: фоновый worker (Celery / Hangfire / Quartz), очередь задач по приоритету (новые дела — сразу, активные — раз в 1–3 часа, архивные — раз в сутки).
API-агрегатор: подключение через единый шлюз (Юрайт API или собственный адаптер к КАД + ГАС + ФССП). you-right.ru +1
Хранение документов: S3-совместимое хранилище, распознавание через OCR (Tesseract / Yandex Vision), индексация полнотекстового поиска.
Персональные данные: система является оператором ПДн (152-ФЗ) — ограничение доступа, журналирование, маскирование при выгрузке.
Производительность: синхронизация 1000 активных дел — не более 30 минут, карточка дела открывается за ≤ 1 секунду.
