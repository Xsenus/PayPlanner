## word/document.xml
СПЕЦИФИКАЦИЯ: МОДУЛЬ «ДОКУМЕНТЫ КОМПАНИИ» В CRM
Назначение: описание структуры и логики документов (счёт, акт, счёт-фактура, УПД, ТОРГ-12, договор и производные) для разработки. Аналог функционала сервиса КУБ24.Без избыточных описаний — только данные, поля, статусы, правила и связи.
Версия 1.0. Основание: функционал КУБ24 (счета, акты, накладные, счёт-фактуры, УПД «в один клик» на основании счёта), нормы 402-ФЗ, ст. 168–169 НК РФ, Постановление Правительства № 1137, формат УПД 5.03.

1.2. Ключевой принцип (как в КУБ24)
Каждый документ типа ACT / SF / UPD / TN создаётся НА ОСНОВАНИИ счёта: данные счёта (позиции, суммы, НДС, реквизиты сторон) копируются в новый документ автоматически.
Счёт → производный документ — жёсткая связь «основание → производный». При изменении счёта, если производный документ уже существует, система показывает предупреждение.
Один клик: кнопки «Создать акт», «Создать УПД», «Создать накладную», «Создать счёт-фактуру» в карточке счёта.
Снимок реквизитов: в момент сохранения документа фиксируется копия реквизитов компании и клиента (реквизиты могли измениться в профиле — документ остаётся неизменным).

2. Счёт (INVOICE)
2.1. Структура печатной формы
Шапка: логотип, «СЧЁТ № [номер] от [дата]».
Продавец: ОПФ + наименование, адрес, ИНН/КПП (для ИП — ОГРНИП с 2026), банковские реквизиты (счёт, банк, БИК, корсчёт).
Покупатель: юрлицо — наименование, адрес, ИНН/КПП; физлицо — ФИО, адрес.
Таблица позиций: № | Наименование | Ед. изм. | Кол-во | Цена | НДС (вариант: в т.ч. / сверху / без налога) | Сумма.
Итоги: сумма НДС, Итого, «Всего к оплате», сумма прописью (автоформирование).
Подпись и печать — по чекбоксу настроек профиля.
2.2. Логика расчётов
vat_mode = included: сумма позиции включает НДС; НДС = сумма × ставка / (100 + ставка).
vat_mode = added: НДС = сумма × ставка / 100; total = сумма + НДС.
vat_mode = none: в печатной форме строка НДС = «Без налога (НДС)».
Округление: до копеек, построчно; итоги — сумма строк.

2.4. Автоматика
Автонумерация по схеме (см. раздел 9).
Автоподстановка реквизитов по ИНН (ЕГРЮЛ/ЕГРИП) и банка по БИК.
Повторяющиеся счета: шаблон с расписанием (ежемесячно) — автосоздание и автосохранение в PDF.
Связь с оплатами: загрузка банковской выписки → разнесение оплат по номеру счёта/сумме → изменение статуса.
3. Акт выполненных работ / оказанных услуг (ACT)
3.1. Структура печатной формы
Название, номер, дата.
Исполнитель и Заказчик (наименования, реквизиты из снимков).
Основание: договор (№, дата) и/или счёт (№, дата) — автоподстановка.
Таблица: № | Наименование услуги/работы | Ед. | Кол-во | Цена | Сумма (опционально НДС).
Итого и сумма прописью.
Блоки: «Работы выполнены в полном объёме, заказчик претензий не имеет» (текст-константа, редактируемый).
Подписи: исполнитель (должность, ФИО), заказчик (должность, ФИО); поле печати — опционально.
3.2. Логика
Создание из счёта: позиции и суммы копируются 1:1.
Создание напрямую из сделки/дела без счёта — допускается.
Статусы: Черновик → Отправлен → Согласован → Подписан (скан загружен) → Отклонён (с комментарием) → Аннулирован.
После статуса «Подписан» система предлагает создать счёт-фактуру или УПД (если компания плательщик НДС).
Один счёт может закрываться несколькими актами (частичное подписание) — поле «Сумма по документу» и контроль остатка.
4. Счёт-фактура (SF)
4.1. Правила (справочно для реализации)
Форма и порядок заполнения: Постановление Правительства РФ № 1137 (актуальная редакция). Форма обязательна к использованию, произвольные формы не допускаются.
Срок выставления: не позднее 5 календарных дней со дня отгрузки/оказания услуги (п. 3 ст. 168 НК РФ).
Новые требования с 01.04.2026: строка 5б — реквизиты авансового счёта-фактуры при отгрузке в счёт полученного аванса; для ИП — ОГРНИП и дата присвоения вместо реквизитов свидетельства.
Подписи: руководитель и главбух (или уполномоченные по приказу/доверенности); для статуса «1» УПД — УКЭП в ЭДО.
Регистрация: в книге продаж у продавца, в книге покупок у покупателя.

4.4. Логика в CRM
Создаётся из счёта/акта/накладной, если компания на ОСНО и vat_mode != none.
Автовалидация: предупреждение, если с даты документа прошло > 5 календарных дней.
Авансовые счёта-фактуры: если по сделке была частичная оплата — система напоминает о необходимости авансового СФ и подставляет его реквизиты в строку 5б при отгрузке.
Статусы: Черновик → Отправлен → Подписан (скан) / Отправлен через ЭДО → Аннулирован.
Отдельная нумерация (обычно с префиксом или общая с УПД — настраивается).

5.3. Структура документа (3 части)
Описательная часть: реквизиты сторон, номер, дата, основание (договор), грузоотправитель/грузополучатель.
Табличная часть: позиции (аналогично счёту-фактуре: наименование, ед. изм. по ОКЕИ, количество, цена, суммы, НДС).
Подтверждающая часть: блок подписей продавца (строки 8–14) и покупателя (строки 15–19): должность, ФИО, подпись, наименование экономического субъекта — составителя документа.
5.4. Логика в CRM
Выбор статуса: автоматически предлагается по СНО профиля компании (ОСНО с НДС → 1; УСН/без НДС → 2), с возможностью ручного изменения.
Создание из счёта в один клик; если позиции — услуги, грузоотправитель/грузополучатель = прочерк.
Даты: первичка — в момент операции или сразу после; статус 1 — не позднее 5 дней (валимация по сроку).
ЭДО: отправка в формате УПД 5.03 (функции СЧФДОП/ДОП), подписание УКЭП. С 01.01.2026 электронная реализация оформляется только УПД; электронные акт и ТОРГ-12 отменены (бумажные формы остаются).
Статусы: Черновик → Отправлен (бумага/ЭДО) → Подписан покупателем (ЭДО-статусы: отправлен, получен, подписан) → Отклонён → Аннулирован.
6. Товарная накладная ТОРГ-12 (TN)
6.1. Правила (справочно)
Унифицированная форма: Постановление Госкомстата № 132 от 25.12.1998; допускается своя форма с обязательными реквизитами ч. 2 ст. 9 402-ФЗ.
С 01.01.2026 электронный формат ТОРГ-12 отменён: в бумаге — форма ТОРГ-12, в ЭДО — только УПД 5.03.
Составляется в 2 экземплярах (продавцу и покупателю). Печать необязательна.

6.3. Логика в CRM
Создание из счёта: позиции, единицы измерения (код ОКЕИ из номенклатуры), количества и суммы копируются.
Только для товарных позиций; для услуг система блокирует создание ТОРГ-12 (предлагает акт или УПД).
НДС: если «Без НДС» — в графе текст «Без НДС» (не прочерк и не пусто).
Соответствие договору: контроль наименований и количеств против позиций счёта/договора (ст. 465 ГК).
Статусы: Черновик → Отправлен → Подписан (скан) → Отклонён → Аннулирован.
7. Договор и дополнительные соглашения (CONTRACT / EXT)
Поля: номер, дата, тип (возмездное оказание услуг, поставка и т. д.), стороны из снимков, предмет, срок, сумма, условия оплаты (предоплата/постоплата, рассрочка), НДС-оговорка.
Шаблоны договоров с переменными (данные клиента, компании, услуг, сумм) — генерация DOCX/PDF.
Связь: к договору привязываются счёта, акты, УПД (поле contract_id).
Статусы: Черновик → На согласовании (юрист) → Отправлен клиенту → Подписан (скан) → Расторгнут → Архив.
Доп. соглашение наследует contract_id, создаёт запись в истории договора.
8. Акт сверки (CLOSING)
Поля: период (от/до), организации из снимков, номер.
Таблица: движение по датам (документ, дата, дебет, кредит); начальное и конечное сальдо.
Источник данных: счета + разнесённые оплаты из выписок.
Статусы: Черновик → Отправлен → Согласован → Расхождение (с комментарием).
9. Нумерация документов
Схема: {префикс}-{номер}-{год}. Пример: СЧ-145-2026, АКТ-12-2026, УПД-7-2026.
Настройки по типу документа: префикс, формат номера (счётчик), сброс счётчика (ежегодно / никогда / ежемесячно).
Режимы: сквозная нумерация (общий счётчик для СФ и УПД со статусом 1 — по правилам ведения книги продаж) или раздельная по типам.
Номер присваивается при переходе из «Черновик» в «Отправлен» (в черновике — номер не фиксируется или предварительный).
Запрет редактирования номера после отправки.

11. Генерация и отправка
Печатные формы: HTML-шаблон на тип документа → PDF. Шаблоны редактируются (логотип, подпись, печать — из профиля компании).
Отправка: email (из шаблона письма с вложением PDF + ссылка на онлайн-версию), мессенджер-интеграция, скачивание.
Онлайн-версия: публичная ссылка с ограниченным сроком, только просмотр.
ЭДО: интеграция с оператором для УПД 5.03, СФ, актов (функции СЧФДОП/ДОП); подписание УКЭП; статусы синхронизируются в CRM.
Хранение: PDF + исходный шаблон + файлы подписей; неизменяемость после подписания (версионирование).

14. Критерии приёмки модуля
Из счёта в 1 клик создаются акт, УПД, счёт-фактура, ТОРГ-12 с корректным переносом позиций, сумм и НДС.
Сумма прописью и итоги формируются автоматически, округление корректно.
Снимки реквизитов фиксируются: изменение профиля не меняет уже созданные документы.
Нумерация сквозная/раздельная настраивается; номер фиксируется при отправке.
Загрузка выписки банка автоматически меняет статусы оплаты счетов.
ЭДО: УПД 5.03 уходит оператору, статусы подписания возвращаются в CRM.
Для услуг ТОРГ-12 недоступна; для товаров недоступен акт услуг.
Авансовые СФ: строка 5б заполняется при отгрузке в счёт аванса.
Каждый документ имеет историю: кто создал, отправил, подписал, когда.
