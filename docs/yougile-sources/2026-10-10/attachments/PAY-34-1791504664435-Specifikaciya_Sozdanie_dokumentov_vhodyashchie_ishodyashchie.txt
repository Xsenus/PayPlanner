## word/document.xml
Спецификация: создание документов компании (исходящие/доходные и входящие/расходные) в CRM
По аналогии с КУБ24.Выставление счетов. Только структура и логика для разработки. Версия 1.0
1. Назначение модуля
Модуль управляет полным документооборотом компании в двух направлениях:
Исходящие (доходные) документы — компания создаёт и отправляет клиенту/покупателю. Формируют дебиторскую задолженность (нам должны деньги). Примеры: счёт, акт, товарная накладная (ТОРГ-12), счёт-фактура, УПД, договор, акт сверки.
Входящие (расходные) документы — документ приходит от поставщика/контрагента (или создаётся сотрудником компании самостоятельно по факту получения). Формируют кредиторскую задолженность (мы должны деньги). Примеры: входящий счёт, входящий акт/УПД/накладная, доверенность.
Принцип КУБ24: документ создаётся всегда на основании чего-либо. Исходящий счёт — точка входа цепочки исходящих документов. Входящий счёт — точка входа цепочки входящих документов и источник задолженности.

4. Общая логика: на основании чего создаётся документ
Единое правило (как в КУБ24): каждый документ имеет «основание». Основание определяет, куда подтягиваются данные и с чем документ связан.
Документ

Что подтягивается
Исходящий счёт
Свободное создание; из карточки контрагента; из карточки договора; из заказа; из справочника услуг («Выставить счёт» по выделенным услугам)
Реквизиты покупателя (по ИНН), договор (если привязан), расчётный счёт, номенклатура
Акт (исходящий)

Входящий счёт
1) Загрузка файла (скан/PDF); 2) создание вручную по данным поставщика; 3) из ЭДО; 4) из карточки поставщика («+Счёт»)

Входящий акт/УПД/накладная

Ключевой сценарий пользователя: «входящий документ можно создать самостоятельно, и на его основании возникает долг».
5. Исходящие (доходные) документы
5.1. Способы создания счёта
Кнопка «+» → «Счёт» (верхнее меню).
Список счетов → «+Добавить» (Меню → Продажи → Счета).
Карточка покупателя → «+Счёт» (покупатель и основание подставляются автоматически).
Карточка договора → «+Счёт» (договор подставляется как основание).
Карточка заказа → «+Счёт».
Раздел «Товары и услуги» → выделить позиции → «Выставить счёт» / «Выставить счёт-договор».
5.2. Форма создания счёта (порядок блоков как в КУБ24)
Покупатель: выбор из справочника или создание по ИНН (автозаполнение из ЕГРЮЛ/ЕГРИП); флажок «Физическое лицо» переключает форму (ФИО, адрес).
Расчётный счёт: выбор счёта получения оплаты (по умолчанию — основной); возможность добавить новый рублёвый или валютный счёт, указать начальный остаток.
Договор: выбор из договоров контрагента или создание по шаблону; если счёт-договор — появляется поле «Предмет договора».
Позиции: выбор из справочника номенклатуры или быстрое добавление новой; тип (товар/услуга), количество, единица измерения, цена, вариант НДС (в т.ч. НДС / НДС сверху / без НДС).
Дополнительные параметры: «Счёт выставил» (ответственный — текущий пользователь), проект, валюта, вложения (до 3 файлов).
Срок оплаты: по умолчанию отсрочка 10 дней (настраивается на контрагента).
5.3. Автонумерация и автоматика
Номер присваивается автоматически; дата = дата создания; сумма прописью формируется по итоговой сумме; НДС и «Итого» считаются формулами без ручного ввода.
Счёт-договор: значение is_contract_invoice = true; после создания доступен для подписания без отдельного договора.
Кнопка «Обновить» на счёте — если в профиль компании или контрагента внесены изменения после создания счёта, предложит обновить данные (реквизиты из карточек).

Отправить (счёт или полный комплект документов); Печать (один PDF); Скачать (PDF, PDF с печатью/подписью, Word, XML для ЭДО).
Копировать — создание нового счёта со всеми параметрами.
Отметить «Оплачен» вручную (дата + тип оплаты: банк/касса/e-money) и «Снять оплату».
Отменить, Удалить (нельзя удалить счёт с оплатой и счёт, у которого есть производные документы — сначала удалить их).
Правый блок: статус и дата, связанный счёт/основание, покупатель, комментарии, кнопка «Проверить покупателя» (ФНС/досье), кнопка «Автосчёт».

6.2. Правило возникновения задолженности
При сохранении входящего счёта со статусом «Принят» система создаёт запись в debt_ledger: контрагент-поставщик, направление EXPENSE, сумма счёта, срок оплаты.
Сумма долга = сумма счёта − разнесённые оплаты (частичная оплата уменьшает остаток).
Аванс (оплата раньше счёта): расходная операция без привязки к счёту висит на контрагенте как «не разнесённая оплата»; при появлении входящего счёта операция может быть разнесена на него (кнопка «Уточнить»).
Если счёт отменён или удалён — запись долга гасится/удаляется (с проверкой на отсутствие оплат).
Дата признания расхода: поле «Дата признания» влияет на отчёт ОПиУ (как в КУБ24).

6.4. Оплата входящих документов
Расходная операция создаётся: вручную (кнопка «+» → «Операцию по банку» → расход), или из автозагрузки выписки (интеграция с банком по токену — пароли не хранятся; автозагрузка по расписанию; загрузка файла формата 1С *.txt из любого банка).
Автопривязка: алгоритм определяет номер счёта в назначении платежа и находит неоплаченный счёт контрагента; статьи расхода подтягиваются из карточки поставщика; поиск дублей выписки.
Если привязать не удалось — «Уточнить»: сотрудник вручную указывает оплаченные счета; без привязки оплата закрепляется за контрагентом («Не разнесённые оплаты» в карточке).
Счёт меняет статус на «Оплачен»/«Частично оплачен» автоматически; напоминания о неоплаченных счетах — по расписанию.
6.5. Поставщики
Раздел «Поставщики» — аналог «Покупателей»: карточка с реквизитами (автозаполнение по ИНН), статьями расхода по умолчанию, вкладками «Счета» (входящие), «Деньги» (оплаты), «Документы», «Акт сверки».
Удаление поставщика запрещено при наличии связанных документов/операций.

7.2. Массовое создание (список счетов, чекбоксы)
Создать акты / ТН / СФ / УПД по выбранным счетам: даты = сегодня, номера — по порядковым номерам списков соответствующих документов.
Создать один Акт / один УПД по нескольким счетам — только для счетов одного контрагента (для УПД — счёты без других закрывающих документов).
Массовая рассылка: «Счета» — письмо со счётом; «Счета+Акт/ТН/СФ/УПД» — полный комплект; только счета одного контрагента.
Массовая оплата: проставить оплаты (дата + тип: банк/касса/e-money) по выбранным счетам.
Массовая смена статусов «Передана/Подписана», выгрузка реестра в Excel.
7.3. Карточки производных документов
Правый блок: статус и дата, ссылка на связанный счёт, покупатель/поставщик, основание, прикреплённые сканы (до 3, до 3 МБ), комментарии, кнопка «i» — история изменений документа.
Редактирование: номер, дата, основание, количество позиций, добавление/удаление позиций, комментарий; изменение количества работает по правилу остатка (см. матрицу).
Нижнее меню: Отправить (PDF + файл для 1С), Печать (PDF с печатью и подписью — настройка профиля компании), Скачать (PDF/Word/XML для ЭДО), «Передан»/«Подписан», Удалить (безвозвратно, только при отсутствии оплат).
8. Долги и разнесение оплат (сводная логика)
Ситуация
Механика
Исходящий счёт создан и отправлен
Дебиторка контрагента += сумма счёта; статус «Отправлен»; напоминания должнику по расписанию
Пришла оплата (приходная операция)
Автопривязка по назначению платежа → payment_allocations; счёт «Частично оплачен»/«Оплачен»; дебиторка уменьшается
Частичная оплата
Остаток долга = сумма − оплачено; счёт присутствует в двух блоках статистики с соответствующими суммами
Авансовая оплата клиента
Приход без счёта → «не разнесённая оплата» на контрагенте; при выставлении счёта можно разнести аванс; контроль сальдо
Входящий счёт принят
Кредиторка на поставщика += сумма; статус «Принят»; напоминания о сроках
Оплачен входящий счёт (расходная операция)
Автопривязка/ручное разнесение; кредиторка уменьшается; счёт «Оплачен»
Акт сверки
Формируется по связке «счёт=оплата» или «акт=оплата», за период, с заполнением обеих сторон по данным контрагента
Блок статистики в списках документов: «Не оплачено всего» (срок оплаты > сегодня), «Не оплачено в срок/Просрочено» (срок < сегодня), «Оплачено» (статусы Оплачен и Частично оплачен). Счёт в частичной оплате учитывается в обоих блоках по долям сумм.
9. Генерация, отправка и хранение
Все печатные формы (PDF, PDF с печатью/подписью, Word, Excel, XML для ЭДО, файл выгрузки в 1С) генерируются «на лету» и не хранятся на сервере как файлы.
Отправка email: сначала на e-mail контакта, затем бухгалтера, затем директора (правила приоритета).
Прикрепление файлов к документу: до 3 файлов, ограничение размера (5 МБ для вложений, 3 МБ для сканов к актам).
Автовыставление: шаблоны повторяющихся счетов (ежемесячно) и автосчёты; автоподготовка актов по графику.
Выгрузка в 1С: все документы и операции доступны для загрузки в бухгалтерскую базу.

11. Правила удаления и целостность
Нельзя удалить контрагента, у которого есть документы или операции по деньгам.
Нельзя удалить счёт, по которому есть оплата или производные документы (сначала снять оплату / удалить производные).
Удалённые производные документы (акт, ТН, УПД, СФ) не восстанавливаются.
Снятие оплаты возвращает счёт в предыдущий статус и пересчитывает задолженность.
Дубли выписки при загрузке помечаются «Дубль» и игнорируются.
12. Критерии приёмки
Счёт (исходящий) создаётся по блокам КУБ24: покупатель → расчётный счёт → договор → позиции; реквизиты автозаполняются по ИНН, банк — по БИК.
Входящий счёт можно создать тремя способами (файл, вручную, из ЭДО) и он порождает запись задолженности после принятия.
Акт невозможно создать без счёта; акт по счёту без услуг — заблокирован; ТН по счёту без товаров — заблокирована.
Частичное закрытие: при акте на меньшее количество в счёте доступен следующий акт на остаток; при увеличении количества — доступен доп. счёт на разницу.
Один акт/УПД по нескольким счетам — только для одного контрагента (для УПД — без других закрывающих документов).
Оплата из выписки автоматически разносится по счетам; неразнесённые оплаты доступны в карточке контрагента и разнесение возможно кнопкой «Уточнить».
Статусы счёта меняются автоматически (Просрочен, Оплачен, Частично оплачен); «Снять оплату» возвращает исходное состояние.
Массовые действия: создание закрывающих документов, рассылка комплектов, массовая оплата, смена статусов, выгрузка Excel.
Все печатные формы генерируются на лету в PDF/Word/XML/Excel и доступны для выгрузки в 1С.
