ФУНКЦИОНАЛ «СЧЁТ»
Для разработки CRM юридической фирмы. Версия 1.0
1. Общая логика
Счёт — первичный документ на оплату услуг, привязывается к клиенту, договору и делу.
Счёт не существует без привязки: минимум «клиент»; для работы по договору — «договор + дело».
Клиент может иметь несколько счетов; дело — несколько счетов; счёт принадлежит только одному делу.
Счёт создаётся в двух сценариях: вручную менеджером/координатором; автоматически из дела (по заказ-наряду / этапу).
Сумма счёта формируется из позиций (услуг). НДС у юридической фирмы по умолчанию «Без НДС» (УСН) — настраивается.
Оплата может быть: полной, частичной (рассрочка), авансовой. Оплаты разнесены по счёту автоматом (банковская выписка) или вручную.

2.1. Правила переходов
Статус «Отправлен» — обязательно фиксируется факт отправки (дата, канал, кем).
Статус «Оплачен» — подтверждается только поступлением денег (выписка банка) либо вручную с отметкой.
«Просрочен» — авто по дате срока оплаты, если статус «Отправлен»/«Согласован» и оплат нет.
Аннулирование — доступно до полной оплаты; причина обязательна; запись в историю.
3. Структура счёта (документ PDF для клиента)
3.1. Шапка
Номер счёта — автонумерация: формат [Префикс]-[ГГГГ]-[NNNN], префикс настраивается.
Дата выставления — по умолчанию текущая, редактируется.
Срок оплаты — дата (авто: дата выставления + X дней, X настраивается, по умолчанию 5).
Наименование исполнителя: логотип (чекбокс вкл/выкл), наименование, реквизиты.
Наименование плательщика: тип (юр. лицо / физ. лицо), реквизиты соответствующего типа.

8. Отчёты по счетам
Список счетов с фильтрами: статус, клиент, договор, дело, период, сумма.
Дебиторка: неоплаченные и частично оплаченные счета, сгруппированные по клиенту.
Конверсия: выставлено → отправлено → оплачено.
Динамика поступлений по месяцам.
