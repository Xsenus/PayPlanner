# Оптимизация производительности и стабильности системы

Дата начала: 17.07.2026.

## Цель

Последовательно проверять серверные запросы, работу с базой данных, фоновые процессы и клиентский слой. Каждое изменение должно сохранять текущую бизнес-логику, иметь регрессионные тесты и подтверждаться на локальной базе данных до коммита.

## Принципы работы

- Сначала измерять текущее поведение и находить конкретное узкое место.
- Выполнять по одной ограниченной задаче, не смешивая несвязанные изменения.
- Проверять PostgreSQL и SQLite, если изменение затрагивает запросы или схему данных.
- Не считать задачу завершённой без тестов, сборки, проверки миграций, кодировки и журналов ошибок.
- До публикации этапа собирать пользовательские изменения в одной общей записи «Что нового».
- Не использовать завершённые планы из `docs/archive/roadmaps/` как активные задачи; учитывать их только для исключения уже выполненной работы.
