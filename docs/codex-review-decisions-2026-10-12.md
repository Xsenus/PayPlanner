# Вопросы после проверки карточек клиента и дела

Основание: [передача Claude](claude-handoff-for-codex-review-2026-10-12.md), исходная ревизия `a019cc8d`. Это предложения для следующих продуктовых этапов; текущая проверка не утверждает новые правила.

## PAY-21 — ЕФРСБ и Почта РФ

В текущем коде `src/` и `backend/` не найден действующий API интеграции с ЕФРСБ или журналом почтовых отправлений дела. Почтовые индексы в адресах клиентов относятся к адресным данным, а не к отслеживанию отправлений. Поэтому тезис Claude о незавершённых интеграциях подтверждён. PAY-26 относится к ФССП; это отдельный источник и не замена ЕФРСБ.

Варианты:

| Вариант | Что получит пользователь | Что требуется перед реализацией |
| --- | --- | --- |
| Ссылка на официальный внешний сайт | Переход для самостоятельного поиска, без обещания синхронизации | Утвердить сайт и формат ссылки; не передавать личные данные в URL без отдельного решения |
| Неактивный пункт с пояснением | Пользователь видит, что раздел планируется, но работать с ним пока нельзя | Утвердить формулировку и необходимость такого пункта в рабочем меню |
| Полноценный раздел отдельным этапом | Связанные записи, история, поиск, обновления и права | Для Почты РФ — PAY-27; для ЕФРСБ — отдельное задание со спецификацией источника, связей и полномочий |

Рекомендация: сохранять текущий рабочий быстрый доступ и реализовывать полноценные разделы отдельными пакетами. Если внешний переход нужен раньше, сначала согласовать его формат. Не показывать вымышленные записи или результаты проверки источника.

## PAY-25 — общий журнал

Исходный макет содержит судебные события, получение/отправку документов и регистрацию дела. Текущая новая вкладка содержит **только судебные события**. Уже существуют отдельные источники: `getCaseTimeline` (история дела), `getCaseDocuments` (документы), `getCaseConversation` (переписка). Общий журнал можно построить поверх них, но требуется уточнить состав событий, дату (создание/загрузка/факт отправки), дедупликацию и доступность каждого типа по правам. Нельзя выдавать загрузку файла за его отправку в суд.

Рекомендация для следующего этапа PAY-25: единая лента подтверждённых событий с переходами к исходным объектам, отдельным указанием источника и фильтрами типов/периода. Финансовые и закрытые задачи не включать без соответствующих разрешений. Текущая судебная вкладка остаётся частичным выполнением пакета; ограничение отражено в общей записи «Что нового».

## PAY-32 — номер клиента

В данных есть реальный ID; утверждённого отдельного номера вида `КЛ-000124` нет. Показанный ID сохранён. Варианты: оставить ID либо утвердить постоянный отдельный номер с правилами импорта, уникальности, исторических записей и неизменности. Рекомендация: использовать ID до утверждения формата, не создавать номер только для сходства с иллюстрацией.

## PAY-32 — название раздела юрлица

Для физлица применяется «Личные данные», для юрлица сохранена «Карточка клиента». Последнее название не меняет существующую форму. Для дальнейшего редизайна предлагается «Данные организации»; это требует согласования словаря продукта и проверки обеих точек входа в организации. Переименование во время текущей проверки не выполнено, чтобы не выдавать несогласованный вариант за принятое название.
