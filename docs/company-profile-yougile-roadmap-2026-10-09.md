# PAY-33 — профиль собственных компаний и филиалы

Срочный блок P1. Источник — Word-ТЗ карточки PAY-33 от 9 октября. Существующие `LegalEntity`, профиль компании, списки реквизитов, выбор главной компании и права компании надо использовать как основу. Их наличие не доказывает выполнение всего нового ТЗ. Ссылка на урок КУБ24 не прочитана: доступ через web-инструмент не получен.

Всего 10 пунктов: завершено 9 (1–9), приёмки 1 (10). **Прогресс: 9/10, 90%.**

- [x] 2. [Матрица составлена](company-profile-gap-matrix-2026-10-09.md). Исходная формулировка: составить точную матрицу «требование → существующий код → проверка → расхождение». Уже найдены `LegalEntity`, `MainCompanySettings`, `CompanyProfile`, `UserCompanyAccess`, `BankAccountsJson`; полная сверка контроллеров и обеих моделей БД ещё нужна.
- [x] 3. Решение владельца (9 октября): профили общие для организации, управляет администратор, новый справочник не создаётся, ИНН уникален в юрлицах, права сотрудников — через существующие роли. Исходно: уточнить владельца профилей: ТЗ использует одновременно аккаунт пользователя и несколько юрлиц CRM. Согласовать общую принадлежность, права сотрудников и уникальность ИНН; не создавать параллельный справочник контрагентов без решения.
- [x] 4. Решение владельца (9 октября): ИНН всегда общий, собственный КПП у подразделения необязателен (пусто — КПП компании); НДС решается в PAY-34. Исходно: согласовать наследование филиала: в общих принципах собственный ИНН запрещён, в таблице есть «свой ИНН/КПП». Сохранять единый ИНН компании и отдельный КПП можно только после подтверждения нужной модели. Налоговый режим сам по себе не означает отсутствие НДС: см. зависимости PAY-34.

Автозаполнение DaData при недоступности источника возвращает «не найдено» (ошибки логируются), поля остаются доступны для ручного ввода — проверено по коду. Контрольные суммы дают предупреждения, а не блокировку: это сознательное решение, чтобы не ломать импортированные данные. Исходная формулировка: доработать создание/редактирование собственных компаний: проверка ИНН, автозаполнение ЕГРЮЛ/ЕГРИП, безопасный ручной ввод при недоступности источника, защита от дубликата, черновик/активен/архив.

Исходная формулировка: реализовать филиалы/офисы/точки/направления, явные переопределения адреса, банка, подписанта и КПП, наследование прочих значений; архивацию при существующих документах.

Для новых моделей — парные миграции SQLite/PostgreSQL, clean/upgrade, отрицательные и конкурентные тесты, заметка «Что нового», полный применимый gate перед выпуском.
- [acceptance] 10. На согласованных компаниях и ролях принять создание, наследование, архивацию, старые документы, подпись/печать/логотип в PDF с реальными размерами. После успешной установки подготовить новый ответ PAY-33; публикация/перевод — только по отдельной команде.

Готово означает выполнение пунктов 1–10, а не существование экрана профиля. Профили и филиалы выбираются в документах без ручного повторения реквизитов, данные прежних документов сохраняются, чужие компании недоступны по правам. Следующий безопасный шаг — завершить матрицу пункта 2; финансовые и принадлежностные решения не подменять предположениями.
