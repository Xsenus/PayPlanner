Дата создания: 29 июля 2026.
Статус: активный roadmap, заблокирован выбором способа идентификации клиента.

## Цель

Дать клиенту безопасный способ просмотреть конкретную версию заказ-наряда, согласовать ее или вернуть замечания без доступа к внутренним данным CRM.

## Текущее состояние

- `[x]` Заказ-наряд существует в карточке дела и содержит позиции, суммы и сроки.
- `[x]` Есть внутренний workflow отправки, согласования и доработки.
- `[x]` Из принятого заказ-наряда можно создавать счет, акт и договор.
- Внешней формы и надежной идентификации клиента нет.

## Решения заказчика

- `[decision]` Выбрать канал: личный кабинет, одноразовая ссылка, email-token, SMS-код или комбинированная проверка.
- `[decision]` Определить, кто вправе согласовать: клиент, представитель, несколько лиц, организация.
- `[decision]` Утвердить показываемые поля, персональные данные и документы.
- `[decision]` Утвердить юридическую силу действия и требуемые доказательства.
- `[decision]` Утвердить срок действия ссылки, число попыток и повторную отправку.

## Этап 1. Модель согласования

- `[ ]` Создать отдельную сущность запроса с immutable snapshot версии заказ-наряда.
- `[ ]` Хранить token hash, срок действия, статус, число попыток и канал доставки.
- `[ ]` Хранить решение, комментарий, время, IP, user agent и подтвержденный контакт.
- `[ ]` Запретить изменение snapshot после отправки; новая версия создает новый запрос.
- `[ ]` Сделать предыдущие ссылки недействительными при отзыве или новой версии.
- `[ ]` Обеспечить идемпотентность повторного нажатия «Согласовать».

## Этап 2. Публичный API и безопасность

- `[ ]` Создать отдельный anonymous endpoint с узким DTO без внутренних идентификаторов.
- `[ ]` Хранить только hash токена; использовать криптографически стойкий одноразовый токен.
- `[ ]` Добавить rate limit, cooldown, блокировку перебора и безопасные ошибки.
- `[ ]` При необходимости добавить второй фактор через SMS/email OTP.
- `[ ]` Запретить index/cache/referrer leakage, настроить CSP и security headers.
- `[ ]` Не отдавать внутренние комментарии, себестоимость, исполнителей и скрытые документы.

## Этап 3. Интерфейс клиента

- `[ ]` Адаптивно показать компанию, дело, услуги, количество, цену, итог, сроки и разрешенные вложения.
- `[ ]` Добавить действия «Согласовать» и «Вернуть с замечаниями».
- `[ ]` Требовать явное подтверждение перед окончательным решением.
- `[ ]` Показать срок действия, номер версии и результат уже принятого решения.
- `[ ]` Обеспечить доступность с клавиатуры и телефона.

## Этап 4. Интерфейс CRM и автоматизация

- `[ ]` Добавить мастер выбора получателя и канала.
- `[ ]` Показать статус доставки, открытия, решения и истечения.
- `[ ]` Записывать отправку, просмотр и решение в историю дела и аудит.
- `[ ]` Уведомлять ответственных о согласовании, замечаниях и истечении.
- `[ ]` После согласования предлагать создание счета/договора/акта без автоматического дублирования.
- `[ ]` После замечаний возвращать заказ-наряд в доработку, сохраняя предыдущую версию.

## Производительность и хранение

- Публичный запрос должен читать один snapshot без загрузки всей карточки дела.
- Вложения выдавать через короткоживущие подписанные ссылки.
- Очистку истекших токенов выполнять пачками; аудит решений хранить по утвержденному сроку.

## Проверки

- `[ ]` Unit-тесты токена, срока, одноразовости, snapshot и переходов статуса.
- `[ ]` API-тесты доступа, перебора, повторного решения и отозванной ссылки.
- `[ ]` Frontend-тесты согласования, замечаний, ошибки, истечения и мобильной верстки.
- `[ ]` Тест миграций на SQLite/PostgreSQL и отката feature flag.
- `[ ]` Security review публичного endpoint и вложений.
- `[acceptance]` Пройти полный сценарий с тестовым клиентом.
- `[acceptance]` Подтвердить состав отображаемых данных и запись доказательств решения.

## Rollout

- Включать feature flag только для выбранных сотрудников и тестовых клиентов.
- Сначала разрешить просмотр, затем решения.
- Иметь кнопку отзыва всех активных ссылок.

## Definition of Done

- Клиент согласует только неизменяемую версию и видит только разрешенные данные.
- Решение доказуемо, идемпотентно и связано с историей дела.
- Истекшие и отозванные ссылки безопасны.
- Есть тесты, release note, успешный deploy и production-приемка.
