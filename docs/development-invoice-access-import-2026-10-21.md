## Реализация

- Видимость соседней строки через общую сущность счёта наследуется только при согласованных владельце, направлении и подтверждённой компании. Разрешённая рассрочка без собственного контрагента и возврат тому же контрагенту сохраняют прежнюю видимость.
- Исторический агрегат с противоречивыми документами исключён из реестра, сводки, карточки, предпросмотра и HTML/PDF/Word. Изменение/удаление, восстановительные маршруты и распределение банковской или ручной оплаты не должны менять такой агрегат. Журнал платежей сохраняет собственные права чтения: карантин документа не скрывает разрешённую первичную историю от администратора.
- Вложенные акты и основной акт карточки проверяются по владельцу. Номер без владельца не является разрешением присоединить акт; старое сопоставление допустимо только для единственного документа данного владельца. Отдельно ограничены поиск по содержимому акта и фильтр по его ID.
- Табличный/1С-импорт ищет документ по контрагенту, направлению, номеру/дате и UID. Уникальный UID допускает обычное изменение номера при повторной загрузке, но не переносит счёт другому контрагенту. Повторяющиеся UID старых выгрузок 1С продолжают поддерживаться при различимых документах. Разные известные UID не перезаписывают друг друга из-за одинакового номера. Дубликат внутри файла учитывает владельца и UID.
- Новый документ получает отдельную техническую сущность счёта. Для актов применяется тот же механизм сопоставления по владельцу и UID; номер и дата другого контрагента не выбирают существующий акт для перезаписи. Существующий документ с общей исторической связью не обновляется импортом. Неоднозначный контрагент или несколько подходящих документов дают невыбираемую строку с причиной; применение повторно строит актуальный preview и проверяет цель до записи.
- При обновлении индекса импорта меняются только ключи конкретной документной строки; полный просмотр индекса после каждой строки убран. Кандидатов повторяющегося UID достаточно двух для определения неоднозначности.
- Импорт SQLite-БД проверяет источник и совпадающие целевые счета до первой записи. Межбазовый ключ включает владельца, направление, продавца и UID, а не локальный ID. Повтор старой базы отказывает, если финансовое состояние существующего счёта уже изменилось, чтобы не добавить вторую документную строку вместо замены суммы. Ссылки акта переводятся через карту документных строк Payments. Несопоставленный филиал вызывает отказ. Импорт выполняется в общей сериализуемой транзакции с точками сохранения этапов; ошибка или конфликт отменяет его записи целиком, счётчики добавлений/обновлений обнуляются.
- Табличный/1С-импорт строит актуальное состояние и применяет пакет в одной сериализуемой транзакции. Запись сообщения об ошибке строки не разрешает частично переписать неоднозначную связь. Одновременная правка не должна незаметно заменить проверенный набор.
- Откат не удаляет счёт, к которому после импорта добавились платежи или внешние акты (включая архивные), и не возвращает старую общую связь с другим документом. Восстановление проверяет именно ID из снимка, сохраняя самостоятельную текущую сущность при отказе.

Схема БД, миграции и публичные форматы API не меняются. Неактивные записи «Что нового» 1.14.108–110 подготовлены отдельно для защиты доступа, импорта и отката. YouGile не менялся.
