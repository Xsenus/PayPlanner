# Безопасность анонимных callback, webhook и служебных маршрутов

Дата проверки: 5 августа 2026 года.

## Что защищено

- OAuth-callback Google Calendar, Яндекс.Календаря и Яндекс.Диска ограничены 30 запросами в минуту на внешний IP и конкретный маршрут.
- Webhook Google Calendar, Telegram и MAX ограничены 300 запросами в минуту на внешний IP и маршрут. Очередь rate limiter отключена, поэтому лишние запросы сразу получают `429` и не удерживают ресурсы приложения.
- Размер тела Google webhook ограничен 16 КиБ, MAX — 64 КиБ, Telegram — 256 КиБ.
- Публичные feature flags и health ограничены отдельной облегчённой политикой. Детальная диагностика судебных интеграций доступна только администратору.
- Параметры OAuth-callback имеют предельную длину до входа в бизнес-логику.

## Одноразовая обработка OAuth

Запросы подключения календарей захватываются условным обновлением статуса `pending -> processing`. Поэтому два параллельных callback с одним `state` не выполняют повторный обмен authorization code и не создают второе подключение. Повторный callback завершённого, отклонённого или просроченного запроса только показывает сохранённый результат.

Для Яндекс.Диска тот же переход выполняется внутри блокировки хранилища OAuth-запросов. Внешний HTTP-запрос выполняет только callback, который первым захватил состояние.

## Журнал активности

Перед записью query string сервер заменяет значения `state`, `code`, `token`, `access_token`, `refresh_token`, `otp`, `password`, `secret`, `hash`, `signature` и сходных ключей на `[скрыто]`. Безопасные параметры остаются видимыми для диагностики, а итоговая строка ограничивается длиной поля журнала.

IP-адрес берётся из `RemoteIpAddress` после штатной обработки доверенного reverse proxy. Необработанный клиентский `X-Forwarded-For` журнал больше не использует.

## Эксплуатационная проверка

При изменении маршрутов внешних интеграций необходимо проверить:

1. наличие `AllowAnonymous` только там, где его требует протокол провайдера;
2. отдельный rate limit и предел тела запроса;
3. проверку секретного заголовка или одноразового `state` до дорогой обработки;
4. отсутствие секретов в URL приложения, журнале активности и сообщениях об ошибках;
5. идемпотентность повторного callback или webhook.
