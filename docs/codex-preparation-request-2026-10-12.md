# Задание для Codex: подготовить входные материалы для разработки Claude Code

Контекст: Claude Code продолжает [roadmap прежних заданий YouGile](archive/roadmaps/unified-2026-10-14/yougile-execution-roadmap-2026-10-12.md) в ветке `claude/practical-bardeen-pglcf3`. Его облачная среда не открывает `yougile.com` (прокси отвечает 403) и не содержит .NET SDK. Из-за этого визуальные пакеты и серверные проверки не начаты. Нужно подготовить материалы в Git. Ничего в YouGile не публиковать, карточки не менять и не двигать (см. [AGENTS.md](../AGENTS.md)). Секреты, пароли и токены в репозиторий не класть.

Работать в ветке `claude/practical-bardeen-pglcf3`, историю не переписывать.

## 1. Макеты в полном размере (главное)

Скачать исходные картинки из чатов карточек и положить в `docs/yougile-sources/mockups/`. Имя файла: `PAY-N-<порядковый номер>-<кратко>.png`. Нужны карточки: PAY-19, 20, 21, 22 (последний дополненный макет с апелляцией, кассацией и ВС РФ), 23, 24, 25, 26, 27, 28, 29, 32. Если у карточки несколько макетов, взять все и отметить, какой последний.

Рядом положить `docs/yougile-sources/mockups/README.md`: таблица «файл → карточка → дата сообщения → что на картинке → что заказчик исключил» (например, левое меню). Для PAY-21 отдельно записать требование добавить в правое меню ЕФРСБ, Почту РФ и Финансы.

## 2. Среда для backend

Подготовить для среды Claude Code (или описать в `docs/`) воспроизводимую настройку:
- .NET SDK по `global.json`, проверенная команда сборки и запуска backend-тестов;
- локальный запуск backend с SQLite, с явно выключенными фоновыми задачами и почтой;
- сидирование синтетических данных (клиенты, дела, задачи, счета, роли). Данные production не использовать, даже санитизированную копию не делать без отдельного разрешения владельца.

Результат: инструкция «как запустить backend и тесты с нуля» и подтверждение, что хотя бы набор `TaskBillingConcurrencyTests` и семейство `InternalChat*` проходят.

## 3. Список вопросов владельцу

Собрать в `docs/owner-decisions-2026-10-12.md` по одному разделу на карточку с предложенным вариантом ответа и последствиями: PAY-2, 8, 9, 17, 18, 30, а также оплата акта, нумерация и PDF (PAY-33, 34), налоговая модель КУДиР (PAY-35), банк и протокол (PAY-36), значение «аннулирована» для календаря (PAY-37). Не придумывать бизнес-правила: только формулировать вопросы.

## 4. Карты действий (можно сделать сразу)

Для PAY-19, 20 и 32 составить таблицы «действие или поле → условия → право → текущее место в коде → кандидат на новое место». Источник — текущий код (`TaskJournal.tsx`, формы задач, карточка физлица). Это материал для Claude Code, код не менять.

## 5. Отчёт

В конце записать в `docs/` короткий отчёт: что положено, чего не удалось получить и почему, какие команды проверены. Коммитить коротко по-русски, пушить в ветку.
