# Google Calendar: подключение и синхронизация задач

## Где находится раздел

Подключение Google Calendar добавлено в профиль пользователя, а не в общие настройки CRM.

Путь для пользователя: профиль пользователя -> блок "Google Calendar".

В этом блоке пользователь видит состояние подключения, может открыть авторизацию Google, сохранить правила синхронизации, запустить обмен вручную, отключить подключение и посмотреть последние события синхронизации.

При отключении Google Calendar CRM сначала удаляет созданные PayPlanner календари и события во внешнем календаре. Если Google не подтвердил удаление хотя бы одного календаря или события, подключение не отключается, а причина сохраняется в журнале синхронизации.

В настройках подключения можно указать дату начала синхронизации. Если дата задана, CRM создаёт и обновляет в Google Calendar только задачи со сроком выполнения начиная с этой даты. Уже созданные события по задачам раньше выбранной даты удаляются при следующей синхронизации, но при полном отключении подключения удаляются все созданные PayPlanner календари и события независимо от этой даты.

Такой вариант выбран потому, что Google Calendar подключается к личному Google-аккаунту конкретного сотрудника. У каждого пользователя может быть свой календарь и свои OAuth-токены. Администратор тоже подключает Google Calendar через свой профиль, но для него включен расширенный режим синхронизации всех задач.

## Что нужно настроить администратору

Перед подключением пользователей администратор должен подготовить OAuth-приложение Google и включить настройки Google в CRM.

1. В Google Cloud Console создать или выбрать проект.
2. Включить Google Calendar API.
3. Настроить OAuth consent screen.
4. Создать OAuth Client ID типа Web application.
5. Добавить redirect URI CRM:

   `https://<домен CRM>/api/google-calendar/auth/callback`

   Для локальной проверки используется адрес локального backend:

   `http://localhost:<порт backend>/api/google-calendar/auth/callback`

6. В CRM сохранить настройки Google OAuth:

   - `auth.google.enabled` = `true`
   - `auth.google.clientId` = Client ID из Google Cloud
   - `auth.google.clientSecret` = Client Secret из Google Cloud

Эти же настройки используются существующим механизмом Google OAuth в CRM. Для календаря дополнительно требуется, чтобы в Google Cloud был включен Google Calendar API и OAuth-приложение разрешало scope календаря.

Для фоновой синхронизации должен быть включен флаг внешней календарной синхронизации:

`FeatureFlags:Legal:ExternalCalendarSync = true`

Интервал фонового обмена можно настроить параметром:

`GoogleCalendarSync:IntervalMinutes`

Если параметр не задан, сервис использует стандартный интервал 10 минут.

## Как подключается пользователь

1. Пользователь открывает свой профиль.
2. В блоке "Google Calendar" нажимает кнопку подключения.
3. CRM открывает окно авторизации Google.
4. Пользователь выбирает Google-аккаунт и разрешает доступ к календарю.
5. После успешной авторизации CRM сохраняет защищенные access/refresh token.
6. В профиле появляется статус подключения, список календарей синхронизации и журнал последних операций.

Если подключение не удалось, в блоке отображается ошибка, а детали сохраняются в журнале синхронизации.

## Как работает синхронизация для обычного пользователя

Обычный пользователь синхронизирует только свои задачи:

- задачи, где он назначен исполнителем;
- задачи, где он указан участником.

При создании или изменении задачи в CRM сервис создает или обновляет событие в Google Calendar. В событии сохраняется служебная связь с задачей CRM, поэтому последующие изменения обновляют уже существующее событие, а не создают дубликаты.

Из Google Calendar обратно в CRM могут возвращаться изменения времени, длительности, названия и статуса события. Правило обработки конфликтов задается в настройках подключения:

- "последнее изменение побеждает" - применяется более свежее изменение;
- "CRM главнее" - изменения из Google читаются, но спорные значения остаются как в CRM.

## Как работает режим администратора

Администратор при подключении Google Calendar может синхронизировать все задачи CRM.

Чтобы календарь администратора не превращался в одну общую ленту, задачи раскладываются по отдельным календарям сотрудников. Для каждого исполнителя создается или используется отдельный календарь с именем вида:

`PayPlanner - <ФИО сотрудника>`

Если у задачи нет исполнителя, она попадает в общий календарь задач PayPlanner. Такой подход позволяет администратору видеть общую картину, но сохраняет разделение по сотрудникам.

## Когда запускается обмен

Синхронизация запускается несколькими способами:

- автоматически после создания или изменения задачи в CRM;
- автоматически при удалении задачи в CRM, чтобы связанное событие PayPlanner исчезло из Google Calendar;
- вручную из блока "Google Calendar" в профиле;
- фоновым сервисом по расписанию, если включен флаг `ExternalCalendarSync`;
- при получении webhook-события Google Calendar, если для календаря зарегистрирован канал уведомлений.

Даже если Google Calendar временно недоступен, сохранение задачи в CRM не блокируется. Ошибка синхронизации записывается в журнал, а пользователь может повторить обмен вручную.

Удаление задач работает строже: если у задачи уже есть связанное событие Google Calendar и CRM не смогла удалить его через Google API, удаление задачи останавливается. Это защищает календарь от оставшихся событий, которые уже нельзя сопоставить с задачей CRM.

## Что происходит при удалении пользователя

Если пользователь удаляется из CRM, система сначала очищает созданные для него календари PayPlanner в Google Calendar:

- личный календарь PayPlanner в Google-аккаунте удаляемого пользователя;
- календарь сотрудника в Google Calendar администратора, если администратор синхронизировал все задачи в режиме отдельных календарей по сотрудникам.

Если Google Calendar недоступен или токен пользователя не позволяет удалить календарь, удаление пользователя останавливается. Администратор видит ошибку, а подробность сохраняется в журнале Google Calendar. После восстановления подключения операцию удаления можно повторить.

## Что хранится в базе

Для интеграции добавлены отдельные таблицы:

- подключения Google Calendar пользователей;
- временные OAuth-запросы;
- созданные или найденные Google-календари;
- связи задач CRM с событиями Google Calendar;
- журнал синхронизации.

Токены Google защищаются через механизм Data Protection приложения и не отображаются пользователю в открытом виде.

## Как проверить после настройки

1. Убедиться, что Google OAuth включен в CRM и сохранены Client ID/Client Secret.
2. Проверить, что redirect URI в Google Cloud совпадает с адресом CRM.
3. Зайти в CRM под обычным пользователем.
4. Открыть профиль и подключить Google Calendar.
5. Создать тестовую задачу на этого пользователя.
6. Запустить ручную синхронизацию в профиле.
7. Проверить, что событие появилось в Google Calendar.
8. Изменить время события в Google Calendar.
9. Запустить синхронизацию еще раз или дождаться фонового обмена.
10. Проверить, что изменение вернулось в задачу CRM.

Для проверки администратора нужно войти под администратором, подключить его Google Calendar, создать задачи на разных сотрудников и убедиться, что события разложены по отдельным календарям сотрудников.

## Где смотреть ошибки

Первые ошибки подключения видны в блоке "Google Calendar" в профиле пользователя.

Подробности сохраняются в журнале синхронизации. Там можно увидеть:

- успешные операции;
- ошибки авторизации;
- ошибки доступа к Google Calendar API;
- удаление событий после удаления задач CRM;
- удаление календарей при удалении пользователя;
- результаты ручного и фонового обмена;
- задачи или события, по которым возник конфликт.

Если ошибка связана с OAuth, в первую очередь нужно проверить Client ID, Client Secret, redirect URI и включение Google Calendar API в Google Cloud.
