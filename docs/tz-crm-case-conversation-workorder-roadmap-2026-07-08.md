## Цель

Довести карточку дела до сценариев ТЗ по обсуждению в рамках дела и согласованию заказа клиентом.

## Рабочие пункты

- `[x]` Проверить текущую переписку дела: модель сообщений, права, уведомления, история, связь с пользователями. Итог аудита сохранен в `docs/case-conversation-current-state-2026-07-08.md`, права и видимость закреплены backend-тестом.
- `[x]` Добавить вложения к сообщениям переписки, если текущая модель хранит только текстовые записи. Сообщение можно отправить с файлами из вкладки "Переписка"; API принимает multipart-запрос и возвращает вложения в ленте.
- `[x]` Связать вложения переписки с документами дела без дублей и с понятным источником файла. Файлы сохраняются как документы дела с типом "Переписка" и скачиваются из ленты по id документа.
- `[x]` Добавить уведомления участникам дела о новом сообщении и вложении. Ответственные участники дела получают уведомления типа "Переписка дела"; автор сообщения не получает уведомление самому себе.
- `[x]` Добавить frontend-тесты переписки: отправка сообщения, вложение, ошибка загрузки, права доступа. Покрыты отправка текста, отправка вложения, ошибка загрузки файла и режим просмотра без права редактирования.
- `[decision]` Подтвердить способ клиентского согласования заказ-наряда: публичная ссылка, личный кабинет, email-подтверждение, SMS-код или только внутреннее согласование.
- `[decision]` Уточнить, какие данные заказа можно показывать клиенту вне CRM: услуги, суммы, сроки, персональные данные, документы.
- `[!]` Реализовать внешний или внутренний сценарий согласования заказ-наряда по выбранному способу. Заблокировано до выбора способа согласования и состава данных, которые можно показывать клиенту вне CRM.
- `[!]` При согласовании заказ-наряда создавать событие истории дела и предлагать создание счета/договора/акта по текущей логике. Заблокировано до реализации базового сценария согласования.
- `[!]` Добавить аудит согласования: кто согласовал, когда, через какой канал, какая версия заказа была согласована. Заблокировано до реализации базового сценария согласования и выбора канала.
- `[!]` Проверить права доступа к переписке и согласованию прямыми API-вызовами. Полная проверка заблокирована до появления endpoint согласования; права переписки уже покрыты существующими тестами.
- `[acceptance]` Проверить согласование на реальном сценарии клиента заказчика.
- `[!]` Внешнее клиентское согласование может потребовать отдельной модели безопасности, если клиент работает без аккаунта CRM.

## Definition of Done

- Переписка по делу хранит текст, вложения и историю без потери прав доступа.
- Заказ-наряд можно согласовать выбранным заказчиком способом, а результат виден в карточке дела.
- Roadmap перенесен в архив после приемки переписки и клиентского согласования.
