## Найдено и исправлено дополнительно

1. **Падение опубликованного API.** DLL миграций находилась в пакете, но отсутствовала в его dependency manifest. Прямой запуск исходного пакета в изолированной тестовой среде воспроизвёл `FileNotFoundException` до запуска API. Контекст теперь загружает DLL по абсолютному пути и сохраняет явно переданную сборку миграций; файл включается в публикацию и при холодной сборке. Добавлен тест запуска настоящего API с его собственным manifest, без маскирующих ссылок проекта тестов.
2. **Расход закрывал заявку как оплаченную.** Регрессионный тест на исходной сборке получил HTTP 200 вместо 409. Переход теперь требует поступления от клиента; отказ не закрывает задачи, не создаёт дело и не меняет историю/версию заявки.
3. **Дробная сумма акта.** Сложение округлённых строк в JavaScript могло отправить `0.30000000000000004` вместо `0.30`. Строки с НДС суммируются в целых копейках; прежняя арифметика документов без явных ставок сохранена. Проверяются ручной акт и акт по счёту.
4. **Состояние карточки заявки.** Неверная сумма больше не пропускается молча; сохранение не открывает карточку после закрытия; несохранённые поля и форма задачи сбрасываются при открытии другой заявки; отмена создания сбрасывает выбранного клиента и незавершённую загрузку его дел.
5. **Граница месяца.** Отчёт использует календарную дату браузера вместо UTC-преобразования полуночи, которое в Новосибирске включало последний день предыдущего месяца.
6. **Недоступная аналитика заявок.** TypeScript обнаружил отсутствующее поле права на frontend; сервер требовал это поле, но сбрасывал его при сохранении роли. Добавлены отдельный переключатель и тип права, сохранение и аудит разрешения без расширения области видимости. Отсутствующее разрешение остаётся запрещённым. Исправлен тип отложенного ответа теста журнала КУДиР. Суммы заявок в отчёте больше не названы фактическими поступлениями.
7. **Гонки браузерных проверок.** Полный backend-gate выявил нестабильное сравнение времени Node и браузера с дедлайном таймера уведомлений, а также проверку блока файлов до получения сетевых ответов. Проверка теперь требует полностью полученного HTTP 200 после последнего события; создание ждёт реальный HTTP 503 с сохранённым ожиданием, восстановление потерянного ответа — точный ключ со статусом `uploaded` и файл в настоящем ответе списка. Проверки интерфейса, скачанных байтов, ошибок, прав и отсутствия дублей сохранены, таймауты интерфейса не увеличены. Добавлены отрицательные Node-тесты наблюдателя и их обязательный запуск в CI.
8. **Граница дисковой ёмкости в тестах.** Два теста выставляли минимальный остаток по текущему свободному месту всего с 1 МБ запаса; параллельное создание PostgreSQL-базы на том же диске нарушало их предпосылку. Сервер корректно отказывал в записи. Фикстуры используют существующий ограниченный native-провайдер и настоящую незавершённую операцию копирования: точная граница и проверки собственного подтверждённого префикса, чужого резерва и неиспользованного верхнего предела сохраняются. Идентичности файлов/тома, запись байтов, SQL и проверки реального свободного места остаются настоящими; серверный механизм не меняется.
9. **Результат долговечной доставки уведомлений.** Дополнительная проверка четырёх новых пакетных UPDATE выявила отсутствие проверки собственной аренды при сохранении исхода: старый обработчик мог менять новую попытку или финальный результат. Все три исхода теперь требуют той же аренды и отсутствия DeliveredAt/AbandonedAt; счётчик успешных доставок увеличивается только при реально изменённой строке. Каждая запись получает пять минут от своего захвата, а не от начала всего пакета. Отдельно воспроизведена ошибка PostgreSQL: DateTime.UtcNow внутри UPDATE несовместим с существующим timestamp без часового пояса и не позволял сохранить подтверждение/прекращение. Время передаётся параметром через прежнее UTC-преобразование, без изменения схемы. Перед исправлением новые 16 сценариев дали 13 отказов, включая нормальную доставку PostgreSQL и перезапись результатов; 3 нормальных сценария прошли.
10. **Перечень пакетных операций.** Контроль обнаружил 111 операций вместо устаревших 107 после добавления очереди уведомлений. Обновлён точный полный перечень с текущими строками и обоснованием аудита четырёх новых технических UPDATE. Контроль количества и каждого места сохранён, не отключён.

Стоимость изменений: загрузка DLL кешируется на процесс; проверка направления платежа использует прежний запрос без дополнительного обращения к БД; сумма строк считается за O(n); исправления состояния не добавляют сетевых запросов. Книга выгружается партиями; поиск дел клиента постраничный. Автоматизация и журнал не объявляются полностью реализованными по наличию основы.

Проверка аренды уведомления добавлена в существующий UPDATE по первичному ключу, без новых запросов и сетевых обращений. Доставка по-прежнему ограничена 50 строками за пакет и использует стабильный ключ события; неизвестный исход внешней отправки не объявляется гарантией единственной отправки.
