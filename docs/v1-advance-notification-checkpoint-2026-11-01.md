## Реализация и границы

V1 получает уже зарегистрированный scoped INotificationService и logger; старое прямое создание контроллера без них остаётся допустимым. Create/Update назначают callback общего VersionedPaymentWriteBoundary, поэтому уведомление начинается только после успешного финансового commit и освобождения транзакции. Используются прежние отбор кандидата, ответственный клиента/организации/дела, права и видимость общего NotificationService, личный запрет типа и сохранённый ключ дедупликации. Финансовая нормализация старого V1, транзакционная граница, серверные права и схема не переписаны.

Для V1 отдельно сохранён подтверждённый финансовый ответ при сбое уведомления: ошибка журналируется с ID платежа, без немедленного повтора. Старый keyless клиент не должен повторять уже сохранённую оплату из-за второстепенного callback. Недостающую запись CRM может создать существующий курсорный монитор авансов по своим настройкам/срокам; новый outbox или параллельный механизм не вводился. Реальная отмена HTTP-запроса не подавляется, если его token уже отменён. Вызванный транспортом OperationCanceledException при живом запросе обрабатывается как ошибка уведомления. Ошибки финансового сохранения и commit не перехватываются этим helper и не запускают уведомление.

Это обработка ошибок только нового V1 callback. Не заявляется исправление всех post-commit уведомлений V2/обычного Create или неясного результата настоящего DB commit. Отмена браузера и потеря подтверждения на сети остаются отдельными границами; прежнее решение о keyless-совместимости ожидается. Уже выданные документы, снимки, задачи, номера, суммы и исторические связи не менялись.
