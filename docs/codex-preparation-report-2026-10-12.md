### Что сначала не прошло и как обработано

1. Первый запуск Seed использовал обычный SQLite migration generator: `AddForeignKeyOperation` не поддерживался. Исправлен **только инструмент подготовки**: подключён существующий `UsePayPlannerSqliteMigrations()`, как в Program.cs/тестовых фикстурах. Частичные файлы новой синтетической базы сохранены вне checkout; новый запуск завершился. Миграции продукта не менялись и не пропускались вручную.
2. Первый backend-прогон без `PAYPLANNER_TEST_POSTGRES`: **130 упало, 208 прошло, всего 338**. Ошибка owned PostgreSQL fixtures — отсутствующая переменная. У старых PostgreSQL-тестов есть возврат при её отсутствии; их первоначальный «успех» не считается проверкой тела. Поднят отдельный пустой PostgreSQL 17.2 на 127.0.0.1:55432, повторён запрошенный набор.
3. Итоговый TRX PostgreSQL-прогона показал **11 timeout чтения потока** в первые минуты работы с обычной дисковой синхронизацией: 4 в TaskBillingConcurrencyTests при очистке базы, 4 в ChatSendPublicationCommitsTheWholeFrozenGraph при клонировании схемы, 1 в InternalChatNoReplyPostgreSqlTests, 2 в PostgreSqlCleanAndUpgradeAllowOldMessagesButRejectDuplicateSendKey. Изменена только конфигурация **disposable** тестового кластера: fsync/synchronous_commit/full_page_writes off; повтор семейства billing с Command Timeout=180 дал 10/10. Остальные затронутые методы повторены отдельно, 31/31 успешно. Таймауты/утверждения самих тестов не менялись. Такой кластер не квалифицирует аварийную долговечность и запрещён для рабочих данных.
4. `npm run dev -- --port 5301 --strictPort` в текущем PowerShell передал `vite 5301`. Этот лишний dev-процесс остановлен; проверена прямая команда Vite с явными host/port. В инструкции оставлена работающая команда.
5. При проверке PostgreSQL-helper с нуля прямой pg_ctl удерживал перенаправленные потоки PowerShell вместе с фоновым сервером. Исправлен только скрипт подготовки: скрытый Start-Process, вывод в собственные файлы и ожидание завершения pg_ctl, без ожидания всей фоновой цепочки. Первоначальный пустой кластер сохранён вне checkout; окончательный helper проверен на новом, отдельный concurrency-метод 2/2 прошёл.
