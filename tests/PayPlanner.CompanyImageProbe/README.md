# Изолированная Linux-проба изображений CMP-01

Консольная проба компилирует тот же `CompanyImageUploadValidator`, что API. Она не ссылается на API-проект, EF, миграции, БД или приложение CRM и не читает пользовательские файлы. Проверяет PNG/JPG, прозрачность, повреждения, APNG, пределы пикселей и два случая с сильно сжатыми метаданными. Последние проверяют расход ресурсов, а не допустимость самих метаданных.

Из корня репозитория подготовить **новую** папку (существующий результат не перезаписывается):

```powershell
node scripts/prepare-company-image-linux-probe.mjs --output=D:/PayPlannerRelease/company-image-linux-candidate
```

Сохранить выданный `manifestSha256`. Сборка framework-dependent `linux-x64` не требует сборки API/истории миграций. Проверяются совпадение версий SkiaSharp с API, отсутствие зависимостей БД и SHA-256 всех файлов. Папка `app/` содержит только программу, библиотеки и лицензии.

Запускать на **существующем изолированном Linux-хосте**, отдельно от VPS/выпуска другого чата. Нужны Node.js, работающий локальный Docker с seccomp и уже загруженный официальный образ .NET 9 runtime linux/amd64 с `/usr/bin/timeout` (обычный Debian-based runtime). Образ задаётся проверенным digest, не тегом. Скрипт не скачивает образ, не запускает демон, не подключается по SSH и не использует удалённые Docker contexts. Ничего устанавливать автоматически не будет.

Переменные ниже оператор заполняет подготовленным каталогом, сохранённой контрольной суммой и digest **имеющегося** образа:

```sh
node scripts/run-company-image-linux-probe.mjs \
  --artifact="$PROBE_DIR" --manifest-sha256="$MANIFEST_SHA256" \
  --image="$IMAGE_DIGEST" --result="$NEW_RESULT_FILE"
```

`IMAGE_DIGEST` имеет вид `mcr.microsoft.com/dotnet/runtime@sha256:…`. Каталог `PROBE_DIR` должен быть скопирован целиком; результат — новый абсолютный путь вне `app/`. Для просмотра плана без Docker/исполнения добавить `--dry-run`; такой вывод не является проверкой Linux.

Контейнер: без сети/портов, root и capabilities, readonly root/app, один CPU, 512 МиБ без дополнительного swap, 64 PID, tmpfs 16 МиБ, core dump запрещён. Внутренний timeout убивает процесс через 40 секунд даже при прерывании внешнего runner; attach ограничен 45 секундами. До запуска проверяются фактическая конфигурация контейнера и digest. Удаляется только контейнер с собственными случайными метками; чужой контейнер не останавливается. При аварийном прерывании runner контейнер сам завершится по timeout, но его metadata могут потребовать отдельного удаления по точной метке.

Успех — только `status=passed` в новом JSON, 16 результатов, отсутствие OOM и exit code 0. Пик памяти процесса должен быть не выше 384 МиБ. Исключение, таймаут, OOM, неполный JSON или невозможность безопасной очистки дают отказ. Сохранять JSON вместе с manifest и журналом сборки. Это адресная native-проба; она не заменяет обязательный полный CI, проверку миграций, CRM startup или production-приёмку.
